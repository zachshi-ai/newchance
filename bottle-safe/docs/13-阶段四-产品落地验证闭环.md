# 13 · 阶段四：产品落地验证闭环

> 本阶段回答：怎么证明这个产品会成（或不成）？用 HDD 把信念变成可证伪假设，用 OHELM 循环推进验证，用 90 天排期对齐安检季与执法节奏，并确立第一桶金。

---

## 1. 假设登记册（HDD）

| # | 假设 | 判据（可证伪） | 验证方法 | 状态 |
|---|---|---|---|---|
| H1 | 站长会持续落账（配送/安检动作留存是全产品的地基） | ≥40% 建档网点第 14 天仍有落账记录新增 | 本地事件流（`delivery`/`check`/`recheck` 埋点，设置页可导出）+ 20 家种子网点微信群自愿回传 | ⬜ 待验证 |
| H2 | 迎检打印包会在真实检查中被使用并采信 | ≥50% 活跃网点每月导出 ≥1 次；≥3 家网点反馈"检查时实际出示" | 埋点：`ledger` 事件按 action 分桶（copy/download/print）+ 种子回访 | ⬜ 待验证 |
| H3 | 隐患告知单会被真实打印并让用户签字 | ≥30% 活跃网点在隐患检查后生成过告知单；≥2 家反馈用户实际签字 | 埋点：`slip` 事件密度 + 照片回访 | ⬜ 待验证 |
| H4 | 付费意愿存在且锚点在一百元内 | 假门按钮点击率 ≥5%；或 ≥10 家愿付 ¥99/年 | 假门 Pro（多站点/月报/自定义抬头，点击后如实告知"功能规划中"）+ 直接报价访谈 | ⬜ 待验证 |
| H5 | 储配站愿意联营分销（配送网络与瓶资产保全叙事成立） | ≥3 家储配站试点贴牌、合计覆盖 ≥60 家网点 | 储配站扫街拜访（一个储配站辐射 10~200 家网点），白标包 ¥1200/年 | ⬜ 待验证 |
| H6 | 隐患整改闭环被真实执行（"整改—复访—销案"的日常化） | 隐患落账的网点中 ≥60% 两周内完成合格复访 | 埋点：`recheck` 事件对未闭环曝光的转化 | ⬜ 待验证 |
| H7 | 瓶数守恒账被真实使用（对账价值成立） | ≥50% 活跃网点累计配送落账 ≥20 单；回访中 ≥3 家反馈"用过在户瓶数对账" | 埋点：`delivery` 密度 + 对账场景回访 | ⬜ 待验证 |
| H8 | 用户会主动备份/迁移数据 | JSON 导出使用率 ≥10%（交接场景天然产生导出需求） | 埋点：`export-json` 事件 | ⬜ 待验证 |

**已证伪风险预案**：若 H1 < 20%（落账动作不成立——旺季忙起来顾不上 R2 成真），转向"迎检台账包生成器"单点工具（弱化日常落账叙事，强化检查前批量补录与安检季名单场景——同一个 core，换一个入口叙事）；若 H2 < 30%（打印包没人用或没人采信），出证价值主张被证伪，产品失去对检查场景的钩子，止损关停，把告知单模板拆给燃气内容号做引流素材另起炉灶。

## 2. OHELM 验证循环

每条假设按 **Objective → Hypothesis → Experiment → Learn → Measure** 循环推进，学习结果写回假设登记册，不做完循环不进入下一轮投入：

| 环节 | 本项目的落地形式 |
|---|---|
| **O** Objective | 90 天内证明"站长愿意把网点台账从纸单升级为落账 + 闭环 + 出证"（H1+H2+H3+H6） |
| **H** Hypothesis | 上表 H1-H8，一条一个预期数值 |
| **E** Experiment | ①20 家种子网点（8 乡镇供应站 + 6 城乡结合部网点 + 4 以餐饮用户为主的网点 + 2 新接手承包人）微信群陪跑（本地优先工具的天然局限：埋点在端上，靠用户自愿导出 + 周回访，储配站送货时面对面回收）②假门付费 ③储配站扫街 10 家、谈 3 家贴牌试点 |
| **L** Learn | 每两周一次循环复盘：判据达标 → 升级投入；不达标 → 触发对应预案（H1/H2 预案） |
| **M** Measure | 北极星：**周活跃落账网点数（周内至少 3 条配送或安检落账的网点数）**；护栏指标：迎检包导出率（H2）、告知单生成率（H3）、落账 14 天留存（H1）、闭环执行率（H6）、守恒账使用率（H7）、备份导出率（H8） |

**北极星指标说明**：不选下载量（vanity）、不选建档数（无门槛），选"每周至少落 3 笔账的网点数"——它同时代表网点留存、真实配送/安检行为与台账的持续可证明性，且与网点的合规健康度同向。

## 3. 第一桶金（确立）

三条腿并进，以 ② 储配站联营为杠杆主攻：

| 路径 | 定价 | 第一笔钱的现实性 | 90 天目标 |
|---|---|---|---|
| ① 网点 Pro | ¥99/年（多站点管理 + 经营月报 + 自定义抬头）；单站点永久免费 | 假门点击 → 直接报价转化；锚点贴"两只气的利润"的心理账户 | H4 判据：≥10 家付费或假门点击 ≥5% |
| ② **储配站联营（主攻）** | ¥1200/年/站（白标 ≤50 家网点，含商家看板：下游网点落账活跃度/未闭环隐患信号/瓶数守恒体检） | 一个储配站服务 10~200 家网点，客单价是网点的 12 倍且决策人单一（储配站老板）；对商家的账：**下游网点被停业 = 配送末梢断档、乱收瓶 = 在外钢瓶资产流失，帮网点合规存续与瓶账守恒 = 保护储配站自己的资产负债表** + 白标 = 每次送货对账时的品牌触点 ≫ ¥1200 | 扫街 10 家、签约 3 家 = **首笔现金 ¥3,600**，同时获得 60+ 精准网点分发面 |
| ③ 燃气器械经销商分佣 | 按成交 20% 分佣（软管/减压阀经销商） | 依赖①②的转化率数据成熟后再开 | 不做承诺，进迭代池 |

**为什么 ② 是主攻**：站长个体付费弱（R1），但储配站 B2B 决策快、有独特且深刻的 ROI（**配送网络与瓶资产保全 + 站点账对齐**——这是燃气流通区别于其他行业的渠道动机，docs/12 §6.3）、且天然批量触达网点主（送货即见面）——**供应链上游即渠道**。第一桶金的本质不是规模，是"有人为价值付了第一笔真钱 + 一条可复制的收款路径"，3 家储配站试点同时验证产品价值（H5）、渠道结构（分发面）与收款能力。

## 6. 诚实条款（本项目的科学底线）

- **不碰充装追溯、不做政府报送、不做订气平台、不装报警器硬件**：瓶号手输照瓶身抄（这是特性不是缺陷：无硬件门槛、无报送合规负担、离线可用）。充装赋码与流向报送是充装单位与监管平台的事，这里是网点自己的经营底账与自证凭据。
- **内置安检项与周期是通识口径预填，绝非属地执法口径**：入户五项（软管/减压阀/钢瓶/灶具/通风）与年度安检（365 天）、钢瓶检验（48 个月周期、90 天预警窗）、证件预警（30 天）均为行业通识默认值——**以《城镇燃气管理条例》原文、属地燃气管理部门要求与气瓶安全技术规程为准，设置页全参数化可覆盖**。条例罚额等检索受限口径的标注见 [docs/14](14-调研来源.md)。
- **打印台账不承诺执法采信**：迎检包是网点自查与备查底账（含守恒体检与隐患闭环），帮助站长"当场拿得出、说得清"；本地记录不具备司法级不可篡改性，不宣称替代法定报送、公证存证或监管平台数据；隐患整改的法定效力以属地要求为准——告知单以用户签字的纸质回执为准。
- **工具不判真伪，只保完整与闭环**：补录数据如实存在（录入即留痕），台账的可信度建立在连续真实的记录上——本工具不提供任何"一键生成完美台账"的功能，造假风险自担。
- **告知单是提醒凭据不是责任切割**：用户签字表示"知悉隐患与整改要求"，不等于责任转移——事故责任认定以司法机关与属地规则为准，**法律永远赢**。
- **用户底档最小留存**：仅存姓名、电话、地址与常用瓶型，不存身份证影像；数据 100% 本地存储，换机/交接走 JSON 导入导出。
- **所有商业假设未验证**：付费、留存、渠道数字全部是待证伪的信念。我们不把"法定安检义务"当作付费的必然性——纸安检单几毛钱一张，脑子里的瓶数和储配站的口账也是船。
