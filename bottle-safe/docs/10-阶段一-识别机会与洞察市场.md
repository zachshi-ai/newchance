# 10 · 阶段一：识别机会与洞察市场

> 本阶段回答：世界的哪个痛点值得做？用第一性原理拆到底，用 JTBD / 船模型 / 非消费者分析还原真实场景，用 PESTEL 扫宏观，用机会缺口矩阵定位空白。

---

## 1. 第一性原理拆解

不问"市面上有什么燃气软件"，只保留不可再分的事实：

| # | 不可再分的事实 | 推论 |
|---|---|---|
| F1 | 瓶装液化气是**危险的消费品加法律责任的载体**：每送出一瓶气，网点就把一份易燃易爆品交到了没有专业知识的家庭与餐馆手里——《城镇燃气管理条例》（国务院令第 583 号，2011 年施行）把"指导用户安全用气、对用户燃气设施定期进行安全检查"写成经营者法定义务（通识口径，罚额区间检索受限见[调研来源](14-调研来源.md)） | 网点的生存确定性不取决于"卖了多少气"，取决于"**出了事故时你能否证明你尽了义务**"——入户安检台账与隐患整改记录是唯一证据。**证明成本**是整个痛点的第一性变量 |
| F2 | 2021 年十堰"6·13"重大燃气爆炸事故后，全国城镇燃气安全专项整治常态化（2023 年起深化"带病运行"治理）——检查频次、罚款力度、"送气必检"要求同步上升（通识口径）；软管老化、减压阀超期、超期未检钢瓶、用户私自倒罐是检查与事故的高频关键词 | 监管风暴不是一次性事件而是**持续状态**：安检记录从"迎检材料"变成"日常运营动作"，纸台账的突击补填模式在逐户核对面前必然露馅 |
| F3 | 隐患只有**整改闭环**才有法律意义：检查发现软管老化只登记不整改、不复查，事故后"你早就发现了却放任"比"没检查"更重；纸台账时代隐患单开出去就石沉大海，谁也说不清换没换 | 隐患→整改→复访→销案的**闭环链条**是台账的灵魂——这正是纸本结构性做不到、软件一分钟做到的事 |
| F4 | 液化气配送天然**两本账合一**：满瓶送出、空瓶收回，一户存几只瓶全凭记忆；餐馆以瓶抵款、邻里借瓶、瓶随房走——钢瓶产权纠纷与"瓶数对不上"是乡镇网点的日常摩擦，而瓶数账与安检账共用同一个"户" | 用户建档即同时承载**钢瓶守恒账**（送出−收回=在户瓶数）与**安检责任账**（这户最后一次安检是什么时候）——两本账一本记，记账动作零增量 |
| F5 | 二级网点/乡镇供应站的现状解法 = **纸安检单塞抽屉 + 瓶数靠脑子 + 检查前突击**：送气工一手交瓶一手收钱，安检单让用户签个字就完事，单子能不能再找到全看运气；年度"逐户安检全覆盖"任务靠月底一天编 | 现状解法的失败不在"不知道要检"，在**记录散、对不上、连不成链**——三种失败都是软件结构性擅长的事 |
| F6 | 行业垂直软件缺位：储配站（充装一级）有充装追溯与企业管理系统，政府侧有气瓶追溯平台与智慧燃气平台——**二级网点（个体承包的乡镇供应站/配送站）被两边同时跳过**：平台管监管数据链，不管网点的经营底账与自证凭据 | 二级网点是非消费者（见 §5）；一部手机 + 原有的纸单流程，就能把"证明基建"建起来，不必等平台覆盖 |
| F7 | 液化气是**低毛利高频刚需**生意：一瓶气赚十几元，一单安检罚款（万元级通识口径）等于几百瓶白送；但网点是储配站的分销末梢，储配站天然批量触达网点 | 免费增值 + 渠道联营（储配站即渠道，动机：网点被停业 = 配送网络损失）——单点付费弱、渠道付费强的结构 |

**第一性结论**：二级液化气网点的生存确定性 = 「配送流水的可核对性 × 入户安检的可证明性 × 隐患整改的闭环性 × 周期义务（年度逐户安检/钢瓶检验/人员证件）的按时性」，四件事共用**同一个用户档案**。谁把"送一瓶落一笔、检一户留一单、有隐患必须回访销案、到期自动点名"的成本打到趋近于零，谁就把悬在头顶的万元罚单，变成网点与储配站、监管部门、事故认定方对话的底气。

## 2. 痛点 - 爽点 - 痒点模型（梁宁）

| 层 | 用户心理 | 瓶安单对应 |
|---|---|---|
| **痛点**（恐惧/怕） | 怕专项整治检查翻不出两年前的安检单；怕某户出事故被翻出"登记过隐患却没复查"；怕年度逐户安检任务月底靠编；怕餐馆的瓶数对不上扯皮；怕送气工证件过期被查 | 隐患必须登记整改措施才让落账 → 复访合格才销案 → 未闭环红灯常亮；年度安检/钢瓶检验/证件到期自动点名；迎检打印包 30 秒出证——风险在爆发前被看见 |
| **爽点**（即时确定性） | 送一瓶落一笔，这个月给李大姐餐馆送了几只、收了几只一目了然；检查进门点两下打出整本台账；隐患告知单当场打印让用户签字 | 配送落账顺手化（守恒账自动算）＋安检单结构化（逐项检查不漏项）＋告知单印刷级出证 |
| **痒点**（虚拟自我） | "我们站是全乡台账最齐的供应站"；储配站来收账时对得上一笔不差；用户的瓶是我站的瓶，清清楚楚 | 印着站点名与燃气经营许可证号的告知单与台账包——夫妻供应站的"规范经营者"身份叙事 |

优先级：痛点 > 爽点 > 痒点。MVP 只做痛点与爽点，痒点靠出证单据的品牌落款顺手满足，不做充装追溯、不做政府报送、不做订气小程序（见阶段三 ERRC）。

## 3. JTBD（待办任务）

**主任务陈述**：**当**送气工出门送 20 瓶气、安检季要逐户覆盖、发现某户软管老化、储配站月底来对瓶账、监管部门上门翻台账、某用户家出了事故时，**我要**当场说得清"这户送了几瓶收了几瓶、检了什么、隐患有没有改、上一次安检是什么时候"，**以便**检查不挨罚、事故不背锅、瓶数不扯皮、年度任务不靠编。

三维拆解：

| 维度 | Job | 现状方案的失败点 |
|---|---|---|
| 功能性 | 用户建档（地址电话钢瓶）；配送落账（满瓶/空瓶/金额）；入户安检（五项检查）；隐患整改复访闭环；年度安检/钢瓶检验/证件到期点名；告知单与台账产出 | 纸单塞抽屉、瓶数靠脑子、隐患开单无下文、到期靠日历贴条 |
| 情感性 | 检查进门不心虚；事故上门不慌；对瓶账不虚 | "我找找那张单子"本身就在制造紧张 |
| 社会性 | 向监管（合规供应站）、向储配站（对得起配送权的正规网点）、向用户（负责任的送气人）证明"这家站是认真的" | 没有任何体面的凭据载体 |

**竞品不是某个行业 SaaS，而是「纸安检单 + 脑子里的瓶数 + 什么都不留」**——它们免费且是行业默认动作（见阶段二波特五力：替代品威胁）。

## 4. 船模型

> 用户要的从来不是船，是安全过河。这里河对岸 = 检查不罚、事故不背、瓶账不乱、年度任务不编。

| 元素 | 本场景 | 现状问题 |
|---|---|---|
| 乘客 | 瓶装液化气二级网点/乡镇供应站（1~5 人，几百到几千用户，储配站供气）；渠道乘客：一级储配站（见 §6.3） | — |
| 船 A：纸安检单 + 脑子里的瓶数 | 现状默认解，零成本 | 单子找不到、瓶数对不上、隐患无下文、检查靠突击 |
| 船 B：储配站/企业管理系统 | 一级站的选择 | 服务充装与站内管理，不覆盖承包网点的入户安检与配送底账；网点买不到也用不起 |
| 船 C：政府气瓶追溯平台 / 智慧燃气平台 | 监管数据链（充装赋码、流向报送） | 服务**监管追溯**，不是网点的经营底账：网点无法用它打印迎检台账、管在户瓶数、开隐患告知单；数据报送了，证据还在别人手里 |
| 船 D：微信记账 + 备忘录 + Excel 表侄子帮做 | 部分年轻站长的过渡解 | 无规则（不知哪户该检了）、无闭环（隐患开了没有下文）、无守恒（瓶数越记越乱） |
| 河 | **配送与安检之间的证明黑箱**：送了多少、收了多少、检了什么、隐患改没改，没有一本随取随用的账 | 四条船共同的黑水区 |

**定位推论**：瓶安单**不造充装追溯的船，也不造储配站管理系统的船**，做挂在所有船上的"网点自己的合规底账"——与追溯平台互补（它管赋码报送，瓶安单管网点自证），与储配站系统互补（它管站内，瓶安单管末梢），与纸单正面对抗但迁移成本 ≈ 0（还是一部手机，只是从"塞抽屉"变成"点打印"）。

## 5. 非消费者分析（Christensen）

| 非消费者类型 | 画像 | 为什么不用现有解 | 对产品的启示 |
|---|---|---|---|
| 乡镇个体供应站 | 承包储配站的片区配送权，1~3 人，站长兼送气工兼安检员 | 企业系统"是站里用的"；追溯平台"数据报给政府了，跟我没关系"；Excel 没人维护 | 说人话（"入户安检"不叫"用户端安全巡检"）；单屏两步动作；送气落账和收瓶数一屏完成 |
| 新接手网点的承包人 | 接手片区时瓶数、用户、隐患全凭前任口述 | 没有交接台账，接手即背锅 | 用户档案 + 在户瓶数 + 隐患未闭环清单 = 交接即盘点（JSON 导出/导入支持整体移交） |
| 配送范围跨村的站长 | 用户散在十里八乡，安检季逐户跑 | 纸质年度安检表分不清哪户检了哪户没检 | 年度安检到期自动点名，先检快到期的，跑单路线有依据 |
| 被罚款/事故吓过的站长 | 邻县某站因隐患未复查被重罚的消息在圈子里传 | 之前觉得"记那玩意没用" | 隐患闭环与告知单存根把"我提醒过、他没改"变成可出示的证据 |

非消费者共同阻碍排序：**"台账是给检查看的，不是给我用的"（价值错觉）> 怕学不会（能力焦虑）> 数据放别人服务器不放心（信任顾虑）**。MVP 依次对应：台账先服务站长自己（瓶数守恒/隐患闭环/到期点名），检查出证只是顺产的输出；名词全部取自纸单原文；数据只存本机。

## 6. PESTEL 宏观扫描

| 维度 | 要点 | 对本机会 |
|---|---|---|
| **P** 政治 | 城镇燃气安全专项整治常态化（十堰事故后国务院安委会部署，2023 起深化治理）；条例对经营者定期安检义务与罚则有明文（罚额通识口径检索受限）；"送气必检"、实名购气在多地落地执行 | 合规是自上而下的硬约束且处于**收紧通道**，顺风；专项整治期间检查频次上升，"迎检出证"价值即时兑现 |
| **E** 经济 | 液化气用户端价格敏感、网点毛利薄；一单处罚（万元级通识口径）等于数百瓶利润；钢瓶是网点的主要实物资产 | 免费是入场券；付费叙事 = 止损（罚款/停业/事故赔偿期望损失）+ 资产账（钢瓶守恒），站长算得清 |
| **S** 社会 | 燃气事故是舆情极敏区（爆炸事故必上热搜）；餐饮用户（小饭馆）是事故高发场景；乡镇老龄化使站长与用户都在向"少写字、多拍照"迁移 | 台账/告知单 = 网点的"社会信任基建"；结构化打卡、纸单原文式输入贴合用户习惯 |
| **T** 技术 | 智能手机在乡镇已普及；PWA/打印是系统级能力；气瓶二维码由充装端赋码（网点无须硬件）；智慧燃气平台在县城以上推进，乡镇末梢覆盖弱 | 不依赖硬件即可把证明基建建到"趋近零增量成本"；平台覆盖弱的乡镇末梢正是空白带 |
| **E** 环境 | 液化气作为农村清洁能源过渡方案仍将长期存在；钢瓶定期检验（检验周期通识口径 4 年）减少安全隐患与资源浪费 | 钢瓶检验台账顺带成为资产管理账——同一本账多一层价值 |
| **L** 法律 | 条例义务与罚则、气瓶安全技术规程（特种设备口径）、实名购气的地方规定构成三层义务；事故认定中"是否定期安检、隐患是否整改"是经营者责任的核心证据（通识口径） | 台账既是行政合规凭据又是事故责任的自证证据；"检查 + 事故 + 纠纷"三场共用 |

结论：宏观无逆风。P（专项整治常态化）与 L（义务成文化）双顺风把"证明"的价值放大；S（事故舆情）把痛点从检查放大到生存；T（乡镇智能手机普及 + 平台末梢空白）让增量成本趋近于零；F（液化气长期存在）保证市场不消失。**监管在收紧、检查年年有、末梢轻产品空白仍在。**

## 7. 机会缺口矩阵

以"用户重要性 × 市场现有解完整度"定位空白：

```
重要性 高 │ ①储配站/企业管理系统      ③【空白】网点自己的配送安检台账
          │ （一级站红海）              （配送守恒/入户安检/隐患闭环/
          │                            年度到期点名/迎检出证，无小微级轻产品）
重要性 低 │ ②政府追溯/智慧燃气平台    ④订气小程序/送气调度平台
          │ （监管数据链，政府主导）    （重运营重补贴，零售平台主场）
          └─────────────────────────────
             现有解完整度 高            低
```

- ③的四段拆解交叉验证：纸安检单（散、丢、连不成链）、储配站系统（不覆盖承包末梢）、追溯平台（管报送不管自证）、微信记账（无规则无闭环无守恒）——**每一段都有人做，合起来无人做**。
- ①与②是重资产与政府主导的主场，付费方与产品形态都在另一个世界；③覆盖的是沉默的大多数（乡镇二级网点与供应站）。
- ④偏离合规主线（订气是零售生意），无冲突也不碰。
- 监管与产业事实给 ③ 背书：条例的定期安检义务与罚则、专项整治常态化、"送气必检"执行化——**规则现行、检查年年有、轻产品空白仍在**。

**阶段一结论**：瓶安单占位 ③——一条被定期安检法定义务、专项整治常态化与隐患整改举证责任共同供养、被"纸安检单 + 储配站系统 + 追溯平台"证明协作真实存在、却被所有重方案忽略的末梢缺口。
