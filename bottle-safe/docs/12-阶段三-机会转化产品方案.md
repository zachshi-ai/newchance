# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会怎么变成一个可卖的产品？用商业画布与价值主张画布定结构，用蓝海四动作定差异化，用 Kano 裁 MVP，最后把供应链想透——本项目供应链分析的重头戏是**瓶装液化气流通链**（储配站 → 二级网点 → 用户，瓶与责一起向下传递）与**分发链**（一级储配站即渠道，渠道动机：配送网络与瓶资产的保全）。

---

## 1. 商业画布（Business Model Canvas）

| 模块 | 内容 |
|---|---|
| **客户细分** | 瓶装液化气二级网点/乡镇供应站（1~5 人，几百到几千用户，储配站供气、个体承包）；正在接手片区的承包人；渠道客户：**一级储配站**（联营贴牌，见 §6.3） |
| **价值主张** | 对站长：送气落账顺手、瓶数守恒不扯皮、入户安检逐项不漏、隐患整改复访闭环、年度安检/钢瓶检验/证件到期不逾期、迎检 30 秒出证、隐患告知单当场打印签字；对监管者/用户：拿得出、说得清、对得上；对储配站：下游网点合规存续 = 配送网络与瓶资产的保全 |
| **渠道** | 直达：抖音/快手"燃气检查被罚/隐患未整改出事故"场景内容 + 网点站长微信群；渠道：**储配站联营**（上游供应商即分销商）、县域燃气器械经销商分佣 |
| **客户关系** | 免费自助 + 内容号陪跑（安检项更新/迎检话术/安检季提醒）；储配站渠道由商家代维护客户关系 |
| **收入来源** | 免费版（单站点全功能）；Pro 待验证（H4 假门 ¥99/年）：多站点管理、经营月报、自定义抬头；储配站联营年费 ¥1200/站（白标 ≤50 家网点）待验证（H5） |
| **核心资源** | 安检项与迎检话术的内容模板库（法规跟踪）、"瓶安单 = 液化气网点台账"品类心智、储配站渠道关系 |
| **关键业务** | 法规与安检项内容运营、渠道拓展（储配站/燃气器械经销商）、留存运营（安检季/到期触达） |
| **重要伙伴** | 一级储配站（渠道 + 安检季任务与瓶资产的真实信息源）、燃气器械（软管/减压阀）经销商（隐患整改的耗材供给方）、静态托管平台 |
| **成本结构** | 近零边际成本：无服务器账单、无 npm 审计、单人维护；获客内容制作为主要成本 |

## 2. 价值主张画布（Value Proposition Canvas）

**客户侧（二级网点站长）**

| 客户任务 | 痛点 | 期望收益 |
|---|---|---|
| 送气收瓶 | 一户存几只瓶全凭记忆，餐馆以瓶抵款越记越乱 | 选户填瓶数 30 秒落账，在户瓶数自动守恒，对账一口清 |
| 入户安检 | 纸安检单逐户签字塞抽屉，年度覆盖全靠月底突击 | 逐项结构化检查（软管/减压阀/钢瓶/灶具/通风）不漏项，检完顺手落账 |
| 隐患整改 | 隐患单开出去石沉大海，事故后"早就发现了却放任"责任更重 | 隐患必须登记整改措施才让落账，复访合格才销案，未闭环红灯常亮 |
| 告知用户 | 口头提醒无凭据，出了事说不清"我提醒过" | 隐患告知单当场打印签字（站点落款 + 整改要求 + 复访约定），微信文本同步发用户 |
| 年度安检任务 | 哪户检了哪户没检靠翻本子，路线乱跑 | 到期自动点名（默认 365 天，可调），先检快到期的，跑单有依据 |
| 钢瓶资产 | 钢瓶检验到期没人盯，超期瓶在用户手里流转 | 钢瓶档案 + 检验到期预警（默认 48 个月周期、90 天窗，通识口径可调） |
| 监管上门 | 台账翻不出来、安检单对不上户 | 迎检打印包：站点与许可证 + 配送守恒体检 + 安检台账（闭环列）+ 到期点名，30 秒出证 |
| 接手/移交 | 接手片区凭前任口述，接手即背锅 | 用户档案 + 在户瓶数 + 未闭环隐患清单 = 交接即盘点，JSON 整体移交 |

**产品侧**

| 功能 | 减痛 / 创益 |
|---|---|
| 用户建档（地址/电话/常用瓶型） | 减痛：实名底档一次建好，配送安检共用 |
| 配送落账（满瓶/空瓶/金额，守恒派生在户瓶数） | 创益：瓶账与气账一本记，守恒体检常亮 |
| 入户安检（五项逐检 + 隐患强制整改登记） | 减痛：不漏项、不空转，"检了什么"当场成单 |
| 复访销案 + 未闭环点名 | 创益："隐患—整改—复访"第一次成为可出示的完整链条 |
| 隐患告知单（印刷级 HTML + 微信文本） | 创益：对用户的提醒第一次有了可签字、可留存的凭据 |
| 三类到期点名（年度安检/钢瓶检验/人员证件）+ 断更体检 | 减痛：四件"靠记性"的事第一次有人盯 |

**契合检验**：八个客户任务 ↔ 六项功能一一对应（告知单覆盖隐患整改与用户告知两个任务），无"我们做了但没人要"的悬空功能。

## 3. 蓝海战略四动作框架（ERRC）

| 动作 | 内容 | 效果 |
|---|---|---|
| **剔除 Eliminate** | 气瓶充装与追溯赋码（充装站与平台的事）、政府数据报送、订气小程序与送气调度、报警器硬件、财务进销存、多角色权限与实施培训 | 与监管平台和零售平台正面会战的战场全部放弃；报送义务与重资产一并剔除 |
| **减少 Reduce** | 建档字段（用户 6 项、安检 5 项逐选）、落账动作（选户 → 填数 → 落账三步）、报告格式（告知单一种模板、台账一种格式） | 把"系统"从文书工作降为"顺手"级动作 |
| **增加 Increase** | 钢瓶守恒账（在户瓶数流水派生、守恒体检）、隐患强制整改与复访销案闭环、年度安检/钢瓶检验/证件三类到期点名、隐患告知单出证、断更体检、迎检打印包 | 把"记台账"升级为"有守恒、有闭环、有周期、有凭据"的合规经营闭环 |
| **创造 Create** | **"末梢责任的证明确定性"**——站长从未体验过"检查进门 30 秒打出台账、事故上门拿得出闭环记录"；监管者与储配站第一次见到网点递出的结构化凭据 | 非消费者（乡镇个体站长、接手片区的承包人）转化为用户 |

## 4. USP（独特销售主张）

> **唯一为瓶装液化气二级网点设计的合规台账：送气落账顺手，瓶数守恒不扯皮，入户安检逐项不漏，隐患整改复访销案，年度安检钢瓶检验不逾期，监管检查 30 秒打出台账包。不碰充装追溯、不做订气平台、不装报警器硬件，一部手机就能用，免费开始。**

- 对比纸安检单：有守恒、有闭环、有周期、有凭据，"塞抽屉"变成"当场记完"；
- 对比储配站系统：不要钱（单站）、不要学、不要电脑，专管站内系统管不到的末梢（入户安检与配送底账）；
- 对比追溯平台：它是监管数据链，瓶安单是网点自己的经营底账与自证凭据——互补不替代。
- 三句话之外的克制：**不说"保证不挨罚"，不说"替代报送与官方系统"**——证据效力边界见诚实条款（docs/13 §6）。

## 5. Kano 模型 → MVP 范围裁剪

| 类型 | 功能 | MVP 取舍 |
|---|---|---|
| 基本型（没有就骂） | 用户/钢瓶/员工建档、配送落账、安检落账、台账与告知单导出（文本/HTML/打印） | ✅ 已做（单元测试覆盖核心逻辑） |
| 期望型（越多越好） | 瓶数守恒派生与负数守卫、隐患强制整改登记、复访销案、三类到期点名、断更体检 | ✅ 已做 |

## 6. 供应链分析（重点：瓶装液化气流通链 + 技术链 + 分发链）

### 6.1 瓶装液化气流通供应链（网点是链条最后一米——台账即供应链的责任单）

一瓶气从充装到灶台：**炼厂/进口 → 储配站（充装+瓶资产）→ 二级网点（配送+安检责任）→ 用户（家庭/餐馆）**。条例的安检义务与实名购气要求，本质上是**把供应链末梢的责任写进网点账本**——账做得越全，网点在链条中的位置越可证明：

| 环节 | 链路 | 暗账（没人记的部分） | 瓶安单的动作映射 |
|---|---|---|---|
| 供气 | 储配站向网点配瓶（赊销或现款） | 网点从站里拿了多少瓶、退了多少空瓶，月底靠对口水账 | 站点档案 + 配送落账的守恒体检让"站—点"两本账对得上（对接储配站联营的信任基础） |
| 配送 | 送气工送满瓶、收空瓶，一户多瓶往返 | 一户在户几只瓶全凭脑子，餐馆以瓶抵款越记越乱 | `recordDelivery` 落账：满瓶送出/空瓶收回按瓶型分行，在户瓶数流水派生、负数拒绝（守恒） |
| 安检 | 入户五项检查（软管/减压阀/钢瓶/灶具/通风） | 纸安检单塞抽屉，年度覆盖月底突击 | `recordCheck` 逐项结构化落账，检查员落名，日期落账 |
| 隐患整改 | 口头提醒或纸单一份 | 开单无下文，复查无人管，事故后责任放大 | 隐患必须登记整改措施才落账 → 复访合格销案 → 未闭环红灯；`slipHtml` 告知单当场打印签字 |
| 钢瓶资产 | 网点自有瓶在用户手里轮转 | 检验到期没人盯，超期瓶流转 | 钢瓶档案 + 检验到期预警（通识口径周期可调） |
| 人员 | 送气工/安检员流动 | 证件到期上岗被查 | 员工证件台账 + 到期预警 |

**上游不碰、下游不碰**：不碰充装与赋码（充装站与平台的事，ERRC 剔除追溯），不碰用户端订气与调度（零售生意，剔除订气平台），不碰报警器硬件（重供应链）——瓶安单只把网点这一米的"送、检、改、证"记成一本守恒的账，它是网点与上游储配站、下游用户、侧向监管者一切对话的底气。

### 6.2 产品自身供应链（MVP 的技术依赖链，逐项消除单点故障）

与仓库内其余项目同一架构纪律：**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**

| 依赖 | 决策 | 单点故障消除 |
|---|---|---|
| 后端/数据库 | 无（localStorage 本地优先） | 无云账单、无停服；用户底档与瓶账不出设备；乡镇网络差照常用 |
| 第三方库 | 无（core.js 纯函数，日期/守恒/闭环链/导出自实现） | 无供应链投毒面；`node --test` 零依赖可测 |
| 分发 | 任意静态服务器（`python3 -m http.server` 3 条命令） | 文档根即部署根，可迁移任意托管 |
| 出证 | 微信文本 + 单文件 HTML（内联样式）+ 系统打印 | 不依赖任何在线渲染/消息服务，监管者与用户零安装 |
| PWA 离线 | sw.js 缓存应用壳（版本化 + `cache:'reload'` 更新） | 断网可用；升级可靠到达 |

### 6.3 分发供应链（获客链路——上游供应商即分销商，渠道动机 = 配送网络与瓶资产的保全）

```
内容制作（抖音/快手："燃气检查被罚第一现场""隐患没复查出了事谁担责" 场景内容 + 告知单/台账模板引流）
      ↓ 免费工具承接（零摩擦，扫码即用）
直达用户（网点站长微信群 / 燃气器械经销商 / 县域安监培训点）
      ↓ 规模化放大（本项目独有的渠道结构）
渠道分层：① 一级储配站联营（B2B2C）：储配站把瓶安单贴牌赠给其下游 10~200 家二级网点
         → 商家动机：储配站最大的资产是片区配送网络与数万只在外钢瓶；网点因安检
           违规被停业 = 配送末梢断档，网点乱收瓶 = 瓶资产流失。帮网点合规存续、
           瓶账守恒 = 保护储配站自己的资产负债表；
           月底对账（站—点瓶数两本账）从对口水账变成对一份守恒体检
         → 瓶安单动机：一个储配站背后是 10~200 家活跃网点，获客成本 ≈ 0
         ② 燃气器械经销商分佣：软管/减压阀经销商的下游正是需要隐患整改耗材的网点，
           按成交 20% 分佣（耗材商亦复用购销逻辑，进迭代池）
         ③ 安检季场景：年度安检季（旺季前）与专项整治节点（通报发布后）集中转化
```

每层渠道都已有真实存在的服务商（储配站、器械经销商）——不需要发明新的中间商，只需给他们一个更好送的商品。**一级储配站是全链路里"上游供应商反过来是分销商"的角色，且其渠道动机（配送网络与瓶资产保全 + 站点账对齐）比流量型渠道深一层——供应链即渠道，与翻房单的洗涤厂联营、购销单的县级批发商联营同构，但供应链角色（储配站 vs 洗涤厂/农资批发商）、渠道动机（瓶资产与配送网络 vs 布草周转/赊销保全）与产品本体完全不同。**

---

**阶段三结论**：商业结构成立的关键在"近零成本 + 免费增值 + 储配站渠道复用"；产品差异化在"把配送与安检之间的证明黑箱变成白箱，并顺手把条例的安检义务和隐患整改要求翻译成站长每天看得懂的动作"。所有付费与渠道假设进入阶段四的假设登记册逐一证伪。
