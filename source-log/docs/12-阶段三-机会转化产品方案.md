# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会怎么变成一个可卖的产品？用商业画布与价值主张画布定结构，用蓝海四动作定差异化，用 Kano 裁 MVP，最后把供应链想透——本项目供应链分析的重头戏是**货源链（站点的"闸口"位置）**与**分发链（打包站即渠道）**。

---

## 1. 商业画布（Business Model Canvas）

| 模块 | 内容 |
|---|---|
| **客户细分** | 1~2 人的个体废品站/社区回收点（夫妻站占绝对多数；收金属类的为重度用户）；渠道客户：**打包站/分拣中心**（联营贴牌，见 §6.3）与**再生资源园区管理方**（联营贴牌） |
| **价值主张** | 对站主主：无证明品类当场拦截（该拒的收不进来）、明显低价强制留原因（"白菜价"有了解释）、销赃特征自动点名（"同一人多次"看得见）、登记册两年口径随导随出；对公安/检查：规范登记的台账呈现；对打包站：下游供货站点来路合规的链条保险 |
| **渠道** | 直达：抖音/快手"收电缆判几年"普法场景内容 + 废品行业微信群；渠道：**打包站联营**（下游买家即分销商）、园区管理方联营、回收行业社群分佣 |
| **客户关系** | 免费自助 + 内容号陪跑（判例解读/登记口径/拒收话术内容）；打包站渠道由站长代维护站点关系 |
| **收入来源** | 免费版全功能（月落账 ≤30 笔）；Pro 待验证（H4 假门 ¥59/年）：落账无限 + 登记册自定义抬头 + 月度台账报表；打包站联营年费 ¥1200/站（白标 ≤200 家供货站点）待验证（H5） |
| **核心资源** | 品类风险模板与判例话术库（司法口径跟踪）、"来路单 = 收购自证"品类心智、打包站渠道关系 |
| **关键业务** | 模板内容运营（判例与属地口径跟踪）、渠道拓展（打包站/园区）、留存运营（销赃特征点名与体检） |
| **重要伙伴** | 打包站/分拣中心（渠道 + 场景源：小站货源的真实入口）、再生资源园区管理方、回收行业协会 |
| **成本结构** | 近零边际成本：无服务器账单、无 npm 审计、单人维护；获客内容制作为主要成本 |

## 2. 价值主张画布（Value Proposition Canvas）

**客户侧（废品站主）**

| 客户任务 | 痛点 | 期望收益 |
|---|---|---|
| 收货时判断"能不能收" | 来路好坏全凭眼神，收错了就是刑事案 | 无证明品类当场拦截 + 拒收登记留痕（该拒的收不进来，拒了有记录） |
| 回答"这价行不行" | 压价收货心里打鼓，"白菜价"是推定明知的情形 | 参考价基线提示 + 低价强制写原因——写下来的原因就是查验过的痕迹 |
| 应对公安检查/倒查 | 翻不出"我问了来路"的任何痕迹，烟盒上的字救不了人 | 登记册一键出证（两年保存口径）；被倒查单笔出自证单，出售人签字栏 |
| 警惕异常卖家 | 同一人反复卖铜毫无警觉，出了事才知道 | 销赃特征自动点名（同一人 30 日内高危品类 ≥3 次） |
| 月底跟打包站对账 | 卖了多少车、多少钱全凭脑子，对账扯皮 | 出货台账 + 对账单文本直接发打包站 |

**产品侧**

| 功能 | 减痛 / 创益 |
|---|---|
| 出售人实名底档（建档一次点选复用） | 减痛：第八条登记义务变成顺手动作 |
| 收购落账守门（无证明拦截/低价强制留原因） | 减痛：风险在成交前被拦下，痕迹在成交时被留下 |
| 拒收登记（含"不明人员"） | 创益：拒收从"损失"变成最硬的自证资产 |
| 销赃特征点名 | 创益：司法推定情形第一次有了工具化预警 |
| 三件套出证（登记册/自证单/对账单） | 创益：检查、倒查、对账三场景一本账全覆盖 |
| 全部本地存储 | 减痛：身份证号不出设备，"多登记 = 多把柄"的心理被结构性化解 |

**契合检验**：六个客户任务 ↔ 六项功能一一对应，无"我们做了但没人要"的悬空功能。

## 3. 蓝海战略四动作框架（ERRC）

| 动作 | 内容 | 效果 |
|---|---|---|
| **剔除 Eliminate** | 行情报价、网上拍卖、电子支付、政务报送、物流调度、智能磅硬件、会员营销 | 与工具站/平台/政务系统正面会战的战场全部放弃；数据源与资金合规负担一并剔除 |
| **减少 Reduce** | 登记字段（实名最小集：姓名+证件号+品类+数量+金额+证明）、拒收登记（7 字段）、报告格式（登记册一模板） | 把"系统"从文书工作降为微信级别动作 |
| **增加 Increase** | 无证明品类拦截、低价强制留痕、销赃特征点名、拒收登记、出售人签字栏、登记册两年保存口径、进出两本账 | 把"记个总数"升级为"有档、有拦截、有点名、有出证"的证据链闭环 |
| **创造 Create** | **"来路可证明"**——站主从未体验过的自证资产；拒收记录第一次成为正面资产而非"没赚到的钱" | 非消费者（夫妻站、纸塑点、游商场景）转化为用户 |

## 4. USP（独特销售主张）

> **唯一为废品站设计的收购治安底账：无证明当场拦截，明显低价强制留原因，同一人高频自动点名；登记册给检查，来源单给倒查，对账单给打包站；身份证号只存本机不上云，免费开始。**

- 对比烟盒记账：有档、有拦截、有出证，"我记得"变成"你看台账"；
- 对比进销存 SaaS：它管货管钱管会员（还要你的数据上云），来路单只管来路（身份信息不出设备）——这正是它做不到的那一段；
- 对比政务备案平台：它管备案报送，来路单管日常留痕——互补不竞争。
- 三句话之外的克制：**不说"用了就不会被判刑"，不说登记册等同执法采信**——证据效力边界见诚实条款（docs/13 §6）。

## 5. Kano 模型 → MVP 范围裁剪

| 类型 | 功能 | MVP 取舍 |
|---|---|---|
| 基本型（没有就骂） | 出售人建档、收购落账、拒收登记、出货台账、登记册导出 | ✅ 已做（23/23 测试覆盖核心逻辑） |
| 期望型（越多越好） | 无证明拦截、低价提示与留痕、流水纠错（删误录）、对账单 | ✅ 已做 |
| 兴奋型（超出预期） | 销赃特征点名、实名缺口点名、自证单出售人签字栏、参考价自定义 | ✅ 已做（数据齐了自动出现）；智能秤对接/多站点进 Pro/迭代池（H4 验证后再投入） |
| 无差异（别做） | 行情报价、拍卖、支付、报送、调度、会员营销 | ❌ 永不做（偏离自证底账主线） |

## 6. 供应链分析（重点：货源链的"闸口"位置 + 技术链 + 分发链）

### 6.1 站点侧供应链（货源到打包站——来路单把最重的"闸口暗账"数字化）

再生资源流通链：**游商/居民/装修队/工程退料 → 回收站点 → 打包站/分拣中心 → 加工厂**。站点是来路的"闸口"：闸口不记，全链条说不清；闸口的暗账全部集中在查验与认知两段：

| 环节 | 链路 | 暗账（没人记的部分） | 来路单的动作映射 |
|---|---|---|---|
| 收货 | 游商/居民拉货上门 | 谁卖的我不知道、来路没问、证件没看 | 出售人实名底档：建档一次点选复用，证件号只存本机 |
| 查验 | 看货、问来路、看证明 | 问了什么、看了什么全在脑子里，三天就忘 | needProof 品类强制登记证明信息——没有证明当场拦截，改走拒收登记 |
| 定价 | 随行就市压价收货 | 为什么这个价说不清——"白菜价"是推定明知的情形 | 参考价基线 + 低价强制留原因（折重/行情），写下来就是查验过的痕迹 |
| 拒收 | 来路不明退回 | 拒了就拒了，没有任何记录——"我拒绝过"无处可证 | 拒收登记 30 秒留痕（含"不明人员"）：拒收成为正面自证资产 |
| 出货 | 卖给打包站 | 卖了多少车、多少钱全凭脑子 | 出货台账：去向留痕 + 月度对账单一键发打包站 |
| 存档 | 纸单塞抽屉 | 两年保存全靠柜子不进水，检查前突击补填 | 登记册按月导出（收购 + 拒收 + 查验痕迹），本地数据天然满足两年口径 |

**与政务平台的供应链关系**：备案/报送平台管"你备案了没有"，来路单管"你经营中查验了没有"——报送是平台的事，底账是站点的事。互补不竞争（ERRC 剔除报送）。

### 6.2 产品自身供应链（MVP 的技术依赖链，逐项消除单点故障）

与 pet-handoff / food-sentry / work-proof 等仓库先例同一架构纪律：**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**

| 依赖 | 决策 | 单点故障消除 |
|---|---|---|
| 后端/数据库 | 无（localStorage 本地优先） | 无云账单、无停服；**身份证号不出设备是产品承诺不是技术妥协**；站点网络差照常用 |
| 第三方库 | 无（core.js 纯函数，日期/守门/点名/出证自实现） | 无供应链投毒面；`node --test` 零依赖可测 |
| 分发 | 任意静态服务器（`python3 -m http.server` 3 条命令） | 文档根即部署根，可迁移任意托管 |
| 出证 | 微信文本 + 单文件 HTML（内联样式）+ 系统打印 | 不依赖任何在线渲染/消息服务，检查与打包站零安装 |
| PWA 离线 | sw.js 缓存应用壳（版本化 + `cache:'reload'` 更新） | 断网可用；升级可靠到达 |

### 6.3 分发供应链（获客链路——下游买家即分销商的结构性优势）

```
内容制作（抖音/快手："收一车电缆判几年？"判例场景内容 + 登记册模板引流）
      ↓ 免费工具承接（零摩擦，扫码即用）
直达用户（废品行业微信群 / 回收创业者社群 / 同行转介绍）
      ↓ 规模化放大（本项目独有的渠道结构）
渠道分层：① 打包站/分拣中心联营（B2B2small）：一个打包站吸 10~200 家固定供货小站
         → 站长动机：供货小站被端 = 货源断档 + 货物来源被倒查的链条风险 +
           对账清晰（来路单对账单直达）——帮小站合规存续 = 保护打包站自己的货源与安全
         → 来路单动机：一个打包站背后是成片的活跃小站，获客成本 ≈ 0
         ② 再生资源园区管理方联营：园区即站点聚集地，白标登记册 = 园区规范背书
         ③ 回收行业社群团长分佣：按成交 20% 分佣
```

每层渠道都已有真实存在的服务商（打包站、园区管理方）——不需要发明新的中间商，只需给他们一个更好送的商品。**打包站是全链路里"下游买家反过来是分销商"的角色——供应链即渠道，与购销单的批发商联营、瓶安单的储配站联营同构但领域不同。**

---

**阶段三结论**：商业结构成立的关键在"近零成本 + 免费增值 + 打包站渠道复用"；产品差异化在"把收进来的货与来路说得清的货之间的证明黑箱变成白箱，并顺手记了进出两本账"。所有付费与渠道假设进入阶段四的假设登记册逐一证伪。
