# 13 · 阶段四：产品落地验证闭环

> 本阶段回答：怎么知道做对了？用 DSTE 定主线，用 HDD 把信念变成可证伪的假设登记册，用 OHELM 跑学习循环，用北极星指标对准价值，用第一桶金验证真金白银，用 90 天排期把一切钉进日历。

---

## 1. DSTE 主线（从战略到执行）

DSTE（Develop Strategy To Execution）要求"市场洞察 → 战略意图 → 业务设计 → 执行落地"闭环运转。本仓库的对应交付物见总览（docs/00 §0 表格）。本阶段的任务是执行层：**MVP 范围、假设登记册、学习循环、北极星、第一桶金、90 天排期**。

战略意图一句话：**让几十万小微修理厂第一次用得起"证明自己合规"的账本——把 10 万起步的罚款风险，变成 30 秒的日常动作和一笔顺手记录的收益账。**

## 2. MVP 范围（本仓库已交付）

| 能力 | 说明 | 对应假设 |
|---|---|---|
| 厂店/品目/接收方建档 | 汽修常见危废品目模板预填（代码可编辑，标注"以最新名录与属地要求为准"） | H1 |
| 出入库台账 | 记一笔 30 秒；出库不得超存量（整体拒绝）；数量最小单位 0.1kg / 件，整数运算无浮点漂移 | H1 |
| 红字冲销撤销 | 撤销 = 追加等额反向记录（留审计痕迹），不可静默删除；部分转移的入库拒绝冲销 | H1 |
| 贮存期限预警 | 按批次倒计时，>365 天红灯（固废法第 81 条口径参数化）、预警窗 30 天；FIFO 先出建议 | H3 |
| 接收方资质台账 | 经营许可证号 + 有效期登记，到期预警；出库未关联资质/联单号 → 红线台亮灯并列待补清单 | H3 |
| 红线自查台 | 逐条亮灯 + 法条依据 + "今天做什么"；管理计划备案按年打卡、贮存区检查打卡 | H2 |
| 收益账 | 出库款额按月/品目/接收方汇总，整数分运算 | H4 |
| 迎检包三通道 | 微信文本 / 打印版单文件 HTML（台账明细+存量汇总+资质核验+自查结论+签字栏）/ 直接打印 | H2 |
| 数据自持 | JSON 导出/导入往返一致；100% 本地存储；SW 离线缓存版本化 | H8 |

**MVP 不做**（ERRC 剔除项，同样重要）：联单报送、环境监测对接、审批代办、在线支付、维修工单、多角色权限。

## 3. HDD 假设登记册（H1-H8，全部待真实用户验证）

> 诚实条款：以下每条都标注了**可证伪判据**——判据不过，假设被证伪，产品随之调整或砍掉。我们不把未验证的信念当成果。

| # | 假设 | 现状 | 可证伪判据（90 天内） |
|---|---|---|---|
| H1 | 台账留存：修理厂会持续记账（每周至少一笔） | 待验证 | 第 4 周：≥40% 周新增记账厂；不过 → 重查记账动线（步骤 >2 即再砍） |
| H2 | 迎检真实使用：检查前/检查后会生成迎检包 | 待验证 | 90 天内 ≥30% 活跃厂生成 ≥1 次；不过 → 迎检包形态不对（改成"检查后补台账"场景） |
| H3 | 预警闭环：超期/资质预警被处理（补转移/换证登记） | 待验证 | 红灯处理后 7 天内状态变绿的比率 ≥50%；不过 → 预警降级为弱提示（避免狼来了） |
| H4 | 单店付费：¥99/年 Pro（多店/自定义抬头/年度归档）有人买 | 待验证 | 假门测试：点击率 ≥5% 且真实支付 ≥10 家；不过 → 付费重心全押渠道 |
| H5 | 收集商渠道：收集商愿意为白标联营付 ¥1200/年 | 待验证 | 访谈 15 家收集商，≥3 家付费/签约试点；不过 → 渠道叙事重写（可能收集商要的是"货源锁定"不是"白标"） |
| H6 | 自查闭环：红线台亮灯 → 厂主按"今日行动"完成整改 | 待验证 | 灯 → 行动完成率 ≥40%；不过 → 把法条语言全部改写为口语指令重测 |
| H7 | 收益账粘性：厂主会持续记录出库款额（而不是只记数量） | 待验证 | 记录款额的出库占比 ≥60%；不过 → 收益账降级为可选字段 |
| H8 | 数据自持信任：JSON 导出归档被真实使用（迁移/备份/交检查） | 待验证 | 90 天内 ≥20% 活跃厂导出 ≥1 次；不过 → 检查导出引导文案与时机 |

## 4. OHELM 循环（Objective → Hypothesis → Experiment → Learning → Metric）

每月一个完整循环，90 天跑三轮：

| 轮次 | 目标 | 实验假门 | 学习产出 → 指标回路 |
|---|---|---|---|
| 第 1 轮（月 1） | 记账动线成立 | 10 家种子厂（内容号 + 3 家收集商引荐），只推"30 秒记一笔 + 存量一眼可见" | 记账频次形态（日/周/检查季脉冲）→ 校准 H1 判据与北极星口径 |
| 第 2 轮（月 2） | 迎检场景成立 | 检查季内容投放 + 迎检包打印版 A/B（带/不带签字栏） | 迎检包使用率与打印率 → 校准 H2/H6 |
| 第 3 轮（月 3） | 钱成立 | 单店假门（¥99/年）+ 收集商联营访谈 15 家 | 付费与渠道双判据 → 校准 H4/H5，定第一桶金主攻路径 |

## 5. 北极星指标与护栏

**北极星：周活跃记账修理厂数**（一周内至少 1 笔出入库记录的厂店数）。

为什么是它：危废账的价值密度 = 台账的持续覆盖度；单周断账 = 追溯断链。它直接度量 H1，向上支撑迎检（H2）与付费（H4/H5）。

护栏指标（防北极星被污染）：迎检包周生成数（防"只打印不记账"）、红线灯处理率（防"亮灯即瘫痪"）、JSON 导出数（防数据自持名存实亡）。

## 6. 第一桶金（三路径，诚实排序）

| 路径 | 定价 | 为什么可能成 | 风险 |
|---|---|---|---|
| ① 收集商联营（主攻） | ¥1200/年/商，白标 ≤200 家下游厂 | 上游即渠道（第四次复用且动机三方对齐）；收集商业务员巡收路线 = 现成地推；下游台账齐 = 收集商自身合规安全 | 收集商数字化意愿参差；销售靠人肉访谈冷启动（H5） |
| ② 单店 Pro | ¥99/年（多店/自定义抬头/年度归档） | 检查季付费窗口明确；单价低于一次执法餐饮成本 | 小店付费心智弱（R2），只做假门不压注（H4） |
| ③ 内容与培训 | 检查季"迎检清单"内容 + 修理厂社群团购 | 获客与收入同源；边际成本近零 | 不易规模化，定位为获客燃料而非利润中心 |

**第一桶金成立的标志**：90 天内出现第一笔真实支付（路径①或②），金额 ≥ ¥1200——这笔钱买断的是"假设"，不是"情怀"。

| 周 | 里程碑 | 判据钩子 |
|---|---|---|

## 8. 诚实条款（边界与免责）

- **已验证**（本仓库内可复现）：核心逻辑单元测试全绿（守恒校验、整体拒绝、红字冲销回滚、FIFO、超期计算、资质预警、收益汇总整数分、迎检包文本/HTML 确定性输出、XSS 转义、导入导出往返）；浏览器端到端全流程；零 npm/CDN/API 依赖；SW 缓存版本化。
- **未验证**：H1-H8 全部商业假设标注"待验证"并配可证伪判据——技术可行 ≠ 商业成立。
- **法律边界**：本工具是产废单位的自查台账与整改指引，**不构成法律意见，不替代法定申报与转移联单报送，不宣称司法级存证**；危废品目代码、罚则口径、贮存要求均参数化并标注"以最新《国家危险废物名录》、现行《固体废物污染环境防治法》及属地生态环境部门要求为准"；属地规则永远赢。
- **数据边界**：数据 100% 本地存储于用户设备，无服务器无账号；设备丢失 = 数据丢失，JSON 导出归档是用户自持的唯一备份通道（产品内引导）。
