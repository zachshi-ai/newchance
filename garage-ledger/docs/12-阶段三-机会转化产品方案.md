# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会怎么变成一个可卖的产品？用商业画布与价值主张画布定结构，用蓝海四动作定差异化，用 Kano 裁 MVP，最后把供应链想透——本项目供应链分析的重头戏是**危废收集-转移-处置链条**（台账即链条的交接凭证）与**分发链**（危废收集商即渠道，上游即渠道的第四次复用）。

---

## 1. 商业画布（Business Model Canvas）

| 模块 | 内容 |
|---|---|
| **客户细分** | 小微机动车维修业户（快修店/轮胎店/综修厂/钣喷店，1~10 工位、夫妻店为主、无会计无 EHS 岗）；连锁快修单店（对上报送的底稿需求）；渠道客户：**持证危废收集商 / 废矿物油与废铅蓄电池回收企业**（联营贴牌，见 §6.3） |
| **价值主张** | 对厂主：每一滴废油可追溯、贮存超期先知道、接收方资质到期先预警、迎检包一键装订、废油卖了多少钱一笔账；对收集商：下游货源台账齐 → 货源合规锁定 + 自身连带风险下降 + 白标品牌触达 |
| **渠道** | 直达：抖音/快手"环保检查罚了多少"场景内容 + 修理厂主微信群；渠道：**危废收集商联营**（上游供应商即分销商）、配件城/油品经销商柜台、县域修理厂社群 |
| **客户关系** | 免费自助 + 内容号陪跑（迎检清单/台账模板内容）；收集商渠道由商家业务员代维护（业务员本来就要挨家巡回收油） |
| **收入来源** | 免费版（单店全功能）；Pro 待验证（H4 假门 ¥99/年）：多店、自定义迎检抬头、年度归档报表；收集商联营年费 ¥1200/商（白标 ≤200 家下游厂）待验证（H5） |
| **核心资源** | 汽修危废品目模板与法条引用库（名录跟踪 + 属地口径）、"危废账 = 产废方追溯账"品类心智、收集商渠道关系 |
| **关键业务** | 模板内容运营（名录/法条/属地口径跟踪）、渠道拓展（收集商/配件城）、留存运营（超期/资质到期预警触达） |
| **重要伙伴** | 持证危废收集/利用企业（渠道 + 行业口径源：回收价行情与联单实务的真实反馈）、静态托管平台、配件城服务商 |
| **成本结构** | 近零边际成本：无服务器账单、无 npm 审计、单人维护；获客内容制作为主要成本 |

## 2. 价值主张画布（Value Proposition Canvas）

**客户侧（小微修理厂主）**

| 客户任务 | 痛点 | 期望收益 |
|---|---|---|
| 把每次产废/转移记下来 | 不记账是默认，纸台账回头再补=永远空白 | 30 秒记一笔，撤销=红字冲销留痕不篡改 |
| 回答"废油存在哪、存了多久" | 桶堆墙角，超没超一年没人知道 | 按批次倒计时红黄灯，最早批次先出建议 |
| 证明"废油给了有资质的人" | 联单号在回收商手机里，换个业务员就断链 | 接收方资质登记 + 有效期预警，出库强制关联联单号（可补录但亮灯） |
| 应对检查 | 翻不出台账、临时抱佛脚 | 迎检包一键生成（台账明细+存量汇总+资质核验+自查结论+签字栏），打印装订 |
| 记废油/旧电瓶的收入 | 现金交易全凭记忆 | 收益账按月按品目自动汇总——合规动作当场兑现成钱账 |
| 管理计划备案与日常自查 | 不知道该做啥、做没做过 | 红线自查台逐条亮灯并给"今天做什么"，备案按年打卡留痕 |

**产品侧**

| 功能 | 减痛 / 创益 |
|---|---|
| 出入库台账 + 守恒校验 + 红字冲销 | 减痛：账实一致、审计痕迹不可静默篡改 |
| 贮存期限按批次倒计时 + FIFO 先出建议 | 减痛：一年红线（固废法第 81 条）从靠运气变有刻度 |
| 接收方资质台账 + 到期预警 + 联单闭环检查 | 减痛：无证委托（处置费 3~5 倍罚）与联单缺失（10 万起步）双红灯前移到日常 |
| 迎检包三通道（微信文本/打印 HTML/直接打印） | 创益：检查不慌，小店第一次有体面的合规档案 |
| 收益账（按月/品目/接收方汇总，整数分） | 创益：合规与变现同一本账，记账有了即时回报 |
| 红线自查台（逐条标注法条依据 + 今日行动） | 创益：合规自查顺手完成，整改有路径 |

**契合检验**：六个客户任务 ↔ 六项功能一一对应，无"我们做了但没人要"的悬空功能。

## 3. 蓝海战略四动作框架（ERRC）

| 动作 | 内容 | 效果 |
|---|---|---|
| **剔除 Eliminate** | 联单报送/在线申报（国家系统的事）、环境监测硬件与第三方检测对接、审批与资质代办（灰域）、在线支付与结算、多角色权限与实施培训 | 与危废 SaaS 正面会战的战场全部放弃；报送义务与灰域风险一并剔除 |
| **减少 Reduce** | 建档字段（厂店 3 项、品目 5 项）、记账动作（选品目 → 填数量两步）、报表格式（迎检包一种模板） | 把"系统"从文书工作降为微信级别动作 |
| **增加 Increase** | 贮存超期按批次倒计时、接收方资质到期预警、红线自查台（带法条依据）、收益账、迎检包双方签字栏 | 把"记台账"升级为"有账、有期限、有凭据、有钱账"的追溯管理闭环 |
| **创造 Create** | **"危险废物的负债与收益一体账"**——产废方从未体验过的追溯透明；废油第一次从"麻烦"变成"有账的资产" | 非消费者（路边店、乡镇店、反 SaaS 老板）转化为用户 |

## 4. USP（独特销售主张）

> **唯一为小微修理厂设计的危废台账：收油卖油 30 秒记账，超期资质先知道，检查来了迎检包一键打印；废油卖了多少钱，顺手就记成账。不做报送、不做监测、不做代办，废油交给谁都能对得上，免费开始。**

- 对比"不记账"：有账、有期限、有凭据、有钱账，"回头再补"变成"当场记完"；
- 对比大企业危废 SaaS：不要钱（单店）、不要学、不要实施，专管 SaaS 不管的那一段（产废方自己的追溯账与迎检）；
- 对比国家联单系统：它是监管追溯通道，危废账是产废方自己的经营底账——互补不替代。
- 三句话之外的克制：**不说"包过检查"、不说"替代联单报送"、不做审批代办**——证据效力边界见诚实条款（docs/13 §6）。

## 5. Kano 模型 → MVP 范围裁剪

| 类型 | 功能 | MVP 取舍 |
|---|---|---|
| 基本型（没有就骂） | 厂店/品目/接收方建档、出入库记账、存量与流水、迎检包导出（文本/HTML/打印） | ✅ 已做（测试覆盖核心逻辑） |
| 期望型（越多越好） | 出库不得超存量（整体拒绝）、撤销红字冲销留痕、超期倒计时、资质到期预警、联单待补清单 | ✅ 已做 |
| 兴奋型（超出预期） | 收益账按月汇总、红线自查台（带法条依据与今日行动）、汽修常见品目模板预填、FIFO 先出建议 | ✅ 已做（数据齐了自动出现）；自定义抬头/多店报表进 Pro/迭代池（H4 验证后再投入） |
| 无差异（别做） | 联单报送、环境监测、审批代办、油配件商城、维修工单 | ❌ 永不做（偏离追溯账主线） |

## 6. 供应链分析（重点：危废链条 + 技术链 + 分发链）

### 6.1 行业侧供应链（危废收集-贮存-转移-处置链——台账就是这条链的交接凭证）

危险废物从修理厂流到最终处置，是一条**持证接力**的供应链：产废（修理厂）→ 收集（持证收集商，区域网络）→ 利用/处置（再生油厂、冶炼厂、处置企业，区域产能不均）→ 联单全程追溯（国家系统）。链条的真实结构决定了产品的三个设计决策：

| 环节 | 链路现实 | 暗账（没人记的部分） | 危废账的动作映射 |
|---|---|---|---|
| 产生 | 换油/钣喷/换电瓶就地产生，容量小、批次碎 | 产了多少全凭记忆，桶满才想起 | 入库即台账：品目/数量/日期落账，按品目存量守恒 |
| 贮存 | 厂内暂存间/桶装，防渗防雨要求（GB 18597 贮存污染控制标准体系） | 存了多久没人计时，一年红线靠运气 | 按批次倒计时红黄灯 + FIFO 先出建议 + 容量预警 |
| 转移 | 上门收集、过磅计价、现金或转账、签联单 | **价格不透明 + 凭据在对方手里**——这是产废方最黑的暗账 | 出库强制登记接收方/数量/款额/联单号，红字冲销留痕；收益账同步落账 |
| 处置 | 再生油厂/冶炼厂最终处置，区域产能集中 | 产废方看不到，也无需看到 | 不越界：链路止于"交给持证接收方 + 联单号"，处置段是监管系统与持证单位的事 |

**行情与产能约束**（供应链分析必须直面）：废矿物油回收价随基础油油价波动，废铅蓄电池按吨/组计价——价格全部**参数化为用户输入**，产品不内置行情（行情是收集商的报价权，做了反而制造错误信息）；区域处置产能不均意味着收集商网络有地缘性——这恰好强化了 §6.3"渠道即区域网络"的分发逻辑。

### 6.2 产品自身供应链（MVP 的技术依赖链，逐项消除单点故障）

与 pet-handoff / food-sentry / turn-sheet / work-proof / class-off 同一架构纪律：**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**

| 依赖 | 决策 | 单点故障消除 |
|---|---|---|
| 后端/数据库 | 无（localStorage 本地优先） | 无云账单、无停服；执法台账与收入数据不出设备；乡镇店网络差照常用 |
| 第三方库 | 无（core.js 纯函数，期限/冲销/守恒/汇总/导出自实现） | 无供应链投毒面；`node --test` 零依赖可测 |
| 分发 | 任意静态服务器（`python3 -m http.server` 3 条命令） | 文档根即部署根，可迁移任意托管 |
| 迎检/导出 | 微信文本 + 单文件 HTML（内联样式）+ 系统打印 + JSON 归档 | 不依赖任何在线渲染/消息服务，检查现场离线可出 |
| PWA 离线 | sw.js 缓存应用壳（版本化 + `cache:'reload'` 更新） | 断网可用；升级可靠到达 |

### 6.3 分发供应链（获客链路——上游收集商即分销商，激励天然对齐）

```
内容制作（抖音/快手："环保检查罚了 X 万，就因为一本台账" 场景内容 + 迎检清单模板引流）
      ↓ 免费工具承接（零摩擦，扫码即用）
直达用户（修理厂主微信群 / 配件城柜台 / 县域修理厂社群）
      ↓ 规模化放大（本项目独有的渠道结构）
渠道分层：① 危废收集商/废油回收企业联营（B2B2B）：商家把危废账白标赠给下游 10~200 家产废修理厂
         → 收集商动机一：下游台账齐 = 货源合规可溯 = 自身不站"非法转移链条"下游（固废法第 80 条连带走）
         → 收集商动机二：台账齐的修理厂是优质货源，白标迎检包落款 = 业务员每次巡收的品牌触达
         → 危废账动机：一个省级废油收集商背后是数百家电厂，业务员巡收路线就是现成的地推网络，获客成本 ≈ 0
         ② 配件城/油品经销商柜台：机油进货柜台是修理厂主的物理聚集地，代理分佣
         ③ 连锁快修总部渗透：单店版自下而上使用，总部需要时升级为报送底稿（不主动销售）
```

每层渠道都已有真实存在的服务商（持证收集商、配件城经销商）——不需要发明新的中间商，只需给他们一个更好送的商品。**危废收集商是全链路里"上游供应商反过来是分销商"且动机三方对齐的角色（收集商要货源合规、修理厂怕罚款、产品要渠道）——供应链即渠道，与翻房单的洗涤厂联营、工据的法律咨询联营、消课单的教具商联营同构但领域不同。**

---

**阶段三结论**：商业结构成立的关键在"近零成本 + 免费增值 + 收集商渠道复用"；产品差异化在"把产生与转移之间的追溯黑箱变成白箱，并顺手记了废油变现的钱账"。所有付费与渠道假设进入阶段四的假设登记册逐一证伪。
