# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会怎么变成一个可卖的产品？用商业画布与价值主张画布定结构，用蓝海四动作定差异化，用 Kano 裁 MVP，最后把供应链想透——本项目供应链分析的重头戏是**车辆服务链**（检测站/维修厂/轮胎机油是车队的上游）与**分发链**（挂靠公司/综检站即渠道）。

---

## 1. 商业画布（Business Model Canvas）

| 模块 | 内容 |
|---|---|
| **客户细分** | 个体货车车主（1~3 台黄牌）、夫妻车队（3~5 台）、小微货运部（10~50 辆，动态监控办法第 22 条点名段）；挂靠公司会计/安全员（名义管 100~500 台，渠道客户见 §6.3）；综检站/维修厂（渠道客户见 §6.3） |
| **价值主张** | 对车主：四只证照钟红黄绿、车龄过线周期自动判档、报警处理有闭环、档案拿得出、路检不心虚；对车队会计：全车队临期一张表、月度小结一键出；对挂靠公司：白标台账让司机觉得"公司在替我管" |
| **渠道** | 直达：抖音/快手"货车被扣车/脱保罚款/年审跑空趟"场景内容 + 卡车司机微信群；渠道：**挂靠公司联营 + 综检站联营**（上游服务商即分销商）、轮胎/机油经销商社群、二手车转营运场景内容 |
| **客户关系** | 免费自助 + 内容号陪跑（年审季提醒话术/罚单解读内容）；渠道客户由挂靠公司/综检站代维护 |
| **收入来源** | 免费版（3 台内全功能）；Pro 待验证（H4 假门 ¥129/年）：3 台以上、多车队报表、自定义迎检抬头；挂靠公司/综检站联营年费 ¥1500/家（白标 ≤50 车）待验证（H5） |
| **核心资源** | 法条口径库（部令条款 → 界面文案的映射表，随部令修订更新）、"车轮账 = 货车合规总账"品类心智、挂靠公司/综检站渠道关系 |
| **关键业务** | 法条内容运营（部令修订跟踪）、渠道拓展（挂靠公司/综检站扫街）、留存运营（证照临期触点） |
| **重要伙伴** | 挂靠公司（渠道 + 真实车队口径源）、综检站（年审季流量入口）、轮胎/机油经销商（高频触点）、静态托管平台 |
| **成本结构** | 近零边际成本：无服务器账单、无 npm 审计、单人维护；获客内容制作为主要成本 |

## 2. 价值主张画布（Value Proposition Canvas）

**客户侧（小微车主/车队会计）**

| 客户任务 | 痛点 | 期望收益 |
|---|---|---|
| 盯住四只证照钟 | 日期在脑子里、证件在遮光板夹里 | 一屏红黄绿倒计时，最急的排最前 |
| 应对车龄周期变化 | 不知道 120 个月后天数减半 | 注册日期建档即自动判档（12↔6 个月） |
| 记技术档案 | 空白档案本，检查前补不了 | 五型流水 30 秒一笔，费用自动进年度账 |
| 处理动态监控报警 | 弹了就划掉，检查拿不出记录 | 三字段闭环归档 + 月度小结带处理率 |
| 年审/卖车/事故后出材料 | 材料散、翻不着 | 一车一档打印版 + 迎检一页纸一键出 |
| 驾驶员证照管理 | 资格证 6 年、诚信考核 12 个月，靠记性 | 双钟倒计时，超 180 日失效提前点名 |

**产品侧**

| 功能 | 减痛 / 创益 |
|---|---|
| 四只证照钟 + 全景紧急排序 | 减痛：红灯（逾期+罚则口径）、黄灯（临期）、绿灯一目了然 |
| 检验周期自动判档 | 创益：部令第 21 条口径内建，车主无需知道规则存在 |
| 技术档案五型流水 + 年度支出 | 创益：一车一档白箱化，养车成本第一次有账 |
| 报警闭环 + 挂账超线点名 | 减痛：处理率 90% 红线的自查仪表 |
| 月度动态监控小结（文本） | 创益：发安全员/存档群，台账义务变成成绩单 |
| 迎检一页纸 / 一车一档打印版 | 创益：路检/审验/卖车三场景的体面材料 |

**契合检验**：六个客户任务 ↔ 六项功能一一对应，无"我们做了但没人要"的悬空功能。

## 3. 蓝海战略四动作框架（ERRC）

| 动作 | 内容 | 效果 |
|---|---|---|
| **剔除 Eliminate** | 货源撮合/派单、油路集采/加油卡、北斗硬件与平台对接、司机社区、多角色权限与实施培训 | 与满帮/G7 正面会战的战场全部放弃；硬件与平台合规负担一并剔除 |
| **减少 Reduce** | 建档字段（车辆 5 项）、记档案动作（6 字段、里程费用可空）、闭环动作（3 字段、日期预填） | 把"系统"从文书工作降为停车场里两分钟的动作 |
| **增加 Increase** | 车龄周期自动判档、红灯法条口径文案、挂账超线点名、月度小结带处理率、一车一档打印版、年度养车支出账 | 把"记日期"升级为"有钟、有档、有闭环、有材料"的合规管理闭环 |
| **创造 Create** | **"营运车的合规确定性"**——车主从未体验过的证照总账与档案白箱；司机侧第一次拿到"帮我对付检查"而非"另一个管我"的工具 | 非消费者（个体车主、夫妻车队、挂靠会计、二手车转入）转化为用户 |

## 4. USP（独特销售主张）

> **唯一为个体货车与小微货运部设计的合规总账：四只证照钟红黄绿倒计时，车龄过线周期自动减半，报警处理一键闭环留痕，迎检一页纸拿出即用。不做货源撮合、不做油路集采、不装硬件、不碰平台，3 台车以内免费，数据不出你的手机。**

- 对比脑子+证件夹：有钟、有档、有闭环，"到日子才办"变成"提前 60 天知道"；
- 对比车队 SaaS：不要钱（3 台内）、不要装硬件、不要实施，专管 TMS 不管的那一段（证照、档案、报警台账）；
- 对比公共平台：它管报警下发与监管归集，车轮账管车主自己的闭环留痕与材料产出——互补不替代。
- 三句话之外的克制：**不说"保证不被扣车"，不说"替代年审与报送"**——证据效力边界见诚实条款（docs/13 §6）。

## 5. Kano 模型 → MVP 范围裁剪

| 类型 | 功能 | MVP 取舍 |
|---|---|---|
| 基本型（没有就骂） | 车辆建档、证照钟红黄绿、技术档案流水、动态监控报警登记与闭环、月度小结、迎检一页纸导出 | ✅ 已做（37/37 测试覆盖核心逻辑） |
| 期望型（越多越好） | 车龄周期自动判档、驾驶员双钟（资格证/诚信考核）、挂账超线点名、年度支出汇总、续期一键办结 | ✅ 已做 |
| 兴奋型（超出预期） | 一车一档打印版（第 15 条形态）、月度小结自带法条口径文本、红灯文案标注罚则依据 | ✅ 已做（数据齐了自动出现）；多车队报表/白标抬头进 Pro/迭代池（H4 验证后再投入） |
| 无差异（别做） | 货源撮合、油路集采、北斗硬件、司机社区、二手车估价 | ❌ 永不做（偏离合规总账主线） |

## 6. 供应链分析（重点：车辆服务链 + 技术链 + 分发链）

### 6.1 车主侧供应链（货运为货主整合的"上游"——车轮账把最碎的一环数字化）

货车把货物送到，其上游最碎的不是油和路，是**车辆自身的服务链**：证照在政府窗口、检测在综检站、维护在修理厂、轮胎机油在经销商——每一环都给车留下一笔"该记的账"。

| 环节 | 链路 | 暗账（没人记的部分） | 车轮账的动作映射 |
|---|---|---|---|
| 证照审验 | 运输证年审/检验检测/保险 | 四只钟分散四处，周期各不相同 | `certBoard` 一屏红黄绿；检验周期按注册日自动判档 |
| 维护修理 | 日常维护/二级维护/视情修理 | 出厂合格证塞进抽屉，档案本空白 | `addRecord` 五型流水，维护/修理/换件逐笔留痕 |
| 检验检测 | 综检+技术等级评定（12/6 个月） | 报告一张纸，次年找不到 | `inspect` 型记录 + 一车一档打印版 |
| 事故处置 | 事故维修与赔偿 | 私了没记录，卖车说不清 | `accident` 型记录（种子数据含"倒车剐蹭私了"实例） |
| 支出对账 | 保险费/检测费/维修费/轮胎钱 | "这车一年养它多少钱"没人答得出 | `vehicleCost` 按年自动汇总，整数分运算 |

**货源与油路供应链**：运价与油费是车主最大的进出项，但那是满帮与两桶油的主场（ERRC 剔除）——车轮账不碰撮合与集采，只把"这台车凭什么一直能上路"这本账记准，它是车主与一切上游谈判的底气。

### 6.2 产品自身供应链（MVP 的技术依赖链，逐项消除单点故障）

与 pet-handoff / food-sentry / class-off 同一架构纪律：**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**

| 依赖 | 决策 | 单点故障消除 |
|---|---|---|
| 后端/数据库 | 无（localStorage 本地优先） | 无云账单、无停服；车牌/驾驶员/费用不出设备；县乡停车场网络差照常用 |
| 第三方库 | 无（core.js 纯函数，月份加法/周期判档/闭环校验/导出自实现） | 无供应链投毒面；`node --test` 零依赖可测 |
| 分发 | 任意静态服务器（`python3 -m http.server` 3 条命令） | 文档根即部署根，可迁移任意托管 |
| 台账/导出 | 月度小结微信文本 + 单文件 HTML（内联样式）+ 系统打印 | 不依赖任何在线渲染/消息服务，安全员零安装 |
| PWA 离线 | sw.js 缓存应用壳（版本化 + `cache:'reload'` 更新） | 断网可用；升级可靠到达 |

### 6.3 分发供应链（获客链路——上游服务商即分销商的结构性优势）

```
内容制作（抖音/快手："交强险脱保被扣车 15 天" "车龄 10 年年审 twice 一年" 场景内容 + 罚单解读引流）
      ↓ 免费工具承接（零摩擦，扫码即用）
直达用户（卡车司机微信群 / 服务区车友 / 二手货车交易群）
      ↓ 规模化放大（本项目独有的渠道结构）
渠道分层：① 挂靠公司联营（B2B2C）：公司把车轮账贴牌赠给挂靠司机（100~500 台/家）
         → 公司动机：司机手续齐 → 公司年审与安全主体责任好交代；白标迎检材料落款 = 公司品牌触达
         → 车轮账动机：一家挂靠公司背后是上百台活跃货车，获客成本 ≈ 0
         ② 综检站/维修厂联营：检测站把车轮账当"售后服务"送（年审季日均几十台车的天然名单）
         → 站里动机：证照不临期 → 客户车况好 → 复检率低口碑好；年审季扫码建档即送
         ③ 轮胎/机油经销商社群分佣：高频触点（换胎 2~4 次/年），团长按成交 20% 分佣
```

每层渠道都已有真实存在的服务商（挂靠公司、综检站、轮胎店）——不需要发明新的中间商，只需给他们一个更好送的商品。**挂靠公司是全链路里"上游服务商反过来是分销商"的角色——供应链即渠道，与翻房单的洗涤厂联营、消课单的教具商联营同构但领域不同。**

---

**阶段三结论**：商业结构成立的关键在"近零成本 + 免费增值 + 挂靠公司/综检站渠道复用"；产品差异化在"把营运车的证照-档案-报警黑箱变成白箱，并顺手记了一车一档与年度养车账"。所有付费与渠道假设进入阶段四的假设登记册逐一证伪。
