## 价值主张画布

- **客户任务**：应付检查（自证合规）、处理投诉（当场判赔）、管住商户（红黄牌+违约追责）、别替商户背锅（先行赔偿要能追回）。
- **痛点**：附表1标准记不住、证书号散在纸堆、检查前一夜补台账、赔出去的钱没人盯追偿、公平秤坏了没人知道。
- **爽点**：登记造册即备案底稿；复秤判定器把吵架变成签字；追偿灯盯着每一笔先赔的钱；强检钟提前 60 天催送检。
- **产品与服务**：一秤一档/强检钟/变动报备/公平秤日检/巡查账/红黄牌/投诉状态机/义务账/三通道出证（对应关系见 README 功能表）。

## 蓝海战略四动作（ERRC）

- **剔除**：云后台、账号体系、支付/溯源/大屏（智慧农贸平台的地盘）、硬件。
- **减少**：配置项减到一页口径参数；每次操作减到一屏一事；学习成本减到「载入示例数据就会」。
- **增加**：复秤判定器（附表1三核称法内置）、55 条赔偿测算器、先行赔偿→追偿闭环灯、备案底稿直出（登记造册表即第5条(五)备案格式）。
- **创造**：「检查来了 30 秒出证」+「投诉当场判赔签字」两个时刻的心智垄断。

## USP（一句话）

> **全场唯一能把《零售商品称重计量监督管理办法》附表1负偏差表和消保法第55条算进处置单的集贸市场台账——秤平不平，账上见。**

支撑点：条号全部一手核验（docs/14）；29/29 单测钉死判定边界；属地口径全参数化。

## Kano 模型

- **基本型（没有就挨骂）**：强检到期钟、登记造册表、投诉留痕。
- **期望型（越多越满意）**：复秤自动判定、55 条测算、红黄牌公示记录、体检打分。
- **兴奋型（没想到会有）**：先行赔偿追偿灯（赔了的钱有人盯）、变动报备后强制重新检定门禁、备案底稿直出（表即第5条(五)格式）、月度小结直接发商户群。

## 供应链分析（三层）

1. **产品自身供应链（零依赖决策）**：无服务器→无账单；无 npm→无投毒攻击面；无 CDN→县域弱网离线可用；无第三方 API→无停服风险。PWA + localStorage + JSON 导出即全部分发与存储。
2. **产品所服务的实物供应链（只做账不碰货）**：电子秤生产→销售→检定→维修→使用全链条（总局整治通知口径），其中「检定」是年复一年的法定触点——产品不碰秤、不碰砝码、不碰强检标志，只把这条链上的法定动作变成台账。秤与检定的实物供给由检定机构和经销商承担，是伙伴不是对手。
3. **分发供应链**：检定机构（强检报告随附账号）→ 计量协会（评价创建辅导打包）→ 经销商（换秤即换账）→ 市监宣贯（演示教材）。不做直销扫街为主力——渠道每次法定触点都是续费提醒。

## MVP 边界（明确不做）

不做电子秤联网采数（第8条鼓励的智能网联秤留给硬件厂）、不代缴罚款、不做在线调解、不做评价评级（属地市监的职权）、不做多市场集团版。MVP 只回答一个问题：**这本账能不能在投诉当下和检查当下替主办者说话。**
