# 秤平账 FairScale ⚖️

> **集贸市场计量合规台账：一秤一档强检钟（第5条(五)登记造册即备案底稿）→ 公平秤按日核账（第5条(六)）→ 周期巡查与红黄牌（第5条(七)/第7条）→ 复秤判定器（附表1负偏差×三种核称法）+ 退一赔三测算（消保法第55条）→ 先行赔偿→追偿闭环（第12条）——鬼秤进不来，检查来了 30 秒出证。**
> 零依赖 · 本地优先 · 免注册 · 可离线 · 数据不出设备

「鬼秤」整治成为常态执法（总局 2023-07 起电子计价秤综合整治、2024-05 公布典型案例）的同一时刻，《集贸市场计量监督管理办法》（**总局令第94号，2025-03-01 施行**，废止 2002 旧办法）把集市主办者推到第一责任位：九项义务（第5条）、红黄牌直至清退（第7条）、罚则三档——**未制止作弊罚 5 万以下、情节严重 10 万以下**（第13条）；短秤缺量消费者可直讨主办者、**主办者先赔后向商户追偿**（第12条），作弊秤欺诈按消保法第55条**退一赔三、不足 500 按 500**。数万家城乡市场的主办者，现状解法还是纸台账+记忆+检查前突击。秤平账把这本账变成白箱：强检钟替你盯证，复秤判定器替你判差，追偿灯替你盯钱。

## 3 条命令跑起来

```bash
cd fair-scale
npm start           # 等价于 python3 -m http.server 8103 --directory app
open http://localhost:8103
```

没有 npm 也可以：任意静态服务器指向 `app/` 目录即可（它就是这个产品的全部）。
首次进入点「**载入示例数据**」，看板上的红灯都是演示钩子，30 秒体验完整投诉闭环。

## 功能

| 模块 | 说明 |
|---|---|
| ⚖️ **一秤一档** | 强检计量器具登记造册（第5条(五)）：器具/经营者/量程分度/检定证书号/检定日/强检标志确认——**本表即向市监部门备案的底稿**；登记缺项（缺证书号/缺标志）体检直接点名 |
| ⏰ **强检钟** | 到期日=检定日+12 个月（JJG 539-2016 口径，属地可参数化覆盖）；临期 60 天黄、告急 15 天红、超期=**不得继续使用**（第9条(三)；细则第43条：责令停止使用+1000 元以下） |
| 🔄 **变动报备** | 新增/减少/更换/维修（第9条(二)）：减少=撤场留痕、更换=停用、维修=检定钟作废——**重新检定录入前恢复不了在用**，杜绝"修完直接摆回台面" |
| 🟢 **公平秤日检** | 公平秤自身也是强检器具+按日砝码试核（第5条(六)保管维护监督检查）：当日绿、昨日黄、中断红，投诉复秤才有公信力 |
| 🧭 **巡查账** | 周期巡查（默认 7 天，第5条(七)发现义务的工具化）：查按键密码/垫泡沫/示值比对公平秤，发现问题当场留处置 |
| 🚩 **红黄牌** | 第7条违法失信公示+违约追责直至清退：出具要写事由（公示要能对上），摘牌要写整改验收 |
| 💬 **投诉状态机** | 受理→公平秤复核（**附表1负偏差×三种核称法**自动判定）→ 处置（经营者退赔/主办者先行赔偿）→ **追偿闭环灯**——先赔的钱没人盯就永远亮红；超 7 天未处置点名（第5条(九)及时处理） |
| 🧮 **复秤判定器** | 四档价格档（≤6/6~30/30~100/>100 元/kg）×称重范围→法定负偏差（粮果蔬 1kg 允 20g、肉蛋水产 2.5kg 允 5g…）；等准确度核称自动放宽 2 倍；**退一赔三测算：价款+退还差价+max(500, 3×价款)** |
| 🗓 **周期义务账** | 台账盘点备案更新（90天）/计量管理员培训/入场协议计量条款审查/诚信承诺组织/年度强检计划——第5条义务节奏化，「及时」口径参数化 |
| 🩺 **九灯体检** | 强检钟/登记缺项/公平秤/巡查/投诉/追偿/红黄牌/义务——确定性扣分，迎检前先自查 |
| 📑 **三通道出证** | **迎检自证包**（单文件 HTML：市场档案+一秤一档备案底稿+变动报备+公平秤日检+巡查红黄牌+投诉先行赔偿追偿+义务账+体检，含盖章签字栏）/ **复秤处置单**（一投诉一单：判定+金额+三方签字）/ **月度小结**（微信文本） |
| ⚙️ **数据自持** | 100% 本地存储，不存消费者身份信息（数据最小披露）；JSON 导出/导入（含结构校验）即离线归档；本地事件流可导出（`complaint_rechecked`、`inspect_generated`、`complaint_recovered` 等 HDD 埋点） |

## 为什么没有后端 / 没有依赖

这不是偷懒，是设计（详见 [docs/12 供应链分析](docs/12-阶段三-机会转化产品方案.md)）：
**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 县域弱网离线可用；无第三方 API → 无停服风险。**
市场管理办公室网络时好时坏，PWA 离线可用；投诉金额与商户信息是主办者最敏感的数据，本地优先=数据不出设备；不存消费者身份信息（最小披露）。**不做电子秤联网采数、不做溯源大屏、不做在线调解、不做评价评级**——智慧农贸平台、检定机构、市监评价体系是互补不是对手，这里是主办者自己的合规底账。

## 诚实条款

法规条号全部一手核验（2026-09-07，出处见 [docs/14](docs/14-调研来源.md)），但**属地细则与市场监管部门要求永远赢**；本工具不替代强制检定、备案、调解、处罚等法定程序与执法认定，金额测算是谈判参考不是司法结论；商业假设（付费/渠道/留存）全部标注"待验证"并配有可证伪判据——我们不把未验证的信念当成果。
