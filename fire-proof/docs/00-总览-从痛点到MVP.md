# 00 · 总览：从痛点到 MVP（防火单 FireProof）

> 机会实验室 **#20 号项目** · 消防救援监管线 · 九小场所/小微公众聚集场所消防安全合规台账。
> 本文档是四阶段方法论的地图：每一个框架都真实应用于本项目（细节见 10~14 号文档），不是模板套话。

## 一句话

**器材有钟、巡查有痕、隐患有闭环——检查来了 30 秒出证**——防火单把九小场所与小微公众聚集场所（小餐饮、小商店、小旅馆、小娱乐、小作坊……）每天真实发生的灭火器检查、防火巡查、隐患整改、培训演练变成拿得出手的自证台账，把"检查前突击补本子"变成"随时打开随时有"。

## 痛点

小微场所站在消防监管的最末端，而末端的法定义务全是周期性的：灭火器要定期检验维修（消防法第 16 条）、公众聚集场所要营业前消防安全检查（第 15 条，未经许可不得营业）、按场所类型要每月防火检查/每 2 小时巡查/每半年培训演练（三类重点场所整治指南）、隐患被通知改正后不消除直接触发第 60 条第（七）项 5000~5 万元罚款、"三合一"未分隔是第 61 条停产停业级风险——而公安派出所**每年至少一次**上门检查（消防监督检查规定第 30 条），查的就是这些记录。2024 年全国接报火灾 90.8 万起、亡 2001 人（国家消防救援局），冬季经营性小场所"小火亡人"被点名。现状是器材年限全凭脑子、巡查本装样子、隐患整改没下文、通知书塞抽屉——**"做了"与"能证明做了"之间，在小微场所这一层没有任何工具承接**。

## 方案

零依赖本地优先 PWA——四本账 + 三只钟 + 一个周期引擎 + 三通道出证：

- **四本账**：灭火器台账（逐具建档、月检四查、同具同日唯一）、防火巡查日结（营业前/营业中/打烊后，四查+异常必写处置）、月度防火检查（八查，对标 5 号令第 35 条与派出所第 31 条清单）、隐患整改闭环（登记→整改→复查销案，通知类必须带文书编号）。
- **三只钟**：灭火器报废钟（水基 6 年/干粉 10 年/CO₂ 12 年，按出厂日自动）、送修钟（3+1/5+2 通识口径）、月检钟（人员密集半月/其他每月）。
- **一个周期引擎**：场所类型（11 类）驱动巡查模式（每 2 小时/昼夜/早晚）、培训周期（人员密集 6 个月）、演练周期（宾馆商场娱乐 6 个月）、月检间隔——老板算不清的口径账，引擎替他算。
- **三通道出证**：月度小结（微信文本）、迎检自证包（单文件 HTML 含签字栏，七段对标派出所检查清单）、隐患整改单（告知-要求-复查-签字，发给责任人/物业/出租方）。

## 快速开始

```bash
cd fire-proof && npm start   # → http://localhost:8097
npm test                     # 纯逻辑层单元测试（node --test，36/36）
```

## 诚实条款

技术可行性已在仓库内验证（36/36 单元测试 + 浏览器端到端：建档 → 示例数据 → 看板红灯 → 月检弹窗闭环 → 隐患销案 → 通知类文书编号强制拦截 → 巡查异常拦截 → 类型切换周期联动 → 月度小结与自证包/整改单下载全链路）；法定条号全部为现行版口径并集中于 docs/14 逐条带出处维护，61 号令全文镜像等检索受限口径已如实标注；不碰消防设施检测与维保、不做许可代办与政府平台接口、不做物联网硬件——检测机构与维保合同是互补不是对手，这里是场所自己的自证底账；台账与出证物是自查底稿，不承诺执法采信，不替代法定检查记录、许可文书与检测报告；周期口径全部参数化，属地规则与最新标准永远赢；商业假设全部标注"待验证"并配有可证伪判据。
