# 12 · 阶段三：机会转化产品方案（防火单 FireProof）

## 1. 商业画布（9 格）

| 格 | 内容 |
|---|---|
| 价值主张 | **器材有钟、巡查有痕、隐患有闭环——检查来了 30 秒出证**：把场所的周期义务变成拿得出手的自证台账 |
| 客户细分 | 九小场所与小微公众聚集场所经营者（餐饮/ retail /宾馆/娱乐/小作坊，1~5 人）；渠道侧：商圈/专业市场/商业街物业管理方、消防技术服务机构 |
| 渠道 | 物业/市场方白标分发（统一管理人即渠道）；消防技术服务机构随器材/检测业务推广；属地商户社群 |
| 客户关系 | 免费基线自服务；检查与整治季（年检、除患行动）是高接触时刻——工具必须在那一刻顶用 |
| 收入流 | 场所 Pro ¥99/年（器材不限量+整改单抬头+三通道出证）；白标 ¥1500/年/项目（50~500 商户+统一抬头） |
| 关键资源 | 已核验的消防法/107 号令/5 号令/整治指南/GB 口径库（本仓库维护）；零依赖技术栈；"检查现场顶用"口碑 |
| 关键活动 | 法定口径维护；落账摩擦持续削减；类型驱动周期引擎的业态覆盖扩充 |
| 重要伙伴 | 物业/市场方（统一管理义务即分销动机）；消防技术服务机构（送修/检测线索互换）；属地商户组织 |
| 成本结构 | 近零边际成本（零依赖本地优先）；主要成本是口径维护人力与渠道让利 |

## 2. 价值主张画布

**客户任务**：①应付派出所年度检查与消防救援机构抽查（第 30/31 条）；②日常别出事（灭火器真能喷、通道真能跑）；③隐患整改有交代（尤其通知类文书）；④别被停业、别丢租约。

**痛点**：器材年限没人记得（报废/送修全靠瓶子说话）；巡查检查留痕坚持不下来；隐患整改没有闭环、通知书没有下文；培训演练"好像搞过"；周期口径自己算不清。

**期望收益**：检查一次通过；台账拿得出手；隐患有头有尾；出事时有"我检过、我巡过、我练过"的底稿。

**产品即止痛与创益**：灭火器三只钟（报废/送修/月检按类型自动）；巡查 30 秒四查+异常必写处置；月度八查防火检查；隐患登记-整改-复查销案（通知类带文书编号）；培训演练年检到期点名；三通道出证（月度小结/迎检自证包/隐患整改单）。

## 3. 蓝海四动作（ERRC）

| 动作 | 内容 | 理由 |
|---|---|---|
| **剔除** | 消防设施检测与维保记录（CMA 机构与维保合同的事，小微场所无此合同）、许可代办、物联网硬件对接、任何报送接口 | 有更强玩家或立场冲突 |
| **减少** | 巡查字段减到四查一键 + 异常才写字；月检四项；隐患登记六字段 | 落账摩擦是生死线 |
| **提高** | 证明的可及性：任何检查场景 30 秒内出齐台账底稿；周期口径的确定性（类型→频次自动判定） | 痛点的第一性变量就是周期证明成本 |
| **创造** | ①**灭火器三只钟**（报废/送修/月检，出厂日一填自动上弦）；②**类型驱动周期引擎**（场所类型→巡查模式/培训/演练/月检周期，法定口径引擎化）；③**通知类隐患销案链**（文书编号+复查+整改单，第 60 条第（七）项的直接对冲）；④三合一红灯与营业前检查状态卡 | 独有结构，也是付费点 |

## 4. USP

- 主 USP：**"你的场所是什么类型，检查口径就自动是什么口径"**——老板算不清的周期账，引擎替他算。
- 副 USP：**"灭火器哪天报废，台账比你先知道"**——器材从"看着还行"变成"日期说话"。

## 5. Kano 分层

- **基本型**（没有就卸载）：灭火器台账与三只钟、巡查打卡、断更与超期红灯。
- **期望型**（越多越满意）：月度八查、隐患闭环与体检打分、培训演练年检点名、月度小结文本。
- **兴奋型**（说出来才想要）：类型驱动周期引擎、通知类隐患销案链与整改单、迎检自证包（八段含派出所第 31 条清单口径）、三合一与营业前检查状态卡。

## 6. 供应链分析（三条链）

### 6.1 内容链（原料）
法规与标准文本 = 免费权威原料：消防法（2021 修正，119.gov.cn 官方全文）、《消防监督检查规定》（公安部令第 107 号，gov.cn）、《高层民用建筑消防安全管理规定》（应急部令第 5 号，mem.gov.cn 官方 doc）、《三类重点场所消防安全整治指南》（国务院安委办行动附件，区政府镜像）、GB 50444-2008 与 GB 55036-2022 承接关系（119.gov.cn 核验）、除患攻坚通知（mem.gov.cn）、2024/2025 火灾统计（国新办/国家消防救援局发布会）——全部官方原文直取（docs/14 逐条带链接）。**供应链决策：不采购任何法规数据库/API**，口径集中维护在本仓库，修订时改一处。

### 6.2 技术链（生产）
零依赖本地优先 PWA：localStorage 单机存储、纯函数逻辑层（Node 可测）、单文件 HTML 出证、无服务器无数据库无第三方 API——**单一供应商是浏览器本身**，断网可用（乡镇店与地下商拍的常态）。数据不出设备：责任人信息只存本机（本地优先即《个人信息保护法》最小披露的实现方式）。

### 6.3 分发链（渠道：统一管理人即渠道，连坐即动机）
- **主渠道：商圈/专业市场/商业街物业管理方白标**。消防法第 18 条要求同一建筑物多个使用单位**明确各方责任并对共用疏散通道、安全出口、建筑消防设施确定责任人统一管理**；应急部令第 5 号第 5 条进一步要求多业主委托统一管理人。商户爆雷（查封/火灾）= 物业的管理责任 + 租金损失 + 整栋楼整改，帮商户合规存续 = 保护物业自己的资产负债表。¥1500/年/项目，白标分发 50~500 个商户——物业还天然需要"每家商户一份消防档案"来应对整栋楼的检查，工具即档案生成器。
- **辅渠道：消防技术服务机构**（维保/检测公司）——小微场所没有维保合同，但灭火器报废/送修 = 器材换购生意线索，年度检测 = 检测合同线索，台账到期点名就是他们的销售漏斗（与 #10 安巡单"培训机构联营"同构但不同对象）。
- **背书渠道**：属地商户社群/行业协会——除患攻坚等整治季前的自查需求是天然获客窗口；保险公司公众责任险投保前自证材料是潜在场景（backlog）。

## 7. MVP 边界

**做**：场所建档与类型驱动周期引擎、营业前检查状态卡（告知承诺三态）、三合一自查红灯、灭火器台账三只钟与逐具月检、防火巡查日结（四查+异常必写+时段唯一）、月度防火检查八查、隐患整改闭环（通知类文书编号+复查销案）、培训演练年检周期账、账本体检九项、三通道出证（月度小结微信文本/迎检自证包单文件 HTML 含签字栏/隐患整改单）、导入导出备份。

**不做**（每一项都有明确不做的理由）：消防设施检测报告与维保记录（CMA/维保机构的事）、物联网烟感与电气监测（硬件生意）、营业前检查申报代办与任何报送接口（立场）、财务进销存（超射程）、多楼层平面图与疏散图绘制（设计工具范畴，backlog）。
