# 13 · 阶段四：产品落地验证闭环（防火单 FireProof）

## 1. DSTE 主线（从市场洞察到执行）

市场洞察（docs/10：高频×高证明刚性空白格 + 派出所年检的法定确定性）→ 战略意图（成为小微场所的"消防痕迹层"标配）→ 创新焦点（灭火器三钟、类型驱动周期引擎、通知类销案链）→ 业务设计（免费基线获客 + 出事时刻付费 + 物业白标放大）→ 执行（本仓库 MVP → 90 天验证 → 渠道复制）。

## 2. MVP 范围（技术验证已在仓库内完成）

- 四本账：灭火器台账（三只钟+逐具月检）、防火巡查日结、月度防火检查八查、隐患整改闭环；外加营业前检查状态卡、三合一自查、培训演练年检周期账。
- 三通道出证：月度小结（微信文本）、迎检自证包（单文件 HTML 含签字栏，七段对标派出所第 31 条检查清单）、隐患整改单（单条隐患的告知-要求-复查-签字）。
- 纯逻辑层全部落进 `core.js` 纯函数，`node --test` 36/36 全绿；单文件 HTML 出证无外部资源、含 XSS 转义；浏览器端到端全链路手测通过。

## 3. HDD 假设登记册（H1~H8，全部可证伪）

| # | 假设 | 可证伪判据（30 天窗口） | 埋点（本地事件流） |
|---|---|---|---|
| H1 | 场所愿意建档并选准类型 | 建档后 7 日内补全类型/责任人/公众聚集标记 ≥60% | `save-place` |
| H2 | 巡查打卡能形成习惯 | 激活后第 4 周周巡查 ≥4 天的场所占比 ≥40% | `patrol`（按日去重） |
| H3 | 灭火器台账真实登记（不是空壳） | 建档场所 14 天内登记 ≥2 具且月检记录当日登记占比 ≥70% | `add-ext`/`ext-check`（dateISO 对照） |
| H4 | 隐患闭环真实走通 | 登记隐患的场所中，30 天内复查销案率 ≥60%；通知类登记带文书编号率 100%（校验强制） | `add-hazard`/`close-hazard` |
| H5 | **迎检自证包真实使用**（最有价值证伪点） | 经历检查的场所中，检查前后 3 天内生成自证包 ≥50% | `inspect-download`/`inspect-print` |
| H6 | 月度八查被执行 | 建档 45 天内出现首条防火检查 ≥50% | `month-check` |
| H7 | 付费意愿成立 | 试用场所 Pro 转化 ≥5%；或出证物累计导出 ≥10 次的场所转化 ≥20% | `paywall-view`→`pro-unlock` |
| H8 | 物业白标渠道成立 | 3 家物业/市场方试用中 ≥1 家付费续用且商户激活率 ≥30% | `channel-seed`（白标装机的场所来源标记） |

最有价值的证伪点：**H5**——如果场所都在落账但没人在检查场景生成自证包，说明"出证"叙事是伪需求，价值主张要重写成纯自查工具。

## 4. OHELM 循环

Objective（小微场所的消防周期义务可自证）→ Hypothesis（H1~H8）→ Experiment（免费基线投放 30~80 场所：1~2 个商圈/市场物业渠道 + 整治季窗口）→ Learning（埋点事件流导出→假设判定）→ Metric（北极星+护栏）→ 下轮迭代（口径/摩擦/定价）。

## 5. 北极星与护栏

- **北极星：周活跃落账场所数**（一周内至少 3 天有巡查打卡的场所）。
- 护栏指标：巡查断更率（有档但连续 ≥3 天无巡查占比，工具红线默认 2 天）——断更即说明工具没进日常，一切付费假设作废；隐患销案率（登记后 30 天内闭环率，产品自己的承诺指标）；自证包生成率（H5 的过程量）。

## 6. 90 天验证排期（与执法与整治节奏对齐）

| 周 | 动作 | 节点依据 |
|---|---|---|
| 1~2 | 仓库 MVP 冻结；找 5 家真实小场所做 30 分钟上手观察 | 修摩擦不改方向 |
| 3~6 | 免费基线投放 30~80 场所（1~2 个商圈/市场物业渠道）；每周导出事件流判 H1~H4 | 常态期养习惯；法定"每年至少一次"派出所检查随时可能落在窗口内 |
| 7~9 | 联系 5~10 家物业/市场方推白标试用（判 H8）；上线 Pro 付费开关（判 H7）；联动 1~2 家消防技术服务机构（送修/检测线索互换试验） | 冬春火灾防控季前：整治=检查密度峰值=工具价值时刻 |
| 10~13 | 实战：盯巡查打卡与自证包生成；首例"通知类隐患销案"案例回访 | 冬春防控季是"小火亡人"高发期也是检查高发期 |
| 13 末 | 判定：北极星 ≥30 且 H2/H4/H5 至少两条通过 → 加渠道复制；否则回到摩擦重做 | 诚实条款：不把兴趣当验证 |

## 7. 诚实条款

技术可行性已在仓库内验证（36/36 单元测试 + 浏览器端到端：建档 → 示例数据 → 看板红灯 → 月检弹窗闭环 → 隐患销案 → 通知类文书编号强制拦截 → 巡查异常拦截 → 类型切换周期联动 → 月度小结与自证包/整改单下载全链路）；法定条号全部为现行版口径并集中于 docs/14 逐条带出处维护，61 号令全文镜像等检索受限口径已如实标注；不碰消防设施检测与维保、不做许可代办与政府平台接口、不做物联网硬件——检测机构与维保合同是互补不是对手，这里是场所自己的自证底账；台账与出证物是自查底稿，不承诺执法采信，不替代法定检查记录、许可文书与检测报告；周期口径全部参数化，属地规则与最新标准永远赢；商业假设（建档留存/巡查习惯/器材真实登记/隐患闭环/自证包使用/付费/物业渠道）全部标注"待验证"并配有可证伪判据。
