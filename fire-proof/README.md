# 防火单 FireProof 🔥

> **九小场所/小微公众聚集场所的消防安全合规台账：灭火器报废/送修/月检三只钟、防火巡查日结、隐患整改闭环（通知类带文书编号）、培训演练到期点名——检查来了 30 秒出证。**
> 零依赖 · 本地优先 · 免注册 · 可离线 · 数据不出设备

九小场所站在消防监管的最末端：灭火器要定期检验维修（消防法第 16 条）、公众聚集场所要**营业前消防安全检查**（第 15 条，未经许可不得营业）、按场所类型要每月防火检查/每 2 小时巡查/每半年培训演练（三类重点场所整治指南）、隐患被通知改正后不消除直接触发第 60 条第（七）项 **5000~5 万元罚款**、"三合一"未分隔是第 61 条**停产停业**级风险——而公安派出所**每年至少一次**上门检查（消防监督检查规定第 30 条），查的就是这些记录。2024 年全国接报火灾 90.8 万起、亡 2001 人（国家消防救援局）。现状是器材年限全凭脑子、巡查本装样子、隐患整改没下文、通知书塞抽屉——防火单把这段黑箱变成白箱：场所建档（类型自动判定全部周期口径）→ 灭火器逐具上三只钟 → 每天 30 秒巡查打卡（异常必写处置）→ 每月一次八查 → 隐患登记-整改-复查销案 → 培训演练到期点名 → 一键出迎检自证包 / 月度小结 / 隐患整改单。

## 3 条命令跑起来

```bash
cd fire-proof
npm start           # 等价于 python3 -m http.server 8097 --directory app
open http://localhost:8097
```

没有 npm 也可以：任意静态服务器指向 `app/` 目录即可（它就是这个产品的全部）。
首次进入点「**先看示例数据**」，30 秒体验完整流程。

## 功能

| 模块 | 说明 |
|---|---|
| 🏪 **场所建档 + 周期引擎** | 名称/类型（11 类）/责任人/公众聚集标记；**类型驱动周期引擎**自动判定巡查模式（宾馆商场娱乐每 2 小时/医疗机构托幼昼夜/其他早晚两巡）、培训周期（人员密集 6 个月）、演练周期（宾馆商场娱乐 6 个月）、灭火器月检间隔（人员密集 15 天/其他 30 天）——法定口径引擎化，属地更严可手动覆盖 |
| 🛡 **营业前检查状态卡** | 公众聚集场所的三态（未申请=红灯"未经许可不得投入使用营业" / 已申请告知承诺待核查 / 已许可带凭证号），消防法第 15 条的场景化 |
| 🧯 **灭火器台账 + 三只钟** | 逐具登记（编号/类型/出厂日/位置）→ **报废钟**（水基 6 年/干粉·洁净气体 10 年/CO₂ 12 年）、**送修钟**（3+1、5+2 通识口径）、**月检钟**（压力/铅封/外观/位置四查，同具同日唯一）自动倒计时；报废红灯明示"停用更换" |
| ✅ **防火巡查日结** | 营业前/营业中/打烊后三时段，四查（用火用电用气/通道出口/器材防火门/重点部位在岗，5 号令第 34 条口径）；异常必须写处置——如实登记是痕迹；打烊档口提示查遗留火种断非必要电源 |
| 🔍 **防火检查月账** | 每月一次八查（通道出口/器材/用电/燃气/住人/防火门/电动车蓄电池/疏散指示），对标 5 号令第 35 条与派出所日常检查清单（第 31 条） |
| 🚨 **隐患整改闭环** | 登记来源（巡查/自查/物业告知/消防救援机构通知/派出所责令改正）→ 期限与责任人 → 复查销案；**通知类必须登记文书编号**（校验强制）——第 60 条第（七）项"通知后不消除"的直接对冲；按"通知超期 > 超期 > 通知在限 > 在限"排序点名 |
| 🎓 **培训演练年检账** | 全员培训/演练/建筑消防设施年度检测三类记录，周期按场所类型自动判定（人员密集培训每半年、宾馆商场娱乐演练每半年、年检仅"有自动消防设施"时适用） |
| 🏠 **三合一红灯** | 经营/储存与住人同建筑的自查判定：未分隔=第 61 条停产停业级红灯；已分隔=重点管理黄灯 |
| 🩺 **账本体检** | 九项灯位打分：营业前许可/三合一/灭火器双钟/月检/巡查断更/防火检查/隐患闭环/培训演练/异常留痕——迎检前先自查 |
| 📑 **三通道出证** | 月度小结（微信文本）/ **迎检自证包**（单文件 HTML 含签字栏，七段全景，检查重点对标派出所第 31 条清单）/ **隐患整改单**（告知-要求-复查-签字，发给责任人/物业/出租方） |
| ⚙️ **数据自持** | 100% 本地存储；JSON 导出/导入（含结构校验）；本地事件流可导出（验证用埋点） |

## 为什么没有后端 / 没有依赖

这不是偷懒，是设计（详见 [docs/12 供应链分析](docs/12-阶段三-机会转化产品方案.md)）：
**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**
小场所在乡镇也在地下商拍，网络时好时坏，PWA 离线可用；月度小结走微信文本，不依赖任何在线服务；责任人信息只存本机（本地优先即《个人信息保护法》最小披露的实现方式）。**不做消防设施检测与维保、不做许可代办、不做物联网硬件、不碰政府平台接口**——检测机构与维保合同是互补不是对手，这里是场所自己的自证底账。
