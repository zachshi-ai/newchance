# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会怎么变成一个可卖的产品？用商业画布与价值主张画布定结构，用蓝海四动作定差异化，用 Kano 裁 MVP，最后把供应链想透——本项目供应链分析的重头戏是**水质耗材链**（药剂/试纸/CMA 的暗账）与**分发链**（泳池水处理药剂/设备经销商即渠道）。

---

## 1. 商业画布（Business Model Canvas）

| 模块 | 内容 |
|---|---|
| **客户细分** | 1~5 个池的小微游泳场所：社区泳培馆（主）、健身房附属泳池、酒店泳池、学校机关泳池；渠道客户：**泳池水处理药剂/设备经销商**（联营贴牌，见 §6.3）与 **CMA 检测机构**（联营） |
| **价值主张** | 对馆主：30 秒两笔打卡、超线强制处置复测闭环、缺检自动点名、迎检台账包一键打印、证照临期预警；对家长/泳客：每天看得见的水质公示，选择泳馆有据；对经销商：白标公示页 = 客户合规存续的增值服务 + 对终端的品牌露出 |
| **渠道** | 直达：抖音/小红书"泳池抽检公示第一现场"/"家长选泳馆先看什么"场景内容 + 泳培馆主社群；渠道：**药剂/设备经销商联营**（上游供应商即分销商）、CMA 检测机构联营、泳培 KOL 社群分佣 |
| **客户关系** | 免费自助 + 内容号陪跑（国标解读/处置话术/公示模板内容）；渠道客户由经销商代维护场馆关系 |
| **收入来源** | 免费版（3 池内全功能）；Pro 待验证（H4 假门 ¥99/年）：多馆多池不限 + 月度小结 + 自定义公示页抬头；经销商联营年费 ¥1500/商（白标 ≤80 家场馆）待验证（H5）；CMA 机构联营 ¥800/年/所（迭代池） |
| **核心资源** | 判定口径与处置话术库（国标/规范跟踪 + 泳池运维通识）、"泳清单 = 水质台账"品类心智、药剂经销商渠道关系 |
| **关键业务** | 口径与模板内容运营（法规跟踪）、渠道拓展（经销商/CMA）、留存运营（未检点名与异常闭环） |
| **重要伙伴** | 泳池水处理药剂/设备经销商（渠道 + 场景源：每周送药上门、认识每个馆）、CMA 检测机构（互补：年度全项报告是台账的证据链上游）、在线监测设备商（互补原料管道，不竞争） |
| **成本结构** | 近零边际成本：无服务器账单、无 npm 审计、单人维护；获客内容制作为主要成本 |

## 2. 价值主张画布（Value Proposition Canvas）

**客户侧（小微泳馆）**

| 客户任务 | 痛点 | 期望收益 |
|---|---|---|
| 每天开放前后测水记录 | 纸台账补抄、检查前突击，"测了白测" | 30 秒两笔落账，读数即判定，缺检自动点名 |
| 超线时处置与复测 | 加了多少药、复测没复测全凭记忆，出了纠纷说不清 | 超线强制处置说明，复测达标才许闭环，处置链完整可查 |
| 应对卫监检查与抽检 | 突击整理档案，缺页断档心里发虚 | 迎检台账包一键打印：体检卡（应检/足额/缺检/达标率/闭环率）+ 逐日明细 + 签字栏 |
| 向家长证明水质 | 公示栏是裱糊，家长看不见，舆情来了自证无门 | 每日水质速报发家长群 + 公示页贴门上发群里，未达标如实标"处置中" |
| 证照与报告管理 | 许可证/健康证/检测报告到期全靠运气 | 临期 30 天自动进"今日"预警 |
| 月底回顾管理质量 | "感觉管得还行"没有数 | 月度小结：达标率、异常次数、平均闭环时长、缺检池·日 |

**产品侧**

| 功能 | 减痛 / 创益 |
|---|---|
| 建档即口径（池型分口径：泳池余氯+pH 必测、浸脚池只管余氯 5~10） | 减痛：判定口径内置，不用背国标 |
| 超线强制处置说明 + 复测闭环链 | 减痛：处置有据、闭环可查（台账里没有裸奔的异常） |
| 缺检点名 + 应检守恒体检卡 | 减痛：突击检查也不虚（应检/足额一目了然） |
| 三通道出证（速报文本/公示页/台账包） | 创益：义务落地与获客资产共用同一份台账 |
| 连续全检天数 streak | 创益：打卡习惯的第一钩子 |
| 证照临期预警 + 月度小结 | 创益：零成本的合规收益与管理复盘 |

**契合检验**：六个客户任务 ↔ 六项功能一一对应，无"我们做了但没人要"的悬空功能。

## 3. 蓝海战略四动作框架（ERRC）

| 动作 | 内容 | 效果 |
|---|---|---|
| **剔除 Eliminate** | 水质在线监测硬件、传感器 API 接入、自动投药控制、法定检测报送、会员/收银/教务、获客营销、多角色权限 | 与监测平台/教务 SaaS 正面会战的战场全部放弃；硬件供应链与报送合规负担一并剔除 |
| **减少 Reduce** | 检测项（日常只留试纸可测的余氯/pH/浊度/水温，尿素等实验室项目归 CMA）、录入（30 秒 5 字段）、档案格式（一个台账包模板） | 把"卫生管理档案"从文书工程降为微信级别动作 |
| **增加 Increase** | 超线强制处置说明、复测闭环链、缺检点名与应检守恒体检卡、连续全检 streak、证照临期预警、月度小结、公示页未达标如实标注"处置中" | 把"抄读数"升级为"有判定、有闭环、有预警、有公示"的证据链闭环 |
| **创造 Create** | **"每天的水质第一次变成家长的可见资产"**——场馆从未有过面向泳客的主动公示工具；自检台账与 CMA 报告第一次合成完整证据链 | 非消费者（泳培夫妻店、健身房附属、酒店后勤）转化为用户 |

## 4. USP（独特销售主张）

> **唯一为小微泳馆设计的水质台账：每天两笔 30 秒，超线强制处置、复测才许闭环；缺检自动点名，迎检台账包一键打印；水质速报发家长群，公示页贴门上——敢晒才是真的干净。不做硬件、不做报送、不做教务，家长不用装 App，免费开始。**

- 对比纸台账：有判定、有闭环、有点名、有公示，"测过了"变成"拿得出"；
- 对比在线监测/智慧平台：它管监测与报送（大场馆与监管端），泳清单管你自己的处置闭环与家长触达（免费）——互补不竞争，仪器读数照样手工落账；
- 对比教务/会员 SaaS：不要钱（3 池内）、不要学、不要实施，专管它们不管的那一段（水质证据链）。
- 三句话之外的克制：**不说"保证抽检合格"，不说台账等同 CMA 报告**——证据效力边界见诚实条款（docs/13 §6）。

## 5. Kano 模型 → MVP 范围裁剪

| 类型 | 功能 | MVP 取舍 |
|---|---|---|
| 基本型（没有就骂） | 场馆/水池/证照建档、每日打卡落账、达标判定、台账导出（文本/HTML/打印） | ✅ 已做（31/31 测试覆盖核心逻辑） |
| 期望型（越多越好） | 超线强制处置说明、复测闭环与删除回滚、缺检点名、重复落账拒绝、证照临期预警 | ✅ 已做 |
| 兴奋型（超出预期） | 应检守恒体检卡、泳客公示页、连续全检 streak、月度小结、口径参数化（属地覆盖） | ✅ 已做（数据齐了自动出现）；多馆/自定义抬头进 Pro/迭代池（H4 验证后再投入） |
| 无差异（别做） | 在线监测、自动投药、法定报送、教务消课、获客通、会员收银 | ❌ 永不做（偏离自检台账主线） |

## 6. 供应链分析（重点：水质耗材链 + 技术链 + 分发链）

### 6.1 场馆侧供应链（消毒到公示——泳清单把最重的两段暗账数字化）

泳馆交付"一池放心的水"，其上游是**药剂链**（消毒剂/絮凝剂，经销商周频配送），中游是**检测链**（DPD 试纸/比色管，月频复购 + 年度 CMA 全项），下游是**信任链**（公示 → 家长选择）。暗账集中在自检与信任两段：

| 环节 | 链路 | 暗账（没人记的部分） | 泳清单的动作映射 |
|---|---|---|---|
| 投药 | 消毒剂/絮凝剂投加（人工或自动投药泵） | 加了多少、何时加的，凭记忆 | 打卡表"加药/补水操作"字段顺手落账 |
| 自检 | 开放前首检 + 开放中抽检（试纸/比色管读数） | 读数抄纸一遍进抽屉，超线也不闭环 | 30 秒落账：读数即判定，超线强制处置说明 |
| 处置 | 加药/补水/换水后复测 | 复测没复测全靠脑子，异常不了了之 | 复测闭环链：达标才许闭环，未闭环挂在首页 |
| 留档 | 卫生管理档案（细则要求保存两年） | 检查前突击补抄，缺页断档 | 应检守恒体检卡 + 逐日明细一键打印包 |
| 公示 | 公示栏/家长群（205 号文成文义务） | 公示是裱糊，注明测定时间的要求形同虚设 | 泳客公示页自动生成（含测定时间），速报文本发家长群 |
| 外检 | CMA 全项检测（尿素/菌落/大肠，年度/泳季前） | 报告锁抽屉，到期没人记得 | 报告登记 + 到期预警，台账落款引用报告编号 |

**与监测平台的供应链关系**：在线监测仪/智慧泳池平台是自检环节的**升级原料管道**——读数从试纸换成仪器，台账动作不变（读数来源无关性）。泳清单不做监测（ERRC 剔除），只承接读数之后的留痕、闭环与公示。原料在别人的管道里，资产在自己的台账里。

### 6.2 产品自身供应链（MVP 的技术依赖链，逐项消除单点故障）

与 pet-handoff / food-sentry / turn-sheet / work-proof / class-off / agri-ledger / car-sheet 同一架构纪律：**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**

| 依赖 | 决策 | 单点故障消除 |
|---|---|---|
| 后端/数据库 | 无（localStorage 本地优先） | 无云账单、无停服；泳客名单与检测读数不出设备；机房/池边网络差照常用 |
| 第三方库 | 无（core.js 纯函数，日期/判定/守恒/出证自实现） | 无供应链投毒面；`node --test` 零依赖可测 |
| 分发 | 任意静态服务器（`python3 -m http.server` 3 条命令） | 文档根即部署根，可迁移任意托管 |
| 出证 | 微信文本 + 单文件 HTML（内联样式）+ 系统打印 | 不依赖任何在线渲染/消息服务，家长零安装 |
| PWA 离线 | sw.js 缓存应用壳（版本化 + `cache:'reload'` 更新） | 断网可用；升级可靠到达 |

### 6.3 分发供应链（获客链路——上游供应商即分销商的结构性优势）

```
内容制作（抖音/小红书："泳池抽检公示第一现场" / "家长选泳馆先看什么" + 水质自检表模板引流）
      ↓ 免费工具承接（零摩擦，扫码即用）
直达用户（泳培馆主微信群 / 泳培教练社群 / 抖音泳池圈）
      ↓ 规模化放大（本项目独有的渠道结构）
渠道分层：① 泳池水处理药剂/设备经销商联营（B2B2C）：每个县城/城区 1~5 家，每家服务 30~200 家场馆，
         每周送药上门、认识每个馆主
         → 经销商动机：场馆被公示停业 = 耗材停购 + 赊销应收坏账 + 续费流失——
           帮场馆合规存续 = 保护经销商自己的流水与资产负债表；
           白标公示页落款 = 经销商对终端的持续品牌露出
         → 泳清单动机：一个经销商背后是 30~200 家精准场馆，获客成本 ≈ 0
         ② CMA 检测机构联营：泳季前检测高峰天然密集触达场馆（¥800/年/所，迭代池）
         ③ 泳培 KOL 社群团长分佣：按成交 20% 分佣
```

每层渠道都已有真实存在的服务商（药剂/设备经销商、CMA 机构）——不需要发明新的中间商，只需给他们一个更好送的商品。**泳池药剂经销商是全链路里"上游供应商反过来是分销商"的角色——供应链即渠道，与翻房单的洗涤厂联营、消课单的教具商联营、购销单的批发商联营、车况单的市场管理方联营同构但领域不同。**

---

**阶段三结论**：商业结构成立的关键在"近零成本 + 免费增值 + 药剂经销商渠道复用"；产品差异化在"把每天真实发生的水质管理与检查者/家长能看见的证明之间的黑箱变成白箱，并顺手记了证照与处置的底账"。所有付费与渠道假设进入阶段四的假设登记册逐一证伪。
