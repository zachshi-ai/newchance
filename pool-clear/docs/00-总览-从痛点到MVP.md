# 00 · 总览：从世界痛点到可运行 MVP

> 项目：**泳清单 PoolClear** —— 小微游泳场所的水质自检台账与泳客信任公示台
> 仓库：`newchance` · 状态：MVP 已开发并通过端到端验证（`app/` 目录，31/31 单元测试 + 浏览器全流程）
> 一句话：**泳馆生意的第一性不是"水干不干净"，是"干净能不能被证明、被相信"——泳清单把每天两笔检测变成台账、把台账变成家长看得见的公示：超线强制处置、复测才许闭环、缺检自动点名、迎检包一键打印、水质速报发家长群。**

## 1. 痛点（真实世界，有据可查）

游泳场所的水质管理是**每天真实发生**的法定动作，而它的"证明"却几乎不存在：

- **自检与公示是成文义务**：[《游泳场所卫生规范》（卫监督发〔2007〕205 号）](14-调研来源.md#法规与政策红线口径的直接依据)要求每场开放前、开放时均应进行池水余氯、pH、温度等检测（室内开放时每 2 小时测一次余氯），**检测结果应公示并注明测定时间**、记录备查；浸脚消毒池水余氯应保持 5~10 mg/L、每 4 小时更换一次。
- **限值被新国标收紧**：[GB 37488-2019《公共场所卫生指标及限值要求》](14-调研来源.md#法规与政策红线口径的直接依据)把人工游泳池水收紧到 pH 7.0~7.8（旧口径 6.5~8.5）、浑浊度 ≤1 NTU（旧口径 ≤5）、游离性余氯 0.3~1.0 mg/L——留痕口径更严，凭感觉加药的时代结束了。
- **不做的代价是阶梯上升的**：[《公共场所卫生管理条例实施细则》](14-调研来源.md#法规与政策红线口径的直接依据)对未按规定检测水质的责令改正、警告、可处 2000 元以下罚款，逾期不改致卫生质量不符标准的处 2000~20000 元，情节严重的责令停业整顿直至吊销卫生许可证——而抽检不合格名单公示一挂，家长用脚投票，损失远大于罚金。
- **台账还有保存义务**：实施细则要求公共场所建立卫生管理档案、分类记录、**至少保存两年**；直接服务顾客的从业人员每年健康检查、持证上岗。
- **现状解法 = 纸台账 + 记忆 + 检查前突击**：试纸比色读数抄在纸上（甚至检查前补抄）、异常处置凭记忆、公示栏是应付检查的裱糊、家长只在出事时才知道水质——**"每天真实发生的水质管理"与"检查者/家长能看见的水质证明"之间，没有任何小微级工具把它接通。**
- 第一性差距：证明成本。把每天的达标变成可查证的记录、把记录送到相信它的人眼前——这两件事的成本决定了泳馆只能选择"不证明"。

## 2. 方案（机会 → 产品）

**泳清单**：零依赖、本地优先的 PWA。

1. **建档即口径**：场馆（名称/卫生许可证号及有效期/电话地址）+ 水池（主池/儿童池/浸脚消毒池，消毒方式、投用日）+ 从业人员健康证 + 第三方全项检测报告——档案字段即台账落款。
2. **30 秒两笔打卡**：读数即判定（余氯/pH 必测，浊度/水温选填；浸脚池只管余氯 5~10）——超线**强制填写处置说明**才能落账；处置后复测达标才算闭环，未闭环异常一直挂在首页。
3. **缺检点名 + 连续全检**：应检 = 天数 × 池数 × 每日频次（默认 2，对应"开放前首检 + 开放中抽检"的规范底线），缺检自动点名到池；连续全检天数是打卡习惯的第一钩子。
4. **三通道出证**（核心交付物）：**每日水质速报**纯文本（微信家长群，主通道）、**泳客公示页**单文件 HTML（贴公示栏/发群，205 号文公示义务的直接落地，未达标如实标注"处置中"）、**迎检台账打印包**（体检卡：应检/足额/缺检点名/达标率/异常闭环率 + 逐日明细 + 签字栏）。
5. **证照临期预警**：卫生许可证（四年）、健康证（年检）、第三方检测报告到期前自动进"今日"预警。
6. **数据自持**：100% 本地存储；限值口径全部参数化（属地口径永远赢）；JSON 导出/导入。

## 3. 诚实的现状声明（真实可落地，不空中楼阁）

- **已验证**（本仓库内可复现）：核心逻辑 31/31 单元测试通过（含国标边界值闭区间、异常强制处置门禁、复测闭环与删除回滚、应检守恒恒等式、缺检点名、证照到期分级、速报/公示页/台账包文本确定性、XSS 转义、单文件无外部资源、导入导出往返）；浏览器端到端全流程（示例数据 → 看板三类预警 → 超线拒绝 → 达标落账 → 复测闭环 → 公示三通道 → 月度体检 → 参数门禁 → 刷新持久化）真实运行通过；零 npm/CDN/API 依赖。
- **未验证**（需真实用户，见 docs/13 假设登记册）：打卡留存（H1）、公示真实使用（H2）、迎检台账真实出示（H3）、付费意愿（H4）、药剂经销商渠道（H5）——全部标注"待验证"并配有可证伪判据。
- **边界与免责**：不做水质在线监测硬件、不接传感器 API、不替代法定检测与报送（尿素/菌落/大肠等实验室项目以 CMA 机构为准）、不做会员收银教务；台账是场馆自检留痕底稿，不宣称司法级存证；**法规原文与属地要求永远赢**。

## 5. 与既有项目的领域隔离（用户约束）

本方向为**游泳场所卫生 · 水质自检台账与泳客信任公示（B2B 小微泳馆 · 公共场所卫生监管线 · 体育服务业）**，登记为机会实验室 **12 号项目**，已对照仓库根 README 领域登记表做领域排除：不与 pet-handoff（C 端宠物照护）、food-sentry（餐饮食安合规台账，市监线）、turn-sheet（民宿退房周转与布草供应链）、work-proof（小微雇主劳动用工合规）、class-off（教培预收费课时账——泳培教务/消课明确不做，属教培领域）、agri-ledger（农资购销台账）、car-sheet（二手车车况披露）、bottle-safe（燃气流通 · 住建/城管燃气监管线）、steril-sheet（口腔诊所器械消毒灭菌追溯 · 医疗机构院感线——同属卫健口但本方向是公共场所卫生，主体从"医疗机构"换成"体育服务场所"、台账对象从"器械灭菌"换成"池水水质"）、safe-patrol（工贸安全生产自查 · 应急管理线）、care-ledger（养老机构服务安全台账 · 民政线）重叠；与同期在建的汽修厂危废台账（机动车维修业废物流，生态环境线）亦不同域。与 `newidea` 仓库 62+ 点子（个人/家庭账本经济学 + 开发者工具）无重叠。付费主体（泳馆与水处理药剂/设备经销商、CMA 检测机构）、使用场景（每日开放前后水质自检与向泳客公示）、行业语境（公共场所卫生监督抽检与夏季泳池舆情）均独立成域。
