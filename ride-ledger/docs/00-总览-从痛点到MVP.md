## 1. 痛点（真实世界，有据可查）

电动自行车是 3.5 亿辆保有量的国民出行工具（通识口径），也是近年公共安全的头号风暴眼——电池起火、非法改装、事故倒查每一次上热搜，监管的探照灯就扫过一次销售门店。门店端被两股政策同时加压（出处见 [docs/14](14-调研来源.md)）：

- **市监线（全链条整治）**：2024 年起的电动自行车安全隐患全链条整治，各地执行口径一致要求销售门店**建立并落实进货检查验收制度、完善购销台账**、组织安全承诺签约、严格核查 CCC 认证，**严禁整车与蓄电池拆分销售**，严打拆改限速与改装蓄电池，推行「一车一池一充一码」；阶段性成效是全国办理案件 **6.1 万起**、查处非法改装黑作坊 **3473 家**——每一家门店都活在被突击检查的概率里。
- **商务线（以旧换新）**：交售的旧车**必须交由具备相关资质的回收企业报废处置，并完善台账管理**（商务部 2025 年度通知解读口径），门店须做到政策图解、价格公示、监督电话、承诺书「四上墙」；2025 年 **8.2 万家**销售门店参加换新、平均拉动单店销售 **30.2 万元**、全年淘汰更新量超 2024 年 **9 倍**——补贴核验认的就是台账。
- **售后与倒查**：电池起火、事故追责时，门店要能一句话说清「卖的是谁、哪辆车、什么电池、哪批进的货」；拿不出进货来源与销售记录的经销商在司法实践中往往直接担责。
- **现状解法 = 合格证扔抽屉 + 车架号懒得抄 + 记忆**：纸台账写在送货单背面、旧车谁拉走全凭记性、顾客回来要质保只能翻抽屉——**两轮车流通最后一公里的台账黑箱没有任何小微级工具承接**。
- 第一性差距：门店的合规生存 = 「进货查验留痕 × 销端三要素（车架号/电池码/3C）× 旧车流向台账」三本账；谁把"记一辆车、出一张凭据"的成本打到 30 秒，谁就把整治风暴变成门店的信任资产。

## 2. 方案（机会 → 产品）

**车销单**：零依赖、本地优先的 PWA。

1. **商品建档 + 3C 红线**：整车/电池/充电器/头盔/配件五类；**整车缺 CCC 证号直接拒绝建档**——进货查验的第一个动作落在数据结构上。
2. **进货建批（采购台账·进端）**：批号 + 首码（首枚车架号/电池编码）+ 供货商，查验留痕即台账；先进先出扣批次，卖出的每一件都能追到哪批进的货。
3. **销售落账（销端台账）**：整车**车架号必填**、电池**电池编码必填**（一车一池一码），缺一拒绝落账；库存不足**整单拒绝不部分入账**；撤销自动回滚。同单整车与电池 = 一车一池；单卖电池未备注用途 → 拆分销售警示灯（非阻断，属地口径永远赢）。
4. **旧车回收台账（以旧换新）**：参考地方商务部门模板字段——旧车品牌、车架号/车牌（必填）、电池数量/重量、回收企业、补贴金额、关联新售单；未挂资质回收企业 → 点名提示。
5. **质保引擎**：质保期从**售出日**起算（月末钳制），临保质保名单（默认 60 天窗）= 主动约顾客免费安检的售后触点 = 换新线索；过保名单 = 售后判责依据。
6. **台账出证三通道**：事故倒查**自证单**按购买人 30 秒生成（车架号/电池码/CCC/批次俱全）；进货/销售/回收台账**微信文本**；**迎检打印包**单文件 HTML（店铺承诺书 + 账实体检 + 四张台账 + 库存盘点）。
7. **账本体检**：进货 = 已售 + 报损 + 库存守恒恒等式；3C/车架号/电池码/回收企业四类台账缺项自查。

## 3. 诚实的现状声明（真实可落地，不空中楼阁）

- **已验证**（本仓库内可复现）：核心逻辑 35/35 单元测试通过（含守恒恒等式、整单拒绝不部分入账、FIFO 批次分配、3C/车架号/电池码红线、拆分销售警示、质保月末钳制、换新台账校验、导出确定性、XSS 转义、导入导出往返）；浏览器端到端全流程（示例数据 → 看板临保预警 → 销售页 → 台账出证四要素核对）真实运行通过；迎检包为单文件 HTML、离线可用；零 npm/CDN/API 依赖；SW 缓存版本化。
- **未验证**（需真实用户，见 docs/13 假设登记册）：落账留存（H1）、车架号登记率（H2）、回收台账真实使用（H3）、临保售后触点（H4）、付费（H5）、代理商渠道（H6）——全部标注"待验证"并配有可证伪判据。
- **边界与免责**：不碰上牌代办、金融分期、改装；3C 证号只做登记与格式校验，真伪以认监委查询为准；属地条例（各省改装罚则差异）永远赢；本地台账不宣称司法级存证；不替代监管平台报送与回收联单。

## 5. 与既有项目的领域隔离（用户约束）

本方向为**电动自行车门店 · 销售与以旧换新合规台账（B2B 小微门店 · 市监产品线 + 商务以旧换新线 · 两轮车流通）**，已对照仓库根 README 领域登记表与 `newidea` 仓库 62+ 点子做领域排除：不与既有项目重叠——宠物照护（C 端）、餐饮食安（市监食品线）、民宿周转、人社用工、教培消课、农药购销（农业农村线）、二手车披露（二手车交易车况）、燃气安检、口腔院感、安全生产自查（应急管理线）、养老九防、泳池水质、废品站收购（公安治安线）均为不同领域方向；也不与 `newidea`（个人/家庭账本经济学 + 开发者工具）重叠。与「二手车披露」的区隔尤其说明：那边是二手车交易环节对消费者的车况披露，这边是新车零售门店自身的购销与回收合规台账——行业（二手车流通 vs 新车零售）、监管抓手（交易披露 vs 全链条整治/换新核验）、付费主体（车商 vs 品牌代理商与门店）均不同域。
