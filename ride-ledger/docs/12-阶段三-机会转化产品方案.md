# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会怎么变成一个可卖的产品？用商业画布与价值主张画布定结构，用蓝海四动作定差异化，用 Kano 裁 MVP，最后把供应链想透——本项目供应链分析的重头戏是**两轮车流通链与旧车回收链**（台账是链条的单据层），以及**分发链**（品牌/电池代理商即渠道）。

---

## 1. 商业画布（Business Model Canvas）

| 模块 | 内容 |
|---|---|
| **客户细分** | 电动自行车零售门店（县乡夫妻店为主，整车 + 换电池 + 配件；8.2 万家换新门店是先行人群）；电池维修小铺（只换电池不卖整车）；渠道客户：**整车品牌县级代理商 / 电池品牌（天能/超威系）县级代理商**（联营贴牌，见 §6.3） |
| **价值主张** | 对门店主：3C/车架号/电池码三条红线当场亮灯、迎检 30 秒出台账包、事故倒查按人出自证单、换新补贴台账备查、质保临期主动售后；对执法者/监管：门店拿得出规范的购销台账与回收台账；对顾客：买的车有据可查、质保有凭据 |
| **渠道** | 直达：抖音/快手"电池起火倒查门店""换新补贴被拒"场景内容 + 电动车一条街扫街；渠道：**品牌/电池代理商联营**（上游供应商即分销商）、换新服务商社群 |
| **客户关系** | 免费自助 + 内容号陪跑（整治/换新政策口径跟踪）；代理商渠道由商家代维护客户关系 |
| **收入来源** | 免费版（单店全功能）；门店 Pro 待验证（H5 假门 ¥99/年）：质保名单导出、自定义台账抬头、换新补贴对账表；代理商联营年费 ¥1500/商（白标 ≤50 家门店）待验证（H6） |
| **核心资源** | 合规台账口径库（整治 + 换新政策跟踪）、"车销单 = 门店台账"品类心智、代理商渠道关系 |
| **关键业务** | 政策口径与台账模板运营、代理商渠道拓展、留存运营（临保质保名单） |
| **重要伙伴** | 品牌/电池县级代理商（渠道 + 政策口径的真实来源）、资质回收企业（台账下游）、静态托管平台 |
| **成本结构** | 近零边际成本：无服务器账单、无 npm 审计、单人维护；获客内容制作为主要成本 |

## 2. 价值主张画布（Value Proposition Canvas）

**客户侧（门店老板）**

| 客户任务 | 痛点 | 期望收益 |
|---|---|---|
| 应付市监检查（购销台账/进货查验） | 合格证塞抽屉，检查翻不出台账 | 进货建批即查验留痕，迎检包 30 秒打印 |
| 电池出事倒查自证 | 说不清卖的是谁、哪辆车、哪批电池 | 自证单按人 10 秒出（车架号/电池码/CCC/批次） |
| 以旧换新拿补贴 | 旧车台账缺失被拒付；旧车拉走没记录 | 回收台账按商务口径字段落账，补贴核验备查 |
| 卖电池规避拆分销售认定 | 不知"整车与电池拆分销售"的红线在哪 | 同单一车一池；单卖电池警示灯 + 备注用途 |
| 质保售后判责 | 不记得谁哪天买的，厂家/门店各执一词 | 质保从售出日起算；临保名单主动售后、过保名单判责 |
| 跟代理商对进货 | 送货单一沓对不清 | 批次台账按供货商聚合，先进先出可追溯 |

**产品侧**

| 功能 | 减痛 / 创益 |
|---|---|
| 整车建档 3C 强制 + 进货查验留痕 | 减痛：检查第一问（查验制度）就有答案 |
| 销端车架号/电池码必填 + 拆分销售警示 | 减痛：一车一池红线落在数据结构里 |
| 自证单三通道（微信文本/HTML/打印） | 创益：倒查时门店第一次"拿得出证据" |
| 旧车回收台账（商务模板字段） | 创益：换新补贴核验备查，回收流向可溯 |
| 质保引擎（售出日起算 + 临保窗） | 创益：免费售后触点 = 换新线索 = 复购 |
| 账实体检（守恒 + 四类缺项自查） | 减痛：迎检前先自扫，缺项就地补 |

**契合检验**：六个客户任务 ↔ 六项功能一一对应，无"我们做了但没人要"的悬空功能。

## 3. 蓝海战略四动作框架（ERRC）

| 动作 | 内容 | 效果 |
|---|---|---|
| **剔除 Eliminate** | 通用进销存的财务/毛利/多仓模块、会员营销、上牌代办、门店金融分期、任何改装相关功能 | 与通用 SaaS 和厂商系统的正面战场全部放弃；牌照类重资产一并剔除 |
| **减少 Reduce** | 建档字段（9 项）、卖单动作（勾商品 → 填编码 → 落账三步）、台账格式（进/销/回收三种模板） | 把"系统"从文书工作降为微信级别动作 |
| **增加 Increase** | 3C/车架号/电池码三条红线、拆分销售警示、旧车回收台账、临保质保名单、账实体检恒等式、迎检承诺书页 | 把"记流水"升级为"有红线、有自证、有门票、有售后"的合规经营闭环 |
| **创造 Create** | **"两轮车流通最后一公里的确定性"**——门店从未体验过的"每辆车说得清来龙去脉"；倒查场景下第一次有拿得出手的自证材料 | 非消费者（夫妻店、电池铺、反 SaaS 老板）转化为用户 |

## 4. USP（独特销售主张）

> **唯一为电动自行车门店设计的合规台账：整车建档强制 3C，卖车落账车架号电池码必填；旧车回收台账补贴核验备查，质保临期主动售后；迎检 30 秒出台账包，倒查按人出自证单。不做进销存财务、不做会员营销、不碰改装，数据不出设备，免费开始。**

- 对比纸面记忆：有红线、有台账、有出证，"回头再记"变成"当场记完"；
- 对比通用进销存：不要钱（单店）、不要学、字段天生为两轮车合规设计（车架号/电池码/CCC/回收）；
- 对比厂商 DMS：它管渠道，车销单管门店自己的底账——互补不替代。
- 三句话之外的克制：**不说"保证过检查"、不说"替代平台报送"**——证据效力边界见诚实条款（docs/13 §6）。

## 5. Kano 模型 → MVP 范围裁剪

| 类型 | 功能 | MVP 取舍 |
|---|---|---|
| 基本型（没有就骂） | 商品建档、进货建批、销售落账、回收台账、台账导出（文本/HTML/打印） | ✅ 已做（35/35 测试覆盖核心逻辑） |
| 期望型（越多越好） | 3C/车架号/电池码红线、FIFO 批次追溯、库存不足整单拒绝、撤销回滚 | ✅ 已做 |
| 兴奋型（超出预期） | 拆分销售警示、临保质保名单、账实体检恒等式、迎检承诺书页 | ✅ 已做（数据齐了自动出现）；质保名单导出/补贴对账表进 Pro/迭代池（H5 验证后再投入） |
| 无差异（别做） | 毛利报表、会员积分、营销群发、上牌代办、金融分期 | ❌ 永不做（偏离台账主线） |

## 6. 供应链分析（重点：流通链 + 回收链 + 技术链 + 分发链）

### 6.1 两轮车流通链与旧车回收链（门店是链条的"单据层"——车销单把最薄的一环数字化）

整车厂 → 品牌代理商（省/县）→ **零售门店** → 消费者；旧车反向：消费者 → **零售门店**（以旧换新）→ 资质回收企业 → 拆解利用。台账就是这条链的单据层，门店是唯一同时面向两个监管线（市监查进销、商务查回收）的节点：

| 环节 | 链路 | 暗账（没人记的部分） | 车销单的动作映射 |
|---|---|---|---|
| 进货查验 | 代理商送货 → 门店验收 | 合格证塞抽屉，查验制度无留痕 | `applyIntake` 建批记批号/首码/供货商，整车批次强制 3C 档案在先 |
| 整车销售 | 交车开票 | 车架号懒得抄，卖出去向模糊 | `applySale` 车架号必填，FIFO 分配到批次，卖出即知哪批进的货 |
| 电池流转 | 整车配电池 / 单换电池 | 一车一池靠口头，拆分销售风险敞口大 | 电池行电池编码必填；同单整车+电池 = 一车一池；单卖电池警示灯 |
| 旧车回收 | 换新交旧 → 资质回收企业 | 旧车拉走没记录，补贴核验缺台账 | `addTradeIn` 按商务口径字段落账（旧车架号必填/电池数量重量/回收企业/补贴/关联新单） |
| 质保售后 | 售出日起 12 个月 | 谁哪天买的没记录，判责靠吵 | 质保引擎按售出日 + 月末钳制；临保名单 = 售后触点，过保名单 = 判责依据 |

**不碰的部分**：厂商与代理商之间的订货/返利（DMS 主场）、门店毛利与财务（通用软件主场）、物流配送（第三方主场）——ERRC 剔除。

### 6.2 产品自身供应链（MVP 的技术依赖链，逐项消除单点故障）

与仓库内既有项目同一架构纪律：**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**

| 依赖 | 决策 | 单点故障消除 |
|---|---|---|
| 后端/数据库 | 无（localStorage 本地优先） | 无云账单、无停服；进货价/车架号/客户姓名不出设备；乡镇网络差照常用 |
| 第三方库 | 无（core.js 纯函数，日期/月份钳制/批次/导出自实现） | 无供应链投毒面；`node --test` 零依赖可测 |
| 分发 | 任意静态服务器（`python3 -m http.server` 3 条命令） | 文档根即部署根，可迁移任意托管 |
| 出证/导出 | 微信文本 + 单文件 HTML（内联样式）+ 系统打印 | 不依赖任何在线渲染/消息服务，收货方零安装 |
| PWA 离线 | sw.js 缓存应用壳（版本化 + `cache:'reload'` 更新） | 断网可用；升级可靠到达 |

### 6.3 分发供应链（获客链路——上游供应商即分销商的结构性优势）

```
内容制作（抖音/快手："电池起火倒查，门店拿不出台账的第一现场" 场景内容 + 回收台账模板引流）
      ↓ 免费工具承接（零摩擦，扫码即用）
直达用户（电动车一条街扫街 / 换新服务门店群）
      ↓ 规模化放大（本项目独有的渠道结构）
渠道分层：① 品牌/电池县级代理商联营（B2B2C）：代理商把车销单贴牌赠给下游 50~300 家门店
         → 代理商动机：下游门店越合规活得越久，进货基本盘越稳；换新放量时代理商出货越多；
           白标迎检包落款 = 代理商每周对门店的品牌触达
         → 车销单动机：一个县级代理商辐射 100~500 家活跃门店，获客成本 ≈ 0
         ② 电池品牌（天能/超威系）代理商：换电池是门店高频业务，电池台账天然带出电池品牌数据
         ③ 换新服务商/回收企业：与门店互为台账上下游，推荐安装即绑定流向协同
```

每层渠道都已有真实存在的服务商（品牌代理商、电池代理商、回收企业）——不需要发明新的中间商，只需给他们一个更好送的商品。**品牌/电池代理商是全链路里"上游供应商反过来是分销商"的角色——供应链即渠道，与翻房单的洗涤厂联营、消课单的教具商联营同构但领域不同。**

---

**阶段三结论**：商业结构成立的关键在"近零成本 + 免费增值 + 代理商渠道复用"；产品差异化在"把两轮车流通最后一公里的台账黑箱变成白箱，并顺手记下旧车流向与质保售后两本暗账"。所有付费与渠道假设进入阶段四的假设登记册逐一证伪。
