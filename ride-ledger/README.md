# 车销单 RideLedger 🛵

> **电动自行车门店的销售与以旧换新合规台账：整车建档强制 3C，卖车落账车架号电池码必填；旧车回收台账补贴核验备查，质保临期主动售后，迎检 30 秒打印台账包。**
> 零依赖 · 本地优先 · 免注册 · 可离线 · 收货方不用装 App

电动自行车是 3.5 亿辆保有量的国民出行工具，也是公共安全的头号风暴眼。全链条整治要求门店落实进货检查验收制度、完善购销台账、核查 CCC、严禁整车与蓄电池拆分销售（全国已办案 6.1 万起）；以旧换新要求旧车交资质回收企业处置并完善台账（2025 年 8.2 万家门店参加、平均拉动单店销售 30.2 万元——补贴核验认的就是台账）。而门店的现状是合格证扔抽屉 + 车架号懒得抄 + 记忆。车销单把这段黑箱变成白箱：整车建档 3C 红线 → 进货建批查验留痕 → 卖车落账三要素（车架号/电池码/3C）→ 旧车回收台账 → 质保临期主动售后 → 迎检包与倒查自证单三通道送达。

## 3 条命令跑起来

```bash
cd ride-ledger
npm start           # 等价于 python3 -m http.server 8094 --directory app
open http://localhost:8094
```

没有 npm 也可以：任意静态服务器指向 `app/` 目录即可（它就是这个产品的全部）。端口被占用时换一个数字即可。
首次进入点「**先看示例数据**」，30 秒体验完整流程。

## 功能

| 模块 | 说明 |
|---|---|
| 🛵 **商品建档 + 3C 红线** | 整车/电池/充电器/头盔/配件五类；**整车缺 CCC 证号直接拒绝建档**（进口数据也逃不过台账体检）——进货查验的第一个动作落在数据结构上 |
| 📦 **进货建批（查验留痕）** | 批号 + 首码（首枚车架号/电池编码）+ 供货商；先进先出扣批次，卖出的每一件都能追到哪批进的货 |
| 🧾 **销售落账（三要素红线）** | 整车**车架号必填**、电池**电池编码必填**，缺一拒绝落账；同单整车+电池 = 一车一池；单卖电池未备注用途 → 拆分销售警示灯（非阻断，属地口径永远赢）；库存不足**整单拒绝不部分入账**；撤销自动回滚 |
| 🔄 **旧车回收台账（以旧换新）** | 参考地方商务部门模板字段：旧车车架号/车牌（必填）、电池数量/重量、回收企业、补贴金额、关联新售单；未挂资质回收企业 → 点名提示 |
| ⏰ **质保引擎** | 质保期从**售出日**起算（月末钳制）；临保质保名单（默认 60 天窗）= 主动约免费安检的售后触点 = 换新线索；过保名单 = 售后判责依据 |
| 🛡️ **台账出证三通道** | 事故倒查**自证单**按购买人 10 秒生成（车架号/电池码/CCC/批次俱全，未查到也如实出具）；进货/销售/回收台账**微信文本**；**迎检打印包**单文件 HTML（店铺承诺书 + 账实体检 + 四张台账 + 库存盘点） |
| ⚙️ **账本体检 + 数据自持** | 进货 = 已售 + 报损 + 库存守恒恒等式；3C/车架号/电池码/回收企业四类缺项自查；100% 本地存储；JSON 导出/导入 |

## 为什么没有后端 / 没有依赖

这不是偷懒，是设计（详见 [docs/12 供应链分析](docs/12-阶段三-机会转化产品方案.md)）：
**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**
乡镇门店网络差，PWA 离线可用；出证走微信文本/打印，不依赖任何在线服务；进货价、车架号、客户姓名不出设备。**不碰上牌代办、不做金融分期、不碰改装**——改装是执法打击对象，工具在结构上不提供任何"改装单"形态。

## 边界与免责

- **不碰上牌代办、不做金融分期、不碰改装、不做监管平台报送**——台账手工录入（这是特性不是缺陷：无牌照负担、离线可用）。平台管核验与报送，这里是门店自己的底账。
- 3C 证号只做登记与格式校验（≥6 位），**真伪以认监委认证查询渠道为准**；台账口径依全链条整治与商务部以旧换新要求整理，**属地条例与属地模板永远赢**，工具亮灯提示不替代法定义务。
- 质保期、临保窗（60 天）、先进先出均为行业通识参数，设置页可覆盖，实际以门店承诺与厂家条款为准。
- 台账与自证单的证据效力以监管部门与法院采信为准，工具不宣称司法级存证；工具不阻止"先卖后补"，**落账的即时性是唯一的皮肤游戏**。
