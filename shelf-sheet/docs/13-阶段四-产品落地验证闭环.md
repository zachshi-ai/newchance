# 13 · 阶段四：产品落地验证闭环（药清账 ShelfSheet）

## 1. DSTE 主线（从市场洞察到执行）

市场洞察（docs/10：高频×高证明刚性空白格 + 劣药罚则按货值倍数计）→ 战略意图（成为单体药店的"效期黑匣子"标配）→ 创新焦点（拒售名册=资产、催销处置单=动销工具）→ 业务设计（免费基线获客 + 检查季付费 + 批发商白标放大）→ 执行（本仓库 MVP → 90 天验证 → 渠道复制）。

## 2. MVP 范围（技术验证已在仓库内完成）

- 四本账：药品建档与批次效期账（三色档）、温湿度日双录（超限处置闭环）、拒售登记簿、养护与隔离报损账；外加双证钟（许可证/药师注册证）与周期义务账。
- 三通道出证：近效期催销处置单（贴柜台双签字）、迎检自证包（单文件 HTML 含签字栏，八段全景）、月度小结（微信文本）。
- 纯逻辑层全部落进 `core.js` 纯函数，`node --test` 26/26 全绿；单文件 HTML 出证无外部资源、含 XSS 转义。

## 3. HDD 假设登记册（H1~H8，全部可证伪）

| # | 假设 | 可证伪判据（30 天窗口） | 埋点（本地事件流） |
|---|---|---|---|
| H1 | 药店愿意建档并填双证信息 | 建档后 7 日内填写许可证有效期 ≥60%；经营处方药的门店填药师信息 ≥50% | `save-pharmacy` |
| H2 | 进货建批能形成习惯 | 激活后第 4 周仍有新增批次或效期动作的门店占比 ≥40% | `add-batch`/`batch-out` |
| H3 | 温湿度日双录能坚持 | 建档 30 天内出现"连续 5 天每日两笔"的门店 ≥35%；漏录补录当日完成占比 ≥60% | `add-reading`（dateISO vs 当日） |
| H4 | 超限处置闭环真实发生 | 超限读数 7 日内处置销案率 ≥80%（不是摆着红灯装没看见） | `handle-reading` |
| H5 | 拒售登记真实发生（不是编的） | 有落账的门店中，30 天内出现 ≥1 条拒售且当日登记占比 ≥70% | `add-refusal`（dateISO vs 当日） |
| H6 | 催销处置单与迎检包被真实使用 | 有红线批次的门店中，7 日内生成催销单 ≥40%；检查季（对照属地检查公告窗口）迎检包导出 ≥50% | `clearance`/`inspect` |
| H7 | 付费意愿成立 | 试用门店 Pro 转化 ≥5%；或出证物累计导出 ≥10 次的门店转化 ≥20% | `paywall-view`→`pro-unlock` |
| H8 | 渠道联营成立 | 3 家批发商/小连锁试用白标中 ≥1 家付费续用且下游激活率 ≥30% | `channel-seed`（白标装机的门店来源标记） |

最有价值的证伪点：**H5**——如果拒售登记量异常高但从不与真实客流匹配（全五星好评式数据），说明"正面资产"叙事被当成表演，价值主张要重写；反过来如果几乎没人登记，说明店员根本顶不住顾客，工具要加"一句话话术"辅助。

## 4. OHELM 循环

Objective（货架上的效期债可见、可证）→ Hypothesis（H1~H8）→ Experiment（免费基线投放 20~50 家药店：区域批发商业务员社群 + 药监检查公告窗口前）→ Learning（埋点事件流导出→假设判定）→ Metric（北极星+护栏）→ 下轮迭代（口径/摩擦/定价）。

## 5. 北极星与护栏

- **北极星：周活跃效期打卡药店数**（一周内 ≥3 天有温湿度记录或效期动作的门店）。
- 护栏指标：温湿度断更率（有档但近 3 天缺笔占比）——断更即说明工具没进日常，一切付费假设作废；过期在架红灯存续时长（从点亮到清零的天数，产品自己的承诺指标）；拒售登记当日率（H5 的过程量）。

## 6. 90 天验证排期（与行业节奏对齐）

| 周 | 动作 | 节点依据 |
|---|---|---|
| 1~2 | 仓库 MVP 冻结；找 5 家真实单体店做 30 分钟上手观察 | 修摩擦不改方向 |
| 3~6 | 免费基线投放 20~50 家（1~2 个区域批发商业务员社群）；每周导出事件流判 H1~H5 | 淡季养习惯 |
| 7~9 | 联系 5~10 家区域批发商/小连锁总部推白标试用（判 H8）；上线 Pro 付费开关（判 H7） | 医保飞检与药监日常检查密集期前的窗口 |
| 10~13 | 检查季实战：重点盯温湿度连续性与催销单使用；首个"迎检包真实出示"案例回访 | 检查季是最大的验证现场 |
| 13 末 | 判定：北极星 ≥50 且 H2/H3/H5 至少两条通过 → 加渠道复制；否则回到摩擦重做 | 诚实条款：不把兴趣当验证 |

## 7. 诚实条款

技术可行性已在仓库内验证（26/26 单元测试 + 浏览器端到端全链路）；商业假设（建档留存/建批习惯/双录坚持/拒售真实登记/出证真实使用/付费/批发商渠道）**全部待验证**并配有可证伪判据；工具不替代法定报送、许可文书与追溯系统，不碰进销存财务与医保结算；温区限值与近效期阈值全部参数化，药品说明书标示的储藏条件、属地规则与连锁制度永远赢；打印与导出物是自查底稿，不承诺执法采信；药店数量与行业数据为宽区间口径（见 docs/14）。
