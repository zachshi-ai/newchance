# 10 · 阶段一：识别机会与洞察市场

> 本阶段回答：世界的哪个痛点值得做？用第一性原理拆到底，用 JTBD / 船模型 / 非消费者分析还原真实场景，用 PESTEL 扫宏观，用机会缺口矩阵定位空白。

---

## 1. 第一性原理拆解

不问"市面上有什么餐饮 SaaS"，只保留不可再分的事实：

| # | 不可再分的事实 | 推论 |
|---|---|---|
| F1 | 外出就餐是城市化刚性；中国餐饮门店 900 万+ 家（红餐网口径），每一家都是合规主体 | 市场基数由"持证主体数"决定，与消费波动弱相关 |
| F2 | 监管无法时刻盯着后厨；检查与追责的载体是**记录（台账）** | 食品安全治理的本质是证据制度，不是道德号召 |
| F3 | "做了" ≠ "能证明做了"；证明需要持续、规范、可出示的记录 | 证明成本是合规率的决定变量——成本越高，补填与侥幸越多 |
| F4 | 现状：纸质台账本 + 记忆补填，记录动作与经营动作在时间上分离 | 分离必然失真：检查前突击补填是理性行为，不是素质问题 |
| F5 | 60 号令把证明义务制度化：日管控/周排查/月调度三类记录，未建立可罚 5 千~3 万 | 需求由法规供给，不是教育出来的；且有明确的违规成本锚点 |
| F6 | 老板手机 + 收款码已普及；小店数字化能力 = 微信 + 扫码级别 | 交付形态必须是"打开就填、填完就走"，任何培训成本都是流失 |
| F7 | WHO：全球每年约 6 亿人因污染食品患病、42 万人死亡 | 一旦出事，"无记录"直接放大责任（十倍赔偿风险，法释〔2020〕14 号） |

**第一性结论**：解的本质不是"再造一个收银/进销存 SaaS"（那是船），而是**把"证明"本身的成本打到趋近于零**——打卡 30 秒、汇总自动、打印一键。谁把证明成本降一个数量级，谁就拿下这个被法规供养的需求。

## 2. 痛点 - 爽点 - 痒点模型（梁宁）

| 层 | 用户心理 | 食安哨对应 |
|---|---|---|
| **痛点**（恐惧/怕） | 怕检查翻台账时缺页断档；怕警告与 5 千~3 万罚款；怕出食安事故时拿不出记录，十倍赔偿全责扛 | 每日打卡自动留痕，漏检项首页点名，异常强制留整改说明——直接对冲"证明不了"的恐惧 |
| **爽点**（即时确定性） | 检查前一天，一键打出整整一册规范台账，签字栏都留好了 | 台账导出：选日期 → 打印版单文件 HTML，10 秒出册 |
| **痒点**（虚拟自我） | "我家后厨的台账，整齐得像连锁品牌" | 排印规范、盖章式完成率、连续全勤天数——小店老板的"规范经营者"身份叙事 |

优先级：痛点 > 爽点 > 痒点。MVP 只做痛点与爽点，痒点靠完成率与全勤提示顺手满足，不做社区/排行。

## 3. JTBD（待办任务）

**主任务陈述**：**当**日常经营中监管要求留痕、或检查/飞检临近时，**我要**用最小代价证明"我每天都在做该做的事"，**以便**不被处罚、出了事有据减责、心里不慌。

三维拆解：

| 维度 | Job | 现状方案的失败点 |
|---|---|---|
| 功能性 | 记录晨检、进货查验、消毒、留样、废弃物处置；汇总成周报月报 | 纸质本靠记忆补；周报月报格式不会写 |
| 情感性 | 检查来了不慌、不心虚 | 突击补填的台账自己都不敢看第二眼 |
| 社会性 | 向监管、向顾客证明"我是规范经营的老板" | 没有任何体面的凭据化载体 |

**竞品不是别的 App，而是"纸质台账本 + 什么都不记 + 检查前找人代办"**——它们免费或一次性、零学习成本，这是我们真正的敌人（见阶段二波特五力：替代品威胁）。

## 4. 船模型

> 用户要的从来不是船，是安全过河。这里河对岸 = 检查通过 + 事故免责。

| 元素 | 本场景 | 现状问题 |
|---|---|---|
| 乘客 | 小微餐饮老板（兼食品安全员） | — |
| 船 A：纸质台账本 | 淘宝 5~30 元/套，单品百人付款 | 便宜，但记录靠记忆补填，动作与经营分离；无汇总、无预警 |
| 船 B：连锁级食安 SaaS | 为大企业设计：多角色权限、硬件、实施培训 | 贵、重、学习成本高，小店"用不起也用不会" |
| 船 C：找人代办/代账 | 存在于市面的灰色服务 | 黑箱甚至代你"编"记录；检查时笔迹一致反成风险 |
| 船 D：官方追溯平台（浙食链等） | 政府侧系统，免费 | 以进货追溯为主、各省分散；老板当任务是负担，非全环节台账 |
| 河 | **"做了但证明不了"的证据鸿沟** | 四条船共同的黑水区 |

**定位推论**：食安哨**不造船**，做给所有船统一配发的**"黑匣子"**——把每天的合规动作自动变成可出示的证据。与官方平台是互补（打印件可贴可存、口径一致），与纸质本正面竞争但迁移成本≈0，与连锁 SaaS 错位竞争。

## 5. 非消费者分析（Christensen）

| 非消费者类型 | 画像 | 为什么不用现有解 | 对产品的启示 |
|---|---|---|---|
| 从不做台账的小店 | 大多数夫妻店 | 不知道监管到底要记什么、记多少 | 模板**预设结构**：按业态预填 6 项 + 法规依据一句话，空白页变填空题 |
| 买纸质本突击补填的 | 有合规意识、无执行习惯 | 天天手写坚持不下来，只在检查前补 | 打卡与经营同步（开店/闭店各 30 秒）；漏检自动点名 |
| 被 SaaS 价格/复杂度劝退的 | 想数字化但被实施门槛吓退 | 月费、多角色、要培训 | 免费开始、零培训、3 分钟建档 |
| 让员工代管的 | 老板不在店 | 授权后失察，出事才知道 | 健康证到期预警 + 异常整改留痕，老板远程可查 |

非消费者共同阻碍排序：**不知道记什么（知识门槛）> 坚持记太麻烦（执行成本）> 记了怕丢（保管）**。MVP 依次对应：业态模板、30 秒打卡、本地存储 + JSON 备份。

## 6. PESTEL 宏观扫描

| 维度 | 要点 | 对本机会 |
|---|---|---|
| **P** 政治 | 60 号令强制"日管控/周排查/月调度"；"四个最严"监管基调；地方细则分级落地（重庆明确大中小型主体均需建立执行） | 需求由法规直接供给；只收紧不放松，顺风 |
| **E** 经济 | 2024 餐饮收入 5.57 万亿（+5.3%）；47.8% 持续经营商户下调人均价位——小店利润被压缩 | 对费用极度敏感 → 免费增值（免费打卡 + 未来 Pro）是唯一可行定价 |
| **S** 社会 | 食安事故舆情极敏感（学校/外卖）；"明厨亮灶"培育了"看得见的合规"心智；小店主数字化基线 = 微信 + 收款码 | 工具必须做到扫码级易用；合规开始成为经营身份的一部分 |
| **T** 技术 | 无统一官方商户端 API；PWA/打印为系统级能力；纸质本仍是默认解 | 本地优先 + 打印双通道恰好规避平台依赖；无 API 不是缺陷是护城河（无需接口授权） |
| **E** 环境 | 纯软件，无硬件/冷链/物流；唯一物理出口是打印（小店打印机已普及或可用打印店） | 供应链极轻（详见 12 供应链分析） |
| **L** 法律 | 未建制度：警告 → 5 千~3 万罚款；法释〔2020〕14 号：违反日管控等要求可构成"明知"，消费者可主张十倍赔偿 | 记录同时是**免责/减责证据**——法律环境是结构性顺风 |

结论：宏观无逆风，P（法规强制）与 L（证据价值）是双顺风；E（价格敏感）约束商业模式但不约束机会成立。

## 7. 机会缺口矩阵

以"用户重要性 × 市场现有解完整度"定位空白：

```
重要性 高 │ ①收银/外卖/进销存       ③【空白】食安合规证据链
          │ （美团收银等，红海）      （台账打卡→周报月报→迎检打印，无小店级产品）
          │
重要性 低 │ ②排班/会员工具          ④老板个人记账
          │ （泛滥，免费方案多）      （已有多个）
          └─────────────────────────────
             现有解完整度 高            低
```

- ③的四段拆解交叉验证：纸质本（无汇总无预警）、官方追溯（只管进货、平台思维）、连锁 SaaS（服务大客户）、代办（黑箱）——**每一段都有人做，合起来无人做**。
- ①②是"高频低恐惧"陷阱：频率高但无合规锚点、付费动机弱；③频率低（每日 30 秒）但违规成本明确（5 千~3 万）、检查节点天然制造付费时刻。
- ④与本产品无冲突：食安哨管"对外合规证明"，不是又一本个人账本。

**阶段一结论**：食安哨占位 ③——一条被 60 号令供养、被纸质台账本证明付费行为存在、却被所有软件产品忽略的缺口。
