# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会怎么变成一个可卖的产品？用商业画布与价值主张画布定结构，用蓝海四动作定差异化，用 Kano 裁 MVP，最后把供应链想透。

---

## 1. 商业画布（Business Model Canvas）

| 模块 | 内容 |
|---|---|
| **客户细分** | 小微餐饮老板（夫妻店/小吃/饮品，兼食品安全员）；单位·学校食堂（食堂模板）；渠道客户：食安代账公司（白标） |
| **价值主张** | 对老板：30 秒打卡 → 检查前一天一键打印台账，"做了就能证明"；对食堂：留样等强制项模板化；对代账：一个客户 5 分钟交付的标准化工具 |
| **渠道** | 直达：抖音/视频号"食安检查"内容 + 微信社群；渠道：代账公司分销、餐饮协会、收银 SaaS 捆绑 |
| **客户关系** | 免费自助 + 打卡提醒（本地通知）+ 内容号陪跑（法规更新速递） |
| **收入来源** | 免费版（单店打卡/导出全功能）；Pro 待验证（H4 假门）：多门店、监管格式套版、云端备份；渠道批发价 |
| **核心资源** | 法规模板内容库（按省/业态持续运营）、"食安哨=小店台账"品类心智、渠道关系 |
| **关键业务** | 模板内容运营（属地细则跟踪）、渠道拓展、留存运营（打卡提醒/全勤激励） |
| **重要伙伴** | 代账公司（分销）、餐饮协会/市场监管培训场景（免费普及）、静态托管平台 |
| **成本结构** | 近零边际成本：无服务器账单（本地优先）、无 npm 审计、单人维护；获客内容制作为主要成本 |

## 2. 价值主张画布（Value Proposition Canvas）

**客户侧（小店老板）**

| 客户任务 | 痛点 | 期望收益 |
|---|---|---|
| 日常合规留痕（晨检/进货/消毒/留样/废弃物） | 不知道记什么；天天手写坚持不了 | 记录完整、随手可查 |
| 应对检查/飞检 | 检查前翻台账心虚，突击补填 | 10 秒打出一册规范台账 |
| 事故免责 | 拿不出记录 = 十倍赔偿风险 | 有记录、有整改闭环可出示 |
| 员工管理 | 健康证过期了才知道 | 到期前 30 天预警 |

**产品侧**

| 功能 | 减痛 / 创益 |
|---|---|
| 业态模板 + 法规依据一句话 | 减痛：空白页变填空题（不知道记什么 → 打开就填） |
| 30 秒打卡 + 漏检点名 | 减痛：执行成本趋近于零（坚持不了 → 顺手完成） |
| 周报/月报自动汇总 | 创益：60 号令三类记录中两类白送 |
| 一键打印版台账（单文件 HTML + 签字栏） | 创益：检查时刻的确定性——爽点兑现处 |
| 健康证 30 天预警 | 减痛：从"出事才知道"到"提前一个月" |
| 本地存储 + JSON 备份 | 减痛：数据在自己手里，不怕平台跑路 |

**契合检验**：四个客户任务 ↔ 六项功能一一对应，无"我们做了但没人要"的悬空功能。

## 3. 蓝海战略四动作框架（ERRC）

| 动作 | 内容 | 效果 |
|---|---|---|
| **剔除 Eliminate** | 多角色权限体系、进销存/库房管理、硬件（测温枪/监控接入）、实施与培训 | 成本与复杂度的来源全砍；交付物只剩"打卡→出证" |
| **减少 Reduce** | 每日记录字段（一屏 6 项、每项 5 秒）、建档步骤（3 项必填）、报告格式（两版通用模板） | 把"合规"从文书工作降为扫码级动作 |
| **增加 Increase** | 迎检一键打印册（含签字栏）、健康证预警、异常整改闭环留痕、完成率/连续全勤可视化 | 把"应付检查"升级为"随时拿得出手"的确定性 |
| **创造 Create** | **"检查前夜不慌"**——小店老板从未体验过的合规从容感；台账即"规范经营者"身份凭据 | 非消费者（从不记录的店）转化为用户 |

## 4. USP（独特销售主张）

> **唯一为小店设计的食安台账工具：30 秒打卡留痕，一键打印迎检台账——不查库房、不管进销存、不用培训，免费开始。**

- 对比纸质本：会自动汇总、会预警、丢不了；
- 对比连锁 SaaS：不要钱、不要学、不要实施；
- 对比官方平台：全覆盖你店的日常台账，不只进货那一环。
- 三句话之外的克制：**不说"替代法定报送"，不说"包过检查"**——证据效力边界见诚实条款。

## 5. Kano 模型 → MVP 范围裁剪

| 类型 | 功能 | MVP 取舍 |
|---|---|---|
| 基本型（没有就骂） | 每日打卡记录、台账打印导出、门店建档 | ✅ 已做（24/24 测试覆盖核心逻辑） |
| 期望型（越多越好） | 周报/月报自动汇总、健康证预警、异常整改闭环、漏检点名 | ✅ 已做 |
| 兴奋型（超出预期） | 监管格式套版导出、连续全勤徽章、多店切换、打卡照片存证 | ⬜ 刻意不做，进 Pro/迭代池（H4 验证后再投入） |
| 无差异（别做） | 社区排行、社交分享、积分商城 | ❌ 永不做（偏离证据链主线） |

## 6. 供应链分析（重点：三条链）

### 6.1 产品侧供应链（食安哨为用户整合的"上游"）

用户要的最终产品是"合规证明"，其上游是一条**内容与制度链**，全部公开可得、无实物货流：

| 环节 | 来源 | 风险与对策 |
|---|---|---|
| 法规制度源 | 市场监管总局 60 号令、《食品安全法》、《餐饮服务食品安全操作规范》——全部公开文本 | 法规修订 → 内容运营跟踪（关键业务），模板标注"以属地监管要求为准" |
| 记录格式惯例 | 监管提供的登记册范本（如韶关市《落实食品安全主体责任登记册》） | 各地格式差异 → 通用两版 + 自定义项兜底 |
| 检查项知识 | 《操作规范》公开条款 + 行业通识 | 用一句话"法规依据"标注每项来源，可审计 |
| 官方平台对接 | 省级追溯平台（浙食链等）——**不对接**，错位互补 | 打印件可贴可存，与其流程并存 |

结论：产品侧供应链**零议价、零断供、零物流**——这是软件合规工具的结构性优势。

### 6.2 产品自身供应链（MVP 的技术依赖链，逐项消除单点故障）

与 pet-handoff 同一架构纪律：**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**

| 依赖 | 决策 | 单点故障消除 |
|---|---|---|
| 后端/数据库 | 无（localStorage 本地优先） | 无云账单、无停服、数据不出设备 |
| 第三方库 | 无（core.js 纯函数，日期/汇总/导出自实现） | 无供应链投毒面；`node --test` 零依赖可测 |
| 分发 | 任意静态服务器（`python3 -m http.server` 3 条命令） | 文档根即部署根，可迁移任意托管 |
| 打印/导出 | 系统级打印 + 单文件 HTML（内联样式） | 不依赖任何在线渲染服务，微信发送即达 |
| PWA 离线 | sw.js 缓存应用壳 | 后厨网络差也能打卡（真实使用场景） |

### 6.3 分发供应链（获客链路）

```
内容制作（抖音/视频号：检查场景短剧"台账被翻的那一天"）
      ↓ 免费工具承接（零摩擦，扫码即用）
直达用户（小店老板社群 / 餐饮老板群）
      ↓ 规模化放大
渠道分层：① 食安代账公司（白标 Pro，一个客户 5 分钟交付）
         ② 餐饮协会 / 市场监管培训场景（免费普及，合规教育即获客）
         ③ 收银 SaaS / 硬件商（作为增值模块捆绑）
```

每层渠道都已有真实存在的服务商（代账公司、协会培训、SaaS 渠道）——不需要发明新的中间商，只需给他们一个更好卖的商品。

---

**阶段三结论**：商业结构成立的关键在"近零成本 + 免费增值 + 渠道复用"；产品差异化在"把合规证据链做到扫码级易用"。所有付费与渠道假设进入阶段四的假设登记册逐一证伪。
