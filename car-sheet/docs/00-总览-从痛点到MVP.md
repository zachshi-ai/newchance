# 00 · 总览：从世界痛点到可运行 MVP

> 项目：**车况单 CarSheet** —— 小微二手车商的车况披露单与库存周转台账
> 仓库：`newchance` · 状态：MVP 已开发并通过端到端验证（`app/` 目录，27/27 单元测试 + 浏览器全流程）
> 一句话：**二手车商最大的尾部风险是"没证据说自己说过"：车况单把收车那一刻已知的车况变成书面披露单（微信发买家、打印签字），把每台车每天压着的资金变成看得见的数——未核查亮灯不装懂，毛利永远是现算的。**

## 1. 痛点（真实世界，有据可查）

二手车是典型的"柠檬市场"，而卖方的最大风险不在收车，在**说不清自己说过什么**：

- **如实告知是法定义务**：[《二手车流通管理办法》第十四条](14-调研来源.md#法规与政策红线口径的直接依据)要求卖方向买方提供车辆的使用、修理、事故、检验、抵押登记、税费、报废期等**真实情况和信息**；隐瞒与欺诈 → [《消费者权益保护法》第五十五条](14-调研来源.md#法规与政策红线口径的直接依据)**退一赔三**。
- **"不知道"不是抗辩**：司法实践通识口径——车商是专业经营者，负有主动查明车况的义务；2023 年以来调表车、事故车"退一赔三"判例持续出现（公开报道口径），一台 10 万元的车，尾部风险 40 万起。
- **库存即资金**：2024 年全国二手车交易 1961.42 万辆（[中国汽车流通协会](14-调研来源.md#市场量级数据)），每台在库车每天压着几万到几十万——在库天数是收售生意的第一性成本，而小微车商对"压了多久、压了多少"只有感觉没有数字。
- **现状解法 = 记忆 + 微信口头 + 手机备忘录**：收车信息不落档、整备成本散在转账记录里、披露靠口头承诺、卖完一车毛利全凭印象——出事时翻不出任何"我告知过"的书面证据。
- 第一性差距：**"收车时已知的车况"与"卖给买家时说过的车况"之间，没有任何小微级工具把它变成可留痕的证据链**——车况单把披露变建档、把口头变单据、把感觉变台账。

## 2. 方案（机会 → 产品）

**车况单**：零依赖、本地优先的 PWA。

1. **收车建档 + 九项披露**：车档即体检表——结构事故/水泡/火烧/维修更换/抵押查封/营运历史/召回/里程一致性/其他瑕疵，每项三态（✅ 正常 / ⚠️ 有异常 / ❓ 未核查），建档即全「未核查」：把"我不知道"从默认状态变成必须消灭的待办。
2. **未核查门诊**：看板自动点名未核查车辆；售出落账时亮灯提示但不阻止——风险先被看见，决策留给车商。
3. **整备落账 + 毛利现算**：整备/美容/轮胎/过户逐笔记账，总成本 = 收车价 + Σ整备；毛利、周转天数、资金占用永远由流水现算——改一笔账，结算自动跟着变。
4. **车况披露单三通道**（核心"信任交付"动作）：纯文本复制微信发买家（主通道）、打印版单文件 HTML（含**买方签字确认栏**）、直接打印——"我书面告知过、买家签了字"是判例里最硬的自证证据。
5. **库存黄线红线 + 资金占用排行**：45/75 天（参数可覆盖）自动分级点名；资金占用 = 总成本 × 在库天数，压钱最多的车排在第一行。
6. **月度经营账 + 数据自持**：收车/售出/毛利/平均周转/整备投入按月汇总；100% 本地存储，JSON 导出/导入。

## 3. 诚实的现状声明（真实可落地，不空中楼阁）

- **已验证**（本仓库内可复现）：核心逻辑 27/27 单元测试通过（含成本守恒、售出门禁、撤销回滚、老化分级边界、毛利恒等式、月报跨年隔离、导出确定性、XSS 转义、导入导出往返）；浏览器端到端全流程（示例数据 → 看板三类预警 → 披露单生成与切换 → 台账毛利核对 → 售出落账 → 披露登记保存）真实运行通过；打印版 HTML 为单文件、离线可用；零 npm/CDN/API 依赖；SW 缓存版本化。
- **未验证**（需真实用户，见 docs/13 假设登记册）：建档留存（H1）、披露单真实发送（H2）、售出落账使用（H3）、付费意愿（H4）、市场管理方渠道（H5）——全部标注"待验证"并配有可证伪判据。
- **边界与免责**：不做车辆估价、不做出险/维保查询（查询平台是互补的原料管道）、不做收付款、不做过户代办；披露单是卖方告知记录不是车辆检测报告，「未核查」不等于没有问题；本地记录不宣称司法级存证；**买卖合同与实车现状永远赢**。

## 5. 与既有项目的领域隔离（用户约束）

本方向为**二手车经销 · 小微车商车况披露与收售台账（B2B prosumer · 1~30 台在库小微车商 · 商务/消费者保护线）**，已对照仓库根 README 领域登记表做领域排除：不与 pet-handoff（C 端宠物照护）、food-sentry（餐饮食安合规台账）、turn-sheet（民宿短租周转与布草供应链）、work-proof（小微雇主劳动用工合规）、class-off（教培预收费课时账）重叠；与同期在建方向亦不同域——农资经营购销台账（农业投入品）、汽修厂危废台账（机动车维修业废物流）分别属农资经营与汽车维修业，本方向属**商贸流通业的二手车经销**（收售交易与消费者告知，不是维修也不是废物流）。与 `newidea` 仓库点子亦无重叠：`odometer-illusion` 是 C 端车主的保养双钟账本（消费者视角的里程/日历），本方向是 B 端车商的披露底账（经营者视角的告知证据链与库存资金），主体、问题、行业语境均不同。付费主体（车商与二手车市场管理方/车务代办商）、使用场景（收车建档与交车披露）、行业语境（如实告知义务与退一赔三判例）均独立成域。
