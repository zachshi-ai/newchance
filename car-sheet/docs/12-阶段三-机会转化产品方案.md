# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会怎么变成一个可卖的产品？用商业画布与价值主张画布定结构，用蓝海四动作定差异化，用 Kano 裁 MVP，最后把供应链想透——本项目供应链分析的重头戏是**车源整备链**（收车到交车的暗账）与**分发链**（二手车市场管理方即渠道）。

---

## 1. 商业画布（Business Model Canvas）

| 模块 | 内容 |
|---|---|
| **客户细分** | 1~30 台在库的小微二手车商（市场驻户 / 临街车行 / 赶集式车贩 / 网约退役车商）；渠道客户：**二手车交易市场管理方**（联营贴牌，见 §6.3）与**车务代办/过户服务商**（联营贴牌） |
| **价值主张** | 对车商主：已知车况书面留痕、买家问车况 10 秒回复披露单、未核查亮灯不装懂、整备毛利现算、库存压钱自动点名；对买家：明白看车，每一项告知有据可签；对市场管理方：场内商户规范经营的背书工具 |
| **渠道** | 直达：抖音/快手"退一赔三第一现场"场景内容 + 二手车商微信群；渠道：**市场管理方联营**（上游场景主即分销商）、车务代办联营、车商 KOL 社群分佣 |
| **客户关系** | 免费自助 + 内容号陪跑（如实告知义务/判例解读/披露话术内容）；市场渠道由管理方代维护商户关系 |
| **收入来源** | 免费版（5 台车档内全功能）；Pro 待验证（H4 假门 ¥99/年）：车档无限 + 经营月报 + 自定义披露单抬头；市场管理方联营年费 ¥3000/市场（白标 ≤100 商户）待验证（H5） |
| **核心资源** | 披露模板与话术库（判例跟踪 + 告知清单）、"车况单 = 披露底账"品类心智、市场管理方渠道关系 |
| **关键业务** | 模板内容运营（法规判例跟踪）、渠道拓展（市场管理方/车务代办）、留存运营（未核查门诊与库存预警） |
| **重要伙伴** | 二手车交易市场管理方（渠道 + 场景源：商户聚集的真实入口）、出险/维保查询平台（互补原料管道）、车商 KOL 社群 |
| **成本结构** | 近零边际成本：无服务器账单、无 npm 审计、单人维护；获客内容制作为主要成本 |

## 2. 价值主张画布（Value Proposition Canvas）

**客户侧（小微车商）**

| 客户任务 | 痛点 | 期望收益 |
|---|---|---|
| 收车时记住车况 | 记忆 + 备忘录回头就忘，"不知道"成为败诉理由 | 九项披露建档即体检，未核查自动变待办清单 |
| 回答买家"有没有事故" | 口头承诺无凭据，说多了怕不成交 | 披露单复制 10 秒发送，未核查也如实标注 |
| 交车环节自证 | 出了纠纷翻不出"我说过"的证据 | 打印版带买方签字栏，交车各留一份 |
| 整备成本记账 | 转账记录散、毛利全凭印象 | 整备逐笔落账，总成本与毛利永远现算 |
| 清库决策 | 说不清哪台车压了多久压了多少 | 黄线红线分级 + 资金占用排行，压钱最多的排第一行 |
| 月底盘点 | "感觉赚了"和"账上赚了"对不上 | 月度经营账：收/售/毛利/周转/整备自动汇总 |

**产品侧**

| 功能 | 减痛 / 创益 |
|---|---|
| 九项披露三态登记（建档即全「未核查」） | 减痛：把"我不知道"变成必须消灭的待办 |
| 未核查门诊（看板点名 + 售出前亮灯） | 减痛：风险在爆发前被看见，亮灯不阻止 |
| 披露单三通道（微信文本为主） | 创益：买家零安装，信任可交付 |
| 整备落账 + 毛利现算（流水推导不落库） | 创益：改一笔账结算自动跟变，账实一致 |
| 库存黄线红线 + 资金占用排行 | 创益：清库决策有据，资金压力可视化 |
| 月度经营账 | 创益：月底盘点有底账 |

**契合检验**：六个客户任务 ↔ 六项功能一一对应，无"我们做了但没人要"的悬空功能。

## 3. 蓝海战略四动作框架（ERRC）

| 动作 | 内容 | 效果 |
|---|---|---|
| **剔除 Eliminate** | 车辆估价、出险/维保数据查询、在线收付款、过户代办、获客营销、多角色权限与实施培训 | 与查询平台/DMS 正面会战的战场全部放弃；支付与数据源合规负担一并剔除 |
| **减少 Reduce** | 建档字段（车档 9 项）、披露登记（九项三态勾选 + 备注）、报告格式（披露单一模板） | 把"系统"从文书工作降为微信级别动作 |
| **增加 Increase** | 未核查门诊、整备流水与毛利联动、库存黄线红线、资金占用排行、月度经营账、披露单买方签字栏 | 把"记车况"升级为"有档、有预警、有凭据、有账"的证据链闭环 |
| **创造 Create** | **"已知车况与对外披露之间的确定性"**——车商从未体验过的自证资产；买家侧第一次收到逐项告知并签字确认的单据 | 非消费者（夫妻店、赶集车贩、DMS 里的库管）转化为用户 |

## 4. USP（独特销售主张）

> **唯一为小微二手车商设计的车况披露底账：收车建档九项披露，未核查亮灯不装懂；整备落账毛利现算，库存压钱自动点名；披露单微信发买家，打印签字留证据。不做估价、不做查询、不做收付款，买家不用装 App，免费开始。**

- 对比记忆口头：有档、有预警、有凭据，"你放心"变成"你看单"；
- 对比查询平台：它卖别人的记录（按次），车况单管你自己的留痕（免费）——互补不竞争；
- 对比车行 DMS：不要钱（5 台内）、不要学、不要实施，专管 DMS 不管的那一段（告知证据与资金压力）。
- 三句话之外的克制：**不说"保证不被告"，不说披露单等同检测报告**——证据效力边界见诚实条款（docs/13 §6）。

## 5. Kano 模型 → MVP 范围裁剪

| 类型 | 功能 | MVP 取舍 |
|---|---|---|
| 基本型（没有就骂） | 收车建档、九项披露登记、披露单导出（文本/HTML/打印）、整备与售出落账 | ✅ 已做（27/27 测试覆盖核心逻辑） |
| 期望型（越多越好） | 未核查门诊、毛利由流水现算、售出撤销回滚、重复售出拒绝 | ✅ 已做 |
| 兴奋型（超出预期） | 库存黄线红线、资金占用排行、月度经营账、售出门诊话术 | ✅ 已做（数据齐了自动出现）；自定义抬头/报表进 Pro/迭代池（H4 验证后再投入） |
| 无差异（别做） | 估价、询价池、金融分期对接、获客通、车辆网查询 | ❌ 永不做（偏离披露底账主线） |

## 6. 供应链分析（重点：车源整备链 + 技术链 + 分发链）

### 6.1 车商侧供应链（收车到交车——车况单把最重的两段暗账数字化）

车商交付"一台过完户的放心车"，其上游是**车源链**（置换/个人/同业/拍卖），中游是**整备链**（维修/美容/轮胎电瓶），下游是**交车链**（合同/过户/售后）。暗账集中在整备与认知两段：

| 环节 | 链路 | 暗账（没人记的部分） | 车况单的动作映射 |
|---|---|---|---|
| 收车 | 置换/个人/同业/拍卖进车 | 收车时已知什么全在脑子里，三天就忘 | 建档 30 秒：九项披露三态落档，来源与收车价入账 |
| 查证 | 出险/维保/抵押记录查询（第三方平台） | 查过的结论没有留痕，"查了"等于"没查" | 查完一项销一项：未核查 → 正常/有异常（备注写结论） |
| 整备 | 维修/美容/轮胎电瓶整备 | 花了多少钱散在转账里，且整备事实**本身就是披露项** | `addCost` 逐笔落账：既进总成本（毛利现算），又进披露单"整备记录"（一份动作两份价值） |
| 展示成交 | 买家看车/砍价/签合同 | 口头承诺无凭据，"你放心"积累尾部风险 | 披露单三通道：微信文本主通道 + 打印版买方签字栏 |
| 售出 | 收款/过户/交车 | 卖完毛利全凭印象，周转快慢没数 | `sellCar` 落账：毛利、周转天数、资金占用一次结清，账实一致可回滚 |
| 持有 | 在库期间的行情与资金 | 压了多久只有感觉 | 黄线红线自动点名 + 资金占用排行（总成本 × 在库天数） |

**与查询平台的供应链关系**：出险/维保查询平台按次卖记录，是车商查证环节的**原料供应商**——车况单不做查询（ERRC 剔除），只承接查询结论的留痕与交付。原料在别人的管道里，资产在自己的车档里。

### 6.2 产品自身供应链（MVP 的技术依赖链，逐项消除单点故障）

与 pet-handoff / food-sentry / turn-sheet / work-proof / class-off 同一架构纪律：**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**

| 依赖 | 决策 | 单点故障消除 |
|---|---|---|
| 后端/数据库 | 无（localStorage 本地优先） | 无云账单、无停服；收车价/毛利/买家信息不出设备；市场里网络差照常用 |
| 第三方库 | 无（core.js 纯函数，日期/成本/结算/导出自实现） | 无供应链投毒面；`node --test` 零依赖可测 |
| 分发 | 任意静态服务器（`python3 -m http.server` 3 条命令） | 文档根即部署根，可迁移任意托管 |
| 披露/导出 | 微信文本 + 单文件 HTML（内联样式）+ 系统打印 | 不依赖任何在线渲染/消息服务，买家零安装 |
| PWA 离线 | sw.js 缓存应用壳（版本化 + `cache:'reload'` 更新） | 断网可用；升级可靠到达 |

### 6.3 分发供应链（获客链路——上游场景主即分销商的结构性优势）

```
内容制作（抖音/快手："退一赔三第一现场：法院只认你写下来的" 场景内容 + 披露单模板引流）
      ↓ 免费工具承接（零摩擦，扫码即用）
直达用户（二手车商微信群 / 抖音二手车圈子 / 车商 KOL 社群）
      ↓ 规模化放大（本项目独有的渠道结构）
渠道分层：① 二手车交易市场管理方联营（B2B2C）：全国 600+ 实体市场，驻场车商几十~几千家
         → 管理方动机：场内投诉与声誉连带（一台调表车砸的是整个市场的招牌）+ 招商服务卖点；
           白标披露单落款 = 管理方对买家的市场级背书
         → 车况单动机：一个区域市场背后是 100~2000 家活跃车商，获客成本 ≈ 0
         ② 车务代办/过户服务商联营：代办天然服务 50~300 家车商，代账式代维护
         ③ 车商 KOL 社群团长分佣：车商社群是小微车主的聚集地，按成交 20% 分佣
```

每层渠道都已有真实存在的服务商（市场管理方、车务代办）——不需要发明新的中间商，只需给他们一个更好送的商品。**二手车市场管理方是全链路里"上游场景主反过来是分销商"的角色——供应链即渠道，与翻房单的洗涤厂联营、消课单的教具商联营同构但领域不同。**

---

**阶段三结论**：商业结构成立的关键在"近零成本 + 免费增值 + 市场管理方渠道复用"；产品差异化在"把已知车况与对外披露之间的证据黑箱变成白箱，并顺手记了库存资金与毛利的底账"。所有付费与渠道假设进入阶段四的假设登记册逐一证伪。
