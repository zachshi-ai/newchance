# 车况单 CarSheet 🚗

> **小微二手车商的车况披露单与库存周转台账：收车建档九项披露，未核查亮灯不装懂；整备落账毛利现算，库存压钱自动点名；披露单微信发买家，打印签字留证据。**
> 零依赖 · 本地优先 · 免注册 · 可离线 · 买家不用装 App

《二手车流通管理办法》第十四条要求卖方如实告知车辆的使用、修理、事故、检验、抵押等情况；隐瞒与欺诈叠加消法五十五条就是**退一赔三**——一台 10 万的车，尾部风险 40 万起，而司法实践通识口径下"我不知道"对专业经营者不成立。小微车商的现状是记忆 + 微信口头 + 手机备忘录：收车信息不落档、整备成本散在转账记录、披露靠口头承诺——出事时翻不出任何"我告知过"的书面证据。车况单把这段黑箱变成白箱：收车建档 30 秒（九项车况默认「未核查」，把"我不知道"变成必须消灭的待办）→ 整备逐笔落账（毛利永远由流水现算）→ 一键生成车况披露单（微信文本 / 打印版买方签字栏）→ 库存黄线红线自动点名（资金占用 = 总成本 × 在库天数，压钱最多的车排第一行）。

## 3 条命令跑起来

```bash
cd car-sheet
npm start           # 等价于 python3 -m http.server 8087 --directory app
open http://localhost:8087
```

没有 npm 也可以：任意静态服务器指向 `app/` 目录即可（它就是这个产品的全部）。
首次进入点「**先看示例数据**」，30 秒体验完整流程。

## 功能

| 模块 | 说明 |
|---|---|
| 🚙 **收车建档 + 九项披露体检** | 结构事故/水泡/火烧/维修更换/抵押查封/营运历史/召回/里程一致性/其他瑕疵，每项三态（✅ 正常 / ⚠️ 有异常 / ❓ 未核查）；建档即全「未核查」——未核查是一种如实，装懂才是风险 |
| 🩺 **未核查门诊（亮灯不阻止）** | 看板自动点名未核查车辆；售出落账时门诊提示"经营者有主动查明义务，先核查或在披露单中如实标注"——风险先被看见，决策留给车商 |
| 🧾 **车况披露单三通道** | 任意车辆一键生成：**纯文本复制**（微信粘贴给买家，主通道）/ 打印版**单文件 HTML**（内联样式、含**买方签字确认栏**）/ 直接打印。「未核查」栏明示"不等于没有问题" |
| 🔧 **整备落账 + 毛利现算** | 维修/美容/轮胎/过户逐笔记账，总成本 = 收车价 + Σ整备；毛利、周转天数、资金占用永远由流水现算——改一笔账，结算自动跟着变；已售车成本账已结（防历史毛利被悄悄改写） |
| 🔴 **库存黄线红线 + 资金占用排行** | 45/75 天（参数可覆盖）自动分级点名；资金占用 = 总成本 × 在库天数（万元·天量纲），压钱最多的车排第一行——清库决策有据 |
| 📒 **月度经营账 + 数据自持** | 收车/售出/毛利/平均周转/整备投入按月汇总，跨月跨年隔离；100% 本地存储；JSON 导出/导入（换机迁移，含结构校验）；本地事件流可导出（验证用埋点） |

## 为什么没有后端 / 没有依赖

这不是偷懒，是设计（详见 [docs/12 供应链分析](docs/12-阶段三-机会转化产品方案.md)）：
**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**
市场里网络差，PWA 离线可用；发披露单走微信文本，不依赖任何在线服务；收车价、毛利、买家信息不出设备。**不做估价、不做查询、不碰支付、不碰过户**——出险/维保查询平台是互补的原料管道，这里是车商自己的披露底账。

## 边界与免责

- **不做车辆估价、不做数据查询、不做在线收付款、不做过户代办**——车档与整备手工录入（这是特性不是缺陷：无数据源合规负担、无资金合规负担、离线可用）。
- **披露单是卖方告知记录，不是车辆检测报告**：「未核查」明示"卖方未掌握该方面信息，不等于没有问题"；本工具不宣称司法级存证，**买卖合同与实车现状永远赢**。
- 退一赔三的适用以法院认定为准，门诊提示只把通识风险标价，不构成法律意见；如实告知义务依据《二手车流通管理办法》第十四条整理，**属地规则与最新法规永远赢**。
- 黄线 45 天/红线 75 天是行业通识先验的参数化，设置页可覆盖。
