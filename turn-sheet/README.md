# 翻房单 TurnSheet 🧺

> **小微民宿的退房周转执行台：窗口自动变任务单，微信发保洁即派工；布草几套在房几套在洗，永不断供。**
> 零依赖 · 本地优先 · 免注册 · 可离线 · 保洁不用装 App

民宿的收入住在好评里，好评住在卫生里，而卫生住在「退房 → 入住」那两三个小时的执行里。小微房东（1~10 间房）的现状是：微信喊保洁、口头交代、布草几套在洗全凭记忆——接了重叠订单、翻不完房、客人到点进不了门、卫生差评下来才知道。翻房单把这段黑箱变成白箱：房期一录，翻房窗口自动算出红黄绿；一张任务单复制给保洁即完成派工；布草按套记账，缺套提前预警、洗涤厂超时可索赔、报废重购有预算。

## 3 条命令跑起来

```bash
cd turn-sheet
npm start           # 等价于 python3 -m http.server 8083 --directory app
open http://localhost:8083
```

没有 npm 也可以：任意静态服务器指向 `app/` 目录即可（它就是这个产品的全部）。
首次进入点「**先看示例数据**」，30 秒体验完整流程。

## 功能

| 模块 | 说明 |
|---|---|
| 📋 **翻房窗口自动派生** | 每单退房自动衔接下一单入住：窗口 < 标准保洁时间亮红灯、贴 1.5 倍线亮黄灯、订单重叠直接点名——「接重叠了」在客人到门之前就被看见 |
| ✅ **翻房打卡留档** | 查遗留 → 撤脏布 → 清洁 → 铺新布 → 补耗品 → 拍照回传，六步勾选；遗留物品记录（品名/联系客人/处理）单独留档——卫生差评申诉与免责的第一证据 |
| 🧾 **翻房任务单三通道** | 任意翻房日一键生成任务单：**纯文本复制**（微信粘贴给保洁，主通道）/ 打印版**单文件 HTML**（内联样式、含签字栏与查遗留填写行）/ 直接打印。保洁不用装任何东西 |
| 🧺 **布草周转账** | 每套布草「在房 → 脏 → 在途 → 净」四态过账，总量守恒有测试钉死；每次洗涤成本 = 购价 ÷ 额定洗涤次数（行业先验 130~150 次，本地可改） |
| ⏰ **洗涤厂 SLA 预警** | 送洗超 SLA（默认 3 天）自动点名：催厂、主张赔付——布草在途无人跟踪是缺套的第一原因 |
| 📉 **缺套与报废预算** | 未来 3 天到客房源的净布缺口提前亮灯；按你的真实洗涤节奏推算 90 天内将耗尽寿命的套数与重购预算（样本不足时诚实拒判，不编造节奏） |
| 📦 **耗品低库存** | 卷纸/瓶装水/洗漱包安全线管理，低于线进首页待办 |
| ⚙️ **数据自持** | 100% 本地存储；JSON 导出/导入（换机迁移，含结构校验）；本地事件流可导出（验证用埋点） |

## 为什么没有后端 / 没有依赖

这不是偷懒，是设计（详见 [docs/12 供应链分析](docs/12-阶段三-机会转化产品方案.md)）：
**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**
乡村民宿与景区民宿网络差，PWA 离线可用；给保洁派工走微信文本，不依赖任何在线服务。数据不出设备。

## 边界与免责

- **不做 OTA 直连、不做 PMS、不做动态定价**——房期手工录入（这是特性不是缺陷：无平台授权依赖、无封禁风险、离线可用）。房期以 OTA 后台为准，本工具只管「退房之后、入住之前」。
- 布草「一客一换」等卫生要求依据 GB 9663-1996 与 GB/T 41648-2022 等公开标准整理；本工具记录执行事实，**不替代卫生许可证、法定检查与属地监管要求**。
- 额定洗涤次数、SLA 天数为行业通识先验的默认参数，供应商与洗涤厂给你的数字永远赢——直接在「设置」里改。
- 完成拍照与遗留记录是自查留档，其证据效力以平台申诉规则与法律规定为准，工具不夸大。
