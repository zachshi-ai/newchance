# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会怎么变成一个可卖的产品？用商业画布与价值主张画布定结构，用蓝海四动作定差异化，用 Kano 裁 MVP，最后把供应链想透——本项目供应链分析是重头戏：**布草供应链本身就是产品要管的对象**。

---

## 1. 商业画布（Business Model Canvas）

| 模块 | 内容 |
|---|---|
| **客户细分** | 小微民宿/短租房东（1~10 间：城市公寓房东、乡村院落主理人、兼职房东）；渠道客户：**布草洗涤厂**（联营贴牌，见 §6.3）与民宿管家/代运营团队 |
| **价值主张** | 对房东：窗口自动算、任务单 30 秒派工、布草永不断供、差评申诉有证据；对洗涤厂：下游客户的送洗数据数字化，锁客 + 减少丢货扯皮；对管家团队：多房源任务单标准化交付 |
| **渠道** | 直达：小红书/抖音"民宿翻房"内容 + 房东微信群；渠道：**洗涤厂联营**（上游供应商即分销商）、管家团队分发、民宿主社群 |
| **客户关系** | 免费自助 + 内容号陪跑（卫生标准/翻房 SOP 内容）；洗涤厂渠道由厂方代维护客户关系 |
| **收入来源** | 免费版（单房源全功能）；Pro 待验证（H4 假门 ¥99/年）：多房源、洗涤台账报表、打印招牌页；洗涤厂联营年费 ¥1200/厂（白标 50 客户内）待验证（H5） |
| **核心资源** | 翻房/布草内容模板库（按业态持续运营）、"翻房单=周转执行"品类心智、洗涤厂渠道关系 |
| **关键业务** | 模板内容运营（卫生标准跟踪）、渠道拓展（洗涤厂）、留存运营（窗口提醒/SLA 预警） |
| **重要伙伴** | 布草洗涤厂（渠道 + 内容源：额定洗涤次数的真实口径）、静态托管平台、民宿社群 |
| **成本结构** | 近零边际成本：无服务器账单、无 npm 审计、单人维护；获客内容制作为主要成本 |

## 2. 价值主张画布（Value Proposition Canvas）

**客户侧（小微房东）**

| 客户任务 | 痛点 | 期望收益 |
|---|---|---|
| 退房后准时翻房 | 窗口算不清、保洁不知道几点前要完 | 窗口红黄绿一眼可见，任务单自带截止时间 |
| 给保洁交待清楚 | 口头交代三小时蒸发，质量靠运气 | 六步标准清单 + 门锁信息随单送达 |
| 布草不断供 | 缺套总在到客日发现；在途没人跟踪 | 提前 3 天缺口预警 + SLA 超时催厂 |
| 差评申诉/纠纷自证 | 没有任何执行留档 | 完成打卡 + 拍照回传 + 遗留物品记录 |
| 控制布草成本 | 发灰才换、突然支出一大笔 | 每次洗涤成本、90 天重购预算 |

**产品侧**

| 功能 | 减痛 / 创益 |
|---|---|
| 窗口派生（红黄绿/重叠点名） | 减痛：接重叠与翻不完在客人到门前被看见 |
| 翻房任务单三通道（微信文本为主） | 创益：保洁零安装，30 秒派工 |
| 布草四态过账 + 总量守恒 | 减痛：几套在房几套在洗第一次有账 |
| SLA 超时预警 | 创益：催厂有凭据，丢货可主张赔付 |
| 缺口预警 + 报废预算 | 创益：从"突然支出"到"按寿命计划重购" |
| 遗留物品记录 | 创益：寄回失物 → 好评，差评申诉有据 |

**契合检验**：五个客户任务 ↔ 六项功能一一对应，无"我们做了但没人要"的悬空功能。

## 3. 蓝海战略四动作框架（ERRC）

| 动作 | 内容 | 效果 |
|---|---|---|
| **剔除 Eliminate** | OTA 直连与抓取、支付/收单、动态定价、多角色权限体系、实施与培训 | 与 PMS 正面会战的战场全部放弃；封禁风险与维护成本一并剔除 |
| **减少 Reduce** | 建档字段（房源 4 项、房期 4 项）、布草录入粒度（批量勾选过账，不逐套拍照）、报告格式（任务单一种模板） | 把"系统"从文书工作降为微信级别动作 |
| **增加 Increase** | 窗口红黄绿与重叠点名、布草四态账 + SLA 催厂 + 报废预算、遗留物品记录、完成拍照留档 | 把"喊保洁"升级为"有截止、有清单、有账、有证据"的执行闭环 |
| **创造 Create** | **"两次入住之间的确定性"**——房东从未体验过的周转从容；布草供应链的第一本账（在房/脏/在途/净 + 寿命） | 非消费者（纯微信房东、家里人打扫的）转化为用户 |

## 4. USP（独特销售主张）

> **唯一为小微房东设计的翻房执行工具：退房到入住的窗口自动变任务单，微信发保洁即派工；布草几套在房几套在洗，缺套提前预警。不做 OTA 直连、不做 PMS、保洁不用装 App，免费开始。**

- 对比微信喊：有清单、有截止、有留痕，"忘了"有处可查；
- 对比 PMS：不要钱（单房源）、不要学、不要直连授权，专管 PMS 不管的那一段；
- 对比海外工具：微信生态原生，中文、离线、免费。
- 三句话之外的克制：**不说"保证好评"，不说"替代卫生许可"**——证据效力边界见诚实条款（docs/13 §5）。

## 5. Kano 模型 → MVP 范围裁剪

| 类型 | 功能 | MVP 取舍 |
|---|---|---|
| 基本型（没有就骂） | 房源/房期建档、翻房窗口计算、任务单导出（文本/HTML/打印） | ✅ 已做（34/34 测试覆盖核心逻辑） |
| 期望型（越多越好） | 布草四态账、SLA 超时预警、缺口预警、耗品低库存、遗留记录、订单重叠检测 | ✅ 已做 |
| 兴奋型（超出预期） | 90 天报废重购预算、每次洗涤成本、额定次数本地覆盖、洗涤厂对账单 | ⬜ 前三项已做（数据齐了自动出现）；对账单进 Pro/迭代池（H5 验证后再投入） |
| 无差异（别做） | 社区/评价营销、房东交流社区、积分商城、动态定价 | ❌ 永不做（偏离执行闭环主线） |

## 6. 供应链分析（重点：三条链，第一条链就是产品本体）

### 6.1 产品侧供应链（民宿为客人整合的"上游"——翻房单直接把它数字化）

用户（房东）的最终产品是"一晚干净、有好评的住宿"，其上游最重的一环就是**布草供应链**。三种模式、三本账，翻房单全部覆盖：

| 模式 | 链路 | 暗账（没人记的部分） | 翻房单的动作映射 |
|---|---|---|---|
| **自洗** | 撤布 → 家用洗衣机 → 晾晒 → 回柜 | 无法举证消毒（卫生检查与纠纷的软肋）；洗涤寿命无账，发灰才发现；水电成本隐性 | `strip → selfwash`（脏→净，washes+1）；寿命账照记 |
| **外洗（洗涤厂/水洗厂）** | 撤布 → 脏布袋 → 厂方取件 → 厂内分拣洗涤 → 送回 → 净布柜 | **在途无跟踪**：哪天送的不记得、超期没人催、丢货扯皮没凭据；黑作坊混洗曝光伤及房东 | `send`（记 sentAt）→ SLA 时钟 → `transitOverdue` 超时点名"催厂/主张赔付" |
| **租赁（按套月租）** | 厂方铺货 → 每客一换 → 厂方回收洗涤循环 | 套数漂移：合同 10 套实际在手几套没人知道，丢赔全凭厂方说了算 | 同外洗流程；总量守恒恒等式（在房+脏+在途+净+报废=总套数）就是租赁对账的底账 |

**布草寿命与重购经济（行业先验 + 本地数据）**：全棉布草额定洗涤寿命常见 130~150 次（通识先验，设置页可改，洗涤厂口径永远赢）。翻房单把每次回洗计入套账：
- **每次洗涤成本** = 购价 ÷ 额定次数（¥129 四件套 ÷ 130 次 ≈ ¥0.99/客晚——布草不是固定资产，是按次的消耗品）；
- **报废预算** = 按你的真实洗涤节奏（近 90 天回洗套次的月均）推 90 天内将耗尽寿命的套数 × 重购单价——样本不足时诚实拒判，不编造节奏。
- **重购时点**从"发灰了突然买"变成"按月计划补"，现金流可预期。

**耗品供应链**：卷纸/瓶装水/洗漱包/拖鞋，1688 集采或本地批发——翻房单不碰采购（ERRC 剔除），只管安全线库存与翻房时逐项核对，把"到客才发现没纸"挡在门外。

### 6.2 产品自身供应链（MVP 的技术依赖链，逐项消除单点故障）

与 pet-handoff / food-sentry 同一架构纪律：**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**

| 依赖 | 决策 | 单点故障消除 |
|---|---|---|
| 后端/数据库 | 无（localStorage 本地优先） | 无云账单、无停服、数据不出设备；乡村网络差照常用 |
| 第三方库 | 无（core.js 纯函数，日期/状态机/导出自实现） | 无供应链投毒面；`node --test` 零依赖可测 |
| 分发 | 任意静态服务器（`python3 -m http.server` 3 条命令） | 文档根即部署根，可迁移任意托管 |
| 派工/导出 | 微信文本 + 单文件 HTML（内联样式）+ 系统打印 | 不依赖任何在线渲染/消息服务，保洁零安装 |
| PWA 离线 | sw.js 缓存应用壳（版本化 + `cache:'reload'` 更新） | 断网可用；升级可靠到达 |

### 6.3 分发供应链（获客链路——上游供应商即分销商的结构性优势）

```
内容制作（小红书/抖音："民宿差评的第一杀手是翻房" 场景内容 + 翻房 SOP 模板引流）
      ↓ 免费工具承接（零摩擦，扫码即用）
直达用户（房东微信群 / 民宿主社群 / 管家团队）
      ↓ 规模化放大（本项目独有的渠道结构）
渠道分层：① 布草洗涤厂联营（B2B2C）：厂方把翻房单贴牌赠给下游 50 家客户
         → 厂方动机：送洗数据数字化锁客 + 减少丢货扯皮 + 排产可视化
         → 翻房单动机：一个洗涤厂背后是 10~200 家活跃送洗民宿，获客成本≈0
         ② 管家/代运营团队：一个管家管 10~30 间房，任务单是其标准化交付物
         ③ 民宿平台生态外的社群（房东群/主理人圈），内容即获客
```

每层渠道都已有真实存在的服务商（洗涤厂、管家公司、社群团主）——不需要发明新的中间商，只需给他们一个更好送的商品。**洗涤厂是全链路里唯一的"上游供应商反过来是分销商"角色——供应链即渠道，这是本项目区别于前两个项目的结构性杠杆。**

---

**阶段三结论**：商业结构成立的关键在"近零成本 + 免费增值 + 洗涤厂渠道复用"；产品差异化在"把两次入住之间的执行黑箱变成白箱，并顺手记了布草供应链的第一本账"。所有付费与渠道假设进入阶段四的假设登记册逐一证伪。
