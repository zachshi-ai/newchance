# 13 · 阶段四：产品落地验证闭环

> 本阶段回答：怎么证明这个产品会成（或不成）？用 HDD 把信念变成可证伪假设，用 OHELM 循环推进验证，用 90 天排期对齐民宿经营节奏，并确立第一桶金。

---

## 1. 假设登记册（HDD）

| # | 假设 | 判据（可证伪） | 验证方法 | 状态 |
|---|---|---|---|---|
| H1 | 房东会持续录入房期 | ≥40% 建档者第 14 天仍有新增房期或编辑动作 | 本地事件流（`track` 埋点，设置页可导出）+ 20 家种子微信群自愿回传 | ⬜ 待验证 |
| H2 | 翻房单会被真实发给保洁（核心动作） | ≥60% 有房期用户导出过任务单 ≥1 次/周；文本复制（微信）占比 ≥70% | 埋点：`runsheet` 事件按 action 分桶（copy/download/print） | ⬜ 待验证 |
| H3 | 布草账会被坚持记 | 活跃用户月均布草过账 ≥4 次（送洗/回库事件流） | 埋点：`linen-send` / `linen-recv` / `linen-selfwash` 事件密度 | ⬜ 待验证 |
| H4 | 付费意愿存在且锚点在百元内 | 假门按钮点击率 ≥5%；或 ≥10 家愿付 ¥99/年 | 假门 Pro（多房源/台账报表/打印招牌，点击后如实告知"功能规划中"）+ 直接报价访谈 | ⬜ 待验证 |
| H5 | 洗涤厂愿意联营分销 | ≥3 家洗涤厂试点贴牌、合计覆盖 ≥60 家民宿 | 本地水洗厂扫街拜访（一个厂辐射 10~200 家送洗民宿），白标包 ¥1200/年 | ⬜ 待验证 |
| H6 | 遗留物品记录真实发生 | ≥30% 完成的翻房卡填写过遗留/异常字段 | 埋点：`found-log` 事件 has=true 占比 | ⬜ 待验证 |
| H7 | 单房源用户占多数但多房源升级存在 | 单房源占比 ≥60%；≥10% 用户建 ≥3 间房 | 埋点：建档房源数分布（若多房源超预期，提前把 Pro 多房源转正） | ⬜ 待验证 |
| H8 | 用户会主动备份/迁移数据 | JSON 导出使用率 ≥10% | 埋点：`export-json` 事件 | ⬜ 待验证 |

**已证伪风险预案**：若 H2 < 30%（派单动作不成立——保洁协作摩擦 R2 成真），则转向"布草周转账"单点工具（弱化派单叙事，强化缺套预警/SLA 催厂/报废预算）——同一个 core，换一个入口叙事。若 H1 < 20%（房期录入都不成立），产品无钩子，止损关停，把布草账拆给洗涤厂做 SaaS 另起炉灶。

## 2. OHELM 验证循环

每条假设按 **Objective → Hypothesis → Experiment → Learn → Measure** 循环推进，学习结果写回假设登记册，不做完循环不进入下一轮投入：

| 环节 | 本项目的落地形式 |
|---|---|
| **O** Objective | 90 天内证明"房东愿意把周转执行从微信喊升级为发单 + 记账"（H1+H2+H3） |
| **H** Hypothesis | 上表 H1-H8，一条一个预期数值 |
| **E** Experiment | ①20 家种子房东（10 城市公寓 + 5 乡村 + 5 管家团队）微信群陪跑（本地优先工具的天然局限：埋点在端上，靠用户自愿导出 + 周回访）②假门付费 ③本地洗涤厂扫街 10 家、谈 3 家贴牌试点 |
| **L** Learn | 每两周一次循环复盘：判据达标 → 升级投入；不达标 → 触发对应预案（H2/H1 预案） |
| **M** Measure | 北极星：**周活跃翻房房源数（周内至少生成或勾选过 1 次翻房记录的房源数）**；护栏指标：任务单导出率（H2）、布草事件密度（H3）、14 天房期留存（H1） |

**北极星指标说明**：不选下载量（vanity）、不选注册数（无门槛），选"每周至少翻一次房的活跃房源数"——它同时代表留存、真实周转与打卡行为发生。

## 3. 第一桶金（确立）

三条腿并进，以 ② 洗涤厂联营为杠杆主攻：

| 路径 | 定价 | 第一笔钱的现实性 | 90 天目标 |
|---|---|---|---|
| ① 房东 Pro | ¥99/年（多房源 + 洗涤台账报表 + 打印招牌页）；单房源永久免费 | 假门点击 → 直接报价转化；锚点贴布草一套 ¥100~300 的心理账户 | H4 判据：≥10 家付费或假门点击 ≥5% |
| ② **洗涤厂联营（主攻）** | ¥1200/年/厂（白标 ≤50 客户，含厂方看板：客户送洗节奏/在途台账） | 一个县城水洗厂服务 10~200 家民宿，客单价是房东的 12 倍且决策人单一（厂老板）；对厂方的账：留客价值 + 丢货纠纷减少 ≫ ¥1200 | 扫街 10 家、签约 3 家 = **首笔现金 ¥3,600**，同时获得 60+ 精准房东分发面 |
| ③ 布草以旧换新导购 | 与布草厂/洗涤厂分佣 | 依赖报废预算数据（90 天重购清单）成熟后再开 | 不做承诺，进迭代池 |

**为什么 ② 是主攻**：房东 CNY 付费弱（R1），但洗涤厂 B2B 决策快、有明确 ROI、且天然批量触达房东——**供应链上游即渠道**（docs/12 §6.3）。第一桶金的本质不是规模，是"有人为价值付了第一笔真钱 + 一条可复制的收款路径"，3 家洗涤厂试点同时验证产品价值（H5）、渠道结构（分发面）与收款能力。

## 6. 诚实条款（本项目的科学底线）

- **不做 OTA 直连、不碰平台数据**：房期手工录入，正确性由房东对照 OTA 后台负责；工具只管"退房之后"，不宣称覆盖订房渠道管理。
- **本地记录不具备司法级不可篡改性**：完成打卡、拍照回传、遗留记录的证据价值在"完整、即时、规范"，可用于平台申诉与日常对账，但本工具不宣称替代法定检测报告或公证存证。
- **不替代卫生许可与法定检查**：一客一换等口径依据公开标准（GB 9663-1996、GB/T 41648-2022）整理，属地监管要求永远赢；工具记录执行事实，不构成卫生学或法律意见。
- **洗涤寿命与 SLA 是先验参数**：130~150 次、3 天均为行业通识默认值，可在设置中覆盖；在供应商给的口径与工具默认值冲突时，以供应商为准。
- **薄数据诚实拒判**：报废预算需要近 90 天 ≥4 套次回洗样本，不足时显示"样本不足"而不是编造节奏（测试钉死）。
- **所有商业假设未验证**：付费、留存、渠道数字全部是待证伪的信念。我们不把"40 万民宿商家"当作需求的必然性——微信喊保洁也免费，纸和记忆也是船。
