# 10 · 阶段一：识别机会与洞察市场

> 本阶段回答：世界的哪个痛点值得做？用第一性原理拆到底，用 JTBD / 船模型 / 非消费者分析还原真实场景，用 PESTEL 扫宏观，用机会缺口矩阵定位空白。

---

## 1. 第一性原理拆解

不问"市面上有什么民宿 SaaS"，只保留不可再分的事实：

| # | 不可再分的事实 | 推论 |
|---|---|---|
| F1 | 民宿收入 = 入住率 × 间夜价 × 好评带来的流量排名；中国民宿相关企业十年增长超 20 倍，现存约 38 万~40 万家（企查查口径，2024 底 32.3 万 → 2026-05 约 40.3 万） | 供给严重过剩：38 万商家抢流量，好评 = 流量 = 生存 |
| F2 | 卫生是住宿差评与投诉的高频来源；「一客一换」是硬性卫生要求（GB 9663-1996《旅店业卫生标准》：床单/枕套/被套一客一换、长住客一周一换），GB/T 41648-2022 把卫生与服务列入民宿国标 | 卫生不是加分项，是底线；底线失守 = 差评 + 罚款风险（实施细则：警告或罚款，情节严重可责令停业整顿） |
| F3 | 卫生住在「退房 → 入住」的窗口里：退房多在 12:00，入住多在 14:00~15:00——**翻房是唯一发生在两次收入之间的必要动作**，它的质量决定差评，它的准时决定当天间夜是否丢失 | 窗口是刚性约束，不是弹性事务；错过就是真金白银 |
| F4 | 小微房东（1~10 间）的翻房执行现状 = 微信喊保洁 + 口头交代 + 无台账：接重叠、翻不完、漏查遗留，全靠运气 | 执行黑箱：问题总在客人到门那一刻才暴露 |
| F5 | 布草（床品/巾类）三条路各有暗账：自洗无法举证消毒；送洗的洗涤厂 SLA 无跟踪、丢货扯皮、黑作坊混洗时有曝光；租赁按套计费、丢赔条款苛刻。**没有一本账记着"几套在房、几套脏、几套在洗、几套净"** | 缺套总在最需要的那天发现；布草供应链是民宿的隐形血管，没人给它装压力表 |
| F6 | 布草是消耗品：全棉布草额定洗涤寿命常见 130~150 次（行业通识先验），到了就发灰发破 | 布草不是坏了才换，是按洗涤次数换——但这笔账没人算，重购永远是"突然发现" |
| F7 | 房东与保洁的协作基线 = 微信发文字/语音；海外已有 Turno 等翻房调度公司验证"turnover 是独立痛点"，但其产品服务英语市场 | 中国小微房东被两边遗漏：PMS 太重、海外工具不可用、微信喊太乱 |
| F8 | OTA 对小微房东不开放 API；平台直连工具需要授权与维护，且有封禁风险 | 离线手工录入反而成为合规、可靠的交付形态 |

**第一性结论**：民宿生意的死循环不在"没有订单"（那是 OTA 的仗），在"接了订单兑现不了"——**两次入住之间的执行确定性**决定好评、间夜与卫生合规。而这个确定性 = 一张按时到达保洁手里的任务单 + 一本永远不会断供的布草账。谁把这两件事的成本打到趋近于零，谁就拿下这个被 40 万供给过剩养出来的需求。

## 2. 痛点 - 爽点 - 痒点模型（梁宁）

| 层 | 用户心理 | 翻房单对应 |
|---|---|---|
| **痛点**（恐惧/怕） | 怕接了重叠订单客人同时到门；怕保洁翻不完客人进不了房；怕卫生差评掉流量；怕布草缺套临时抓瞎；怕被卫生检查点名「未一客一换」 | 窗口红黄绿 + 订单重叠点名 + 布草缺口提前 3 天预警——恐惧在客人到门之前被看见 |
| **爽点**（即时确定性） | 退房列表一键变成任务单，复制、粘贴、发送——30 秒完成派工；布草柜剩几套一眼可见 | 任务单三通道（微信文本/打印/HTML）；布草四态看板 |
| **痒点**（虚拟自我） | "我家民宿像酒店一样有标准作业流程"；保洁交接不靠人情靠单子 | 六步标准任务 + 签字栏 + 完成拍照留档——个体房东的"标准化经营者"身份叙事 |

优先级：痛点 > 爽点 > 痒点。MVP 只做痛点与爽点，痒点靠标准任务单顺手满足，不做社区/排行/学院。

## 3. JTBD（待办任务）

**主任务陈述**：**当**有客人今天退房、下一批客人今天或明天入住时，**我要**确保房间在窗口内翻好、布草不断供、遗留物品有记录，**以便**不丢间夜、不掉评分、出了纠纷有证据。

三维拆解：

| 维度 | Job | 现状方案的失败点 |
|---|---|---|
| 功能性 | 派工（谁、哪间、几点前、做什么）；布草调度（撤/洗/回/铺）；耗品补给 | 微信口头派工无清单无截止；布草全凭记忆 |
| 情感性 | 客人到门那一刻心里不慌；不担心保洁"忘了" | 保洁在忙别的，口头交代三小时后蒸发 |
| 社会性 | 向客人（干净）、向平台（评分）、向检查（合规）证明"我是规范的经营者" | 没有任何体面的执行凭据 |

**竞品不是别的 App，而是「微信喊保洁 + 纸质日历本 + 什么都不记」**——它们免费、零学习成本，这是我们真正的敌人（见阶段二波特五力：替代品威胁）。

## 4. 船模型

> 用户要的从来不是船，是安全过河。这里河对岸 = 每一间房准时翻好、好评稳定、布草不断供。

| 元素 | 本场景 | 现状问题 |
|---|---|---|
| 乘客 | 1~10 间房的小微民宿房东 / 主理人（兼保洁调度员） | — |
| 船 A：微信 + 电话 + 口头 | 现状默认解，免费 | 无清单、无截止、无留痕；"忘了"无法归责；遗留物品没人记录 |
| 船 B：民宿 PMS（订单来了/云掌柜等） | 渠道直连、房态日历、对账 | 为"渠道效率"设计，翻房只是日历上的一个色块；不生成保洁任务单、不管布草供应链；年费 + 学习成本对 3 间房的房东过重 |
| 船 C：海外翻房工具（Turno/TurnoverBnB 等） | 保洁调度 + 认领 + 赔付，已验证需求 | 英语市场 + 海外平台生态，中国房东与保洁均不可用 |
| 船 D：洗涤厂自己的接单本 | 只管"收了多少件要洗" | 只覆盖供应链一环；不记在房/在库，不预警缺套，不服务房东的整体节奏 |
| 河 | **"退房 → 入住"之间的执行黑箱 + 布草供应链无账** | 四条船共同的黑水区 |

**定位推论**：翻房单**不造 PMS 的船**，做挂在所有船上的**"周转执行黑匣子 + 布草压力表"**——房期从哪来（OTA/直客/纸质）不重要，重要的是退房之后发生的事第一次有了清单、截止时间和账。与 PMS 互补（房期手抄 10 秒），与微信正面对抗但迁移成本≈0（还是微信，只是从"喊"变成"发单"），与洗涤厂天然同盟（它的送洗数据第一次有了下游对账方）。

## 5. 非消费者分析（Christensen）

| 非消费者类型 | 画像 | 为什么不用现有解 | 对产品的启示 |
|---|---|---|---|
| 纯微信房东 | 1~3 间房，兼职经营 | PMS 太重太贵；日历本记不住窗口 | 免费开始；单房源全功能；录入一单 20 秒 |
| 家里人打扫的 | 亲属/自己顺手做保洁 | "给家里人派什么工"——但没有标准就没有稳定质量 | 任务单让"家里的标准"显性化；六步清单统一质量 |
| 乡村民宿主理人 | 景区/县域，网络差，请零工保洁 | PWS/云工具断网即瘫；零工换人频繁无人带教 | PWA 离线可用；任务单打印贴布草柜，换人即换标准 |
| 自洗布草的 | 家用洗衣机洗床品 | 不知道洗涤有寿命账，布草发灰才换 | 「自洗回库」动作 + 洗涤次数账本，第一次看见布草成本 |

非消费者共同阻碍排序：**不知道要管什么（知识门槛：窗口/布草/遗留三类盲区）> 觉得"就几间房不用系统"（规模错觉）> 怕保洁嫌麻烦（协作摩擦）**。MVP 依次对应：翻房窗口自动派生、单房源免费全功能、保洁不装 App 微信收文本。

## 6. PESTEL 宏观扫描

| 维度 | 要点 | 对本机会 |
|---|---|---|
| **P** 政治 | GB/T 41648-2022《旅游民宿基本要求与等级划分》2023-02 实施，卫生与服务制度化；《公共场所卫生管理条例》体系对住宿业公用品具有「一客一换」与清洗消毒保洁义务，违者警告/罚款乃至停业整顿；民宿等级评定（丙/乙/甲）把日常管理纳入评分 | 合规要求从"隐性常识"变"显性国标"，顺风；工具顺手成为"等级评定备查"材料 |
| **E** 经济 | 民宿市场规模约 422.7 亿元（2026 年报道口径）；38 万+ 商家供给过剩内卷，价格战打不动只能打评分；保洁人力成本上行 | 对费用极度敏感 → 免费增值是唯一可行定价；但"差评损失一间夜"的账算得过来，付费逻辑是省钱不是合规罚款 |
| **S** 社会 | 反向旅游/县域旅游兴起，乡村民宿供给加速；卫生舆情（布草黑作坊曝光）让客人对"看不见的干净"极度敏感；房东数字化基线 = 微信 + OTA App | 乡村供给 = 离线需求的真实来源；卫生敏感 = 留档证据的价值上涨 |
| **T** 技术 | OTA 封闭生态、对小微不开放 API；PWA/打印为系统级能力；微信是保洁协作的绝对通道 | 本地优先 + 微信文本双通道恰好规避平台依赖；无 API 不是缺陷是护城河 |
| **E** 环境 | 布草洗涤是高水耗环节；集中洗涤的大水洗厂比分散自洗更节水节能，各地对洗涤废水监管趋严 | 「转外洗」是政策顺风——而送洗越多，布草周转账的价值越大 |
| **L** 法律 | 卫生违法有明确罚则区间（警告或 1 千~1 万、情节严重 1 万~3 万，以属地现行文本为准）；卫生差评引发的平台处罚与客人索赔（皮肤过敏等）需要执行留档自证 | 记录同时是**免责/申诉证据**——完成拍照、遗留记录直接服务这一层 |

结论：宏观无逆风。P/L（卫生制度化）与 S（卫生敏感）双顺风；E（价格敏感）约束商业模式但不约束机会成立；T（无 API）被本地优先架构结构性化解。

## 7. 机会缺口矩阵

以"用户重要性 × 市场现有解完整度"定位空白：

```
重要性 高 │ ①渠道直连/房态日历        ③【空白】退房周转执行 + 布草供应链账
          │ （PMS 红海）               （窗口→任务单→保洁；布草四态账，无小微级产品）
          │
重要性 低 │ ②动态定价/收益管理        ④房东个人记账
          │ （需数据与专业度）          （通用记账 App 已泛滥）
          └─────────────────────────────
             现有解完整度 高            低
```

- ③的四段拆解交叉验证：微信喊（无清单无账）、PMS（渠道思维、执行留白）、海外工具（生态不可用）、洗涤厂接单本（只管一环）——**每一段都有人做，合起来无人做**。
- ①是 PMS 的主场，40 万商家里头部连锁才用得起；③覆盖的是沉默的大多数（1~10 间）。
- ②需要经营数据与专业方法论，小微房东无感；④与本产品无冲突。
- 政策与产业事实给 ③ 背书：民宿企业存量十年 20 倍（企查查）、卫生国标 2023 年生效、海外 turnover 品类融资验证——**需求增长中、标准已生效、品类空白仍在**。

**阶段一结论**：翻房单占位 ③——一条被 40 万供给过剩与卫生国标共同供养、被微信喊保洁证明协作真实存在、却被所有软件产品忽略的缺口。
