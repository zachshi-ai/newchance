# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会怎么变成产品？用商业画布与价值主张画布定骨架，用蓝海四动作砍功能，用 USP / Kano 定卖点优先级，最后拆供应链——产品侧、产品自身、分发链。

---

## 1. 商业画布

| 模块 | 内容 |
|---|---|
| **价值主张** | 把 GB 38600 九防与 66 号令的记录义务，变成 30 秒打卡、缺班点名、事件强制闭环、检查 30 秒出证的一本机构自有底账——"照护落在纸上，安全才站得住" |
| **客户细分** | 10~100 床民办养老院 / 乡镇敬老院 / 社区嵌入式中型机构（院长兼管理者的一人多角门店）；渠道客户：辅具/适老化/护理耗材供应商、保险经纪 |
| **渠道** | ①供应商联营白标（上游即渠道）②民政检查与保险续保节奏的事件式获客 ③养老行业社群与地方养老协会 |
| **客户关系** | 自助 + 种子期微信群陪跑；无账号体系（本地优先意味着零 CRM 负担） |
| **收入流** | 免费核心（建档/打卡/事件/出证全可用）→ Pro ¥99/年（自证包自定义抬头、月报导出、多员工打卡授权）→ 渠道白标 ¥1200/年/商 |
| **关键资源** | 行当 know-how（九防字段模板、检查场景、判例叙事）、零依赖 PWA 代码资产、种子机构口碑 |
| **关键活动** | 内容供应链维护（法条/国标口径更新）、种子陪跑与 OHELM 循环、渠道联营洽谈 |
| **关键伙伴** | 辅具/适老化改造/护理耗材供应商（联营渠道）、保险经纪与养老责任险承保方（66 号令第三十四条背书）、地方养老协会 |
| **成本结构** | 近零边际成本（无服务器、无云依赖——本地优先即成本结构）；主要成本是行当内容与渠道拓展的人力 |

## 2. 价值主张画布

**用户任务（Jobs）**：迎接检查不心虚；收住老人先评估；每班交接有据；出了事告知家属有痕、复盘有措；演练/体检/评估不超期。

| 痛点 | 解药（Pain Relievers） |
|---|---|
| 纸本断更、补记痕迹明显，检查现场被怀疑 | 缺班自动点名 + 近 7 天缺班看板——断更在爆发前被看见，而不是在检查现场被发现 |
| 出事只走口头，家属事后不认 | 事件闭环门禁：**家属告知（时间+方式+通知人）与复盘整改填不齐，工具拒绝结案** |
| 九防评估"没评过"或"评了没措施" | 建档即全「未评估」点名；watch/high 级别强制填写防护措施 |
| 周期义务（演练/体检/复评）靠记性 | 周期义务账：到期/临期点名，完成打勾自动滚动下一轮 |
| 全家桶买不起、用不动 | 零安装、零账号、零费用核心；值班手机即可；导出 JSON 数据自持 |

| 收益 | 创造者（Gain Creators） |
|---|---|
| 检查/家属质询 30 秒出证 | 自证包三通道：微信文本 / 单文件 HTML（含查阅签字栏）/ 直接打印；缺口如实列出 |
| 家属信任可视化 | 九防防护措施一览 + 每班署名记录，成为参观讲解材料 |
| 数据自有 | 本地优先 = 66 号令第三十二条个人信息保护义务的实现方式，而非合规负担 |

## 3. 蓝海战略四动作（ERRC）

| 动作 | 内容 | 理由 |
|---|---|---|
| **剔除（Eliminate）** | 呼叫系统/IoT 看护硬件；民政报送接口；排班与工资；招生营销；在线收付费 | 硬件与报送是智慧养老平台与政府侧的地盘；排班招生非安全痛点；碰资金与报送会把工具拖进监管与资金责任 |
| **减少（Reduce）** | 档案管理范围——只做"服务安全"一条线（评估/值班/事件/周期），不做膳食、医疗、财务档案 | 一条线做到"检查 30 秒出证"的极值，比十个模块的半吊子有用 |
| **提升（Raise）** | 打卡速度（30 秒/班）；出证速度（30 秒/包）；异常的强制留痕（异常必写处置、结案必写告知与复盘）；缺口的诚实点名 | 速度决定纸本替代能否成立；强制与诚实决定记录在纠纷里是否过硬 |
| **创造（Create）** | ①事件闭环门禁（未告知家属不能结案——行业工具里第一次把"告知义务"做成硬约束）②自证包（按老人 × 时段重组记录，检查/家属/法官三场景共用）③缺口如实列出（把"记录不完美"从遮掩项变成整改项） | 三个创造点都来自"证明成本"这个第一性变量 |

## 4. USP（独特销售主张）

> **"每一班都有人署名，每一事都有家属签字——检查来了 30 秒出证。"**

对机构院长的一句话：*你不需要多做事，你只需要把做过的每一班照护，变成拿得出手的记录。* 差异化支点：不卖硬件、不碰报送、不做全家桶——只做小微机构自己的证明基建，数据不出设备。

## 5. Kano 模型（MVP 功能分级）

| 级别 | 功能 | MVP 处置 |
|---|---|---|
| **基本型（Must-be）** | 九防评估登记（未评估点名）；每班打卡（署名必填、异常必写处置）；缺班点名；本地数据自持与导出 | ✅ 全部内置，缺任何一个产品不成立 |
| **期望型（One-dimensional）** | 事件闭环（家属告知 + 复盘强制）；周期义务账（到期/临期点名 + 打勾滚动）；自证包生成 | ✅ 全部内置——直接决定付费叙事成立与否 |
| **魅力型（Attractive）** | 自证包打印版签字栏；夜巡不足点名；重点看护名册（高风险老人自动汇总）；月度服务安全速览 | ✅ 已内置（成本低、口碑价值高） |
| **无差异（Indifferent）** | 多院区管理、API 对接、照片/视频存证 | ❌ 不做——留待真实用户提出再说 |

## 6. 供应链分析

### 6.1 产品侧：照护供应链（工具服务的真实链条）

```
家属（付费方/质询方）
   │ 服务费 · 信任 · 事件知情权
   ▼
养老机构（本工具用户：10~100 床民办院）
   │ 采购 · 联营分发
   ▼
上游供应商：护理耗材 / 适老化改造 / 辅具 / 员工培训 / 养老责任险
   （资金流：机构的钱先流向这里；风险流：机构被罚/关停 = 上游的坏账与客户流失）
```

**洞察**：与农资批发商联营（6 号项目）同构——**上游供应商的资产负债表与机构存续强绑定**。机构因记录缺失被处罚、停业甚至刑责，上游面对的是应收坏账 + 复购客户消失；而机构投保责任险（66 号令第三十四条鼓励）时，保险端需要风控证据，理赔时需要照护记录。上游即渠道的动机比流量型渠道深一层：**帮机构合规存续 = 保护供应商自己的钱**。

### 6.2 产品自身的技术链

| 环节 | 决策 | 供应链逻辑 |
|---|---|---|
| 内容原料 | GB 38600 九防目录、66 号令义务条款、民法典 1198——全部公开法条与国标 | 权威原料免费且稳定，产品做的是**小微化拆解**（法条 → 字段 → 点名规则） |
| 生产 | 零依赖 PWA（纯 ES Module，无 npm/CDN/构建链） | 无第三方断供风险；单文件分发；SW 离线缓存 |
| 存储 | localStorage + JSON 导入导出 | 数据不出设备 = 隐私卖点 + 零服务器成本 + 换机走文件 |
| 交付 | 微信文本（主通道）/ 单文件 HTML 打印版 / 直接打印 | 收件方（家属/检查人员）零安装 |

### 6.3 分发链：上游即渠道

| 渠道 | 动机 | 打法 |
|---|---|---|
| 辅具/适老化改造/护理耗材供应商 | 机构存续 = 赊销回收 + 复购；台账完整的机构也是更好的客户 | ¥1200/年/商白标包，分发其下游 20~100 家机构客户；先谈 2 家试点 |
| 养老责任险经纪/承保方 | 投保与理赔都需要风控与记录证据（第三十四条背书） | 台账完整的机构 = 更低赔付风险；联合定价优惠或经纪返佣试点 |
| 地方养老协会 / 民政促做的行业培训 | 协会需要给会员"迎检干货" | 免费工具作为协会会员福利渗透，培训课件内置产品 |

**供应链总结**：内容链（公开法条 → 字段模板）零成本且权威；技术链（零依赖 PWA）近零边际成本；分发链借用照护供应链上**与机构存续利益一致的上游**——三段链条都不依赖烧钱。
