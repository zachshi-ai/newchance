# 00 · 总览：从世界痛点到可运行 MVP

> 项目：**安巡单 SafePatrol** —— 小微工贸企业的安全生产自查台账与动火作业许可
> 仓库：`newchance` · 状态：MVP 已开发并通过端到端验证（`app/` 目录，25/25 单元测试 + 浏览器全流程）
> 一句话：**安全合规的第一性变量是证明成本——安巡单把"如实记录"变成 30 秒打卡，把应急管理部令第 10 号的判定标准变成动火开票前的软件闸机（无有效焊工证，这张单开不出来），把检查要看的五本台账变成一页纸迎检包：检查来之前，台账先在。**

## 1. 痛点（真实世界，有据可查）

安全生产的法定义务链是"排查 → 记录 → 治理 → 通报"，而小微工贸主体（1~50 人的加工厂、注塑坊、木器厂、仓储点）的现状是：义务每天连着，台账只在检查前存在。

- **如实记录是法定义务**：[《安全生产法》第 41 条](14-调研来源.md#法规与政策红线口径的直接依据)要求事故隐患排查治理情况**如实记录**并向从业人员通报；未如实记录、特种作业人员无证上岗 → 第 97 条责令限期改正处 10 万元以下罚款，逾期未改正**停产停业整顿**并处 10 万~20 万元（检索口径）。
- **执法已经清单化**：[《工贸企业重大事故隐患判定标准》（应急管理部令第 10 号，2023-05-15 施行）](https://www.mem.gov.cn/gk/zfxxgkpt/fdzdgknr/202304/t20230417_448156.shtml)把 64 种情形直接判定为重大事故隐患——通用类第（二）项就是"特种作业人员未取得相应资格，上岗作业"。焊工证过期一天，当天动火就是重大事故隐患。
- **尾部风险是生存级**：2022 安阳"11·21"火灾 38 人、2023 北京长峰医院火灾 29 人（公开通报口径），调查都指向违规动火作业——对小微厂主这是罚款、停产、刑责三连。
- **现状解法 = 纸检查表 + 微信群 + 记性**：检查来了翻箱倒柜找证、隐患开了单就石沉大海、培训签名凑数、动火全凭"喊一嗓子"——第一性差距：**日常动作与法定台账之间没有任何小微级工具把它变成"做动作即留痕"的证据链**。

## 2. 方案（机会 → 产品）

**安巡单**：零依赖、本地优先的 PWA。

1. **今日安全台**：五类红灯一屏点名（证照过期/临期、逾期隐患、未销票动火、未自查、演练超期），"今天做什么"按红灯优先级排序——厂长只需要看一条待办清单。
2. **30 秒十二项自查**：执法高频词拆解的通用检查项，异常必须写明情况并自动登记为隐患（"如实记录"的软件门禁）；当天只查一半也如实记录。
3. **隐患闭环状态机**：登记 → 整改（说明必填）→ 复查销案（记录必填），逾期红灯；只打勾不留痕被直接拒绝——隐患只有闭环才有台账意义。
4. **动火开票闸机（核心差异化）**：焊割动火必须挂当日有效的焊工证，过期证开票被拒（错误信息直接引用令 10 号口径）；六项安全措施逐项确认、监护人必填；完工销票。**开不出来的单子，就是今天不该动的火。**
5. **证照三态引擎**：6 类证种（焊工/电工/高处/制冷/叉车司机证/叉车定检），证面"有效期至"录入，60 天黄线（可调），过期即红并点名"到期办理"动作。
6. **培训与演练体检**：按人按年学时累计 vs 红线（默认 8，可覆盖）；综合/专项与现场处置方案演练频次体检（周期可覆盖）。
7. **迎检自证包三通道**：微信快报文本（主通道）/ 打印版单文件 HTML（账本体检 + 五本台账 + 签字栏，离线可用）/ 直接打印——检查要看的都在一页纸上。
8. **数据自持**：全部存本机 localStorage，JSON 导出导入；员工名单、证件号、隐患记录不出设备。

## 3. 诚实的现状声明（真实可落地，不空中楼阁）

- **已验证**（本仓库内可复现）：核心逻辑 25/25 单元测试通过（含开票闸机六类拒绝、隐患状态机跳级拒绝、证照三态边界、学时/演练体检、闭环率口径、XSS 转义、导出导入往返）；浏览器端到端真实走通（示例数据 → 今日台红灯排序 → 自查异常强制留隐患的门禁拒绝与放行 → 过期焊工证开票被拒/有效证开票成功 → 迎检包体检与快报生成 → 学时体检点名）+ 界面截图核验；打印版 HTML 为单文件离线可用；零 npm/CDN/API 依赖；SW 缓存版本化。
- **未验证**（需真实用户，见 [docs/13](13-阶段四-产品落地验证闭环.md) 假设登记册）：建档留存（H1）、自查习惯（H2）、隐患真闭环（H3）、动火真实使用（H4）、迎检包真实使用（H5）、付费（H6）、培训机构渠道（H7）、复训联动（H8）——全部标注"待验证"并配有可证伪判据。
- **边界与免责**：不做监管报送、不做证照真伪核验（提示官方平台）、不做拍照 OCR 与云同步；动火单是企业内部许可的数字化，高危行业法定审批另行适用；台账如实记录是义务的底线，不是事故的护身符；**属地规则与最新公告永远赢**（全部口径参数化，企业可覆盖）。

## 5. 与既有项目的领域隔离（用户约束）

本方向为**工贸小微 · 安全生产自查与动火作业台账（B2B · 1~50 人小微加工/仓储企业 · 应急管理监管线）**，已对照仓库根 README 领域登记表做领域排除：不与 pet-handoff（C 端宠物照护）、food-sentry（餐饮食安台账，市监线）、turn-sheet（民宿短租周转与布草）、work-proof（人社线劳动用工）、class-off（教培预收费课时账）、agri-ledger（农业农村线农药购销）、car-sheet（二手车经销车况披露）、bottle-safe（瓶装液化气网点配送与入户安检，住建/城管燃气监管线，经营主体是燃气网点）、steril-sheet（口腔诊所器械灭菌追溯，卫健·院感线）重叠；与同期在建草稿亦不同域——养老机构服务安全（民政线）、汽修厂危废台账（生态环境线·废物流）、泳馆水质（体育/卫生线）。本方向属**应急管理部门主管的工贸企业安全生产**（企业侧自查与动火许可）：与燃气安检同写"安全"但法源不同（安法/令 10 号/消防法 vs 城镇燃气管理条例）、主体不同（加工制造与仓储企业 vs 燃气经营网点）；与汽修危废同涉"工厂"但一条管生产安全一条管废物流。付费方（厂长与安全培训机构）、使用场景（车间自查与动火开票）、行业语境（重大事故隐患判定清单）均独立成域。与 `newidea` 仓库 67 个点子亦无重叠（检索其索引无安全生产/动火/叉车/应急管理方向）。
