# 00 · 总览：从痛点到 MVP（递安单 ParcelProof）

> 机会实验室 **#19 号项目** · 邮政业监管线 · 快递末端网点合规与服务台账。
> 本文档是四阶段方法论的地图：每一个框架都真实应用于本项目（细节见 10~14 号文档），不是模板套话。

## 一句话

**检查来了 30 秒出证，罚款来了 10 分钟出申诉单**——递安单把小微快递末端网点（快递超市/驿站兼收寄点/承包区站点）每天真实发生的三项制度、投诉处理、底单销毁、培训演练变成拿得出手的履责痕迹，并把总部考核罚款变成一本可挽回的账。

## 痛点

末端网点站在寄递安全的闸口上：收寄验视与实名查验（反恐法第 20 条；条例第 23、32 条）、发现问题件停止运转（第 34 条）、投诉 7 日内处理并告知（第 29 条）、运单定期销毁（第 35 条）、培训演练（第 21、36 条）、开办 20 日内备案（第 19 条）——义务的执行现场在网点，罚则的牙齿也是 2025 年修订后最新磨过的（未备案 1 万~5 万、加盟链未统一管理 1 万~10 万、验视违规转致反恐法 10 万~50 万、运单未销毁/信息泄露 1 万~10 万）。而网点只有总部系统（管业务流）和一本纸台账（检查前突击）——**"做了"与"能证明做了"之间没有任何小微级工具**。还有一条独有的钱线：总部考核罚款月月挨罚，申诉要证据，没人替网点把证据留成账。

## 方案

零依赖本地优先 PWA——五本账 + 四只钟 + 三种出证：

- **五本账**：每日三项制度落账（验视/实名/安检三确认，异常必登记）、拦截登记簿（拒验视/身份不实/禁寄嫌疑，闭环处置——拦下来的每一件都是没被罚的证据）、投诉台账（渠道/事项/答复日）、考核罚款与申诉挽回账（登记→申诉→结果→挽回金额）、底单销毁台账（定期销毁条例第 35 条的落实痕迹）。
- **四只钟**：投诉 7 日答复钟、备案 20 日红线钟、销毁周期钟、周期义务钟（培训/演练/消防器材/车辆电池充电）。
- **三种出证**：月度小结（微信文本）、迎检自证包（单文件 HTML 含签字栏，对口条例第 46 条检查重点）、申诉材料单（单笔罚款的时间线+证据清单打印版）。

## 快速开始

```bash
cd parcel-proof && npm start   # → http://localhost:8096
npm test                       # 纯逻辑层单元测试（node --test）
```

## 诚实条款

技术可行性已在仓库内验证（单元测试 + 浏览器端到端手测：建档→示例数据→看板红灯→日落账→拦截→投诉闭环→罚款挽回→出证全链路）；本工具是网点自查与申诉的底账——不碰实名收寄报送、不做政府平台接口、不做件数对账与财务进销存；法定条号全部为 2025 修订版（国务院令第 806 号）口径并集中于 docs/14 带出处维护，属地规则、品牌制度与证件文书永远赢；相关人员信息最小披露只存本机；月度挽回金额是网点自己登记的口径；商业假设全部标注"待验证"并配有可证伪判据。
