# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会怎么变成一个能交付的产品？用商业画布定商业结构，用价值主张画布对齐用户，用蓝海四动作砍掉不该做的事，用 USP 说清一句话，用 Kano 排功能层次，最后把供应链（内容链 + 技术链 + 分发链）拆到能执行。

---

## 1. 商业模式画布

| 模块 | 内容 |
|---|---|
| **客户细分** | 主：小微电梯维保公司（1~30 名维保工、在保 100~2000 台）的老板/调度；次：维保工（执行者）；参与方：使用单位安全管理人员（签字端，不付费） |
| **价值主张** | 四周期自动滚动不漏台；30 秒落单；使用单位签字链闭环；困人救援时钟；迎检包一键出证；维保费月账即催款凭据 |
| **渠道** | ① 电梯配件经销商白标联营（主）；② 老板熟人网络/维保工微信群直销；③ 检验机构不碰（政府关联线，保持中立） |
| **客户关系** | 自助（零安装 PWA）+ 渠道方陪跑（配件商业务员上门顺带演示） |
| **收入来源** | ① 维保公司 Pro：¥99/年（台量无限 + 月账 + 迎检包）；② 配件商白标：¥1500/年/商（分发下游 10~100 家）；③ 后期：与检验/保险的数据合作（假设，未验证） |
| **关键资源** | T5002 叠层周期与签字链的领域正确性；配件商渠道关系；沉淀的维保台账数据 |
| **关键活动** | 保持法规口径更新；渠道方启用与培训；HDD 假设验证循环 |
| **关键伙伴** | 电梯配件经销商（光幕/门机/钢丝绳/按钮/导靴等耗材）；维保行业协会（后期） |
| **成本结构** | 近零边际成本（本地优先无服务器）；人力：法规跟踪 + 渠道拓展 |

## 2. 价值主张画布

**用户侧（老板/调度）**
- 任务：不漏保、记录合规、收得到钱、出事说得清
- 痛：漏保被罚；纸单丢/补签穿帮；物业拖欠；半夜困人到场时间说不清
- 收益：睁眼看见今天该干啥；检查来了 30 秒出包；老板能算清每台梯赚不赚

**产品侧**
- 产品：零依赖本地优先 PWA
- 止痛：四周期引擎（红黄绿点名、深层覆盖浅层）；落单门禁（异常必须写处置、补录如实打标）；签字确认单三通道；救援时钟（30/60 分钟口径参数化）
- 创益：迎检打印包；月账（应收/已收/欠收/签字率）；七项体检

**契合点**：用户的「证明成本」= 产品的「一键出证」；用户的「组合调度」= 产品的「叠层滚动引擎」。

## 3. 蓝海四动作（ERRC）

| 动作 | 内容 | 理由 |
|---|---|---|
| **剔除 Eliminate** | 物联网传感器与远程监测；政府平台报送；派单调度大系统；财务进销存；员工 GPS 打卡 | 不是小微的痛，且各有专业玩家；避免与监管平台争名分 |
| **减少 Reduce** | 保养项目清单 → 据 T5002 附件整理的关键子集（可增删）；落单字段 → 一屏；账号体系 → 无（本地优先） | 让 30 秒落单成立 |
| **提升 Raise** | 周期正确性（叠层覆盖、参数化）；签字链闭环；应急时限计时；异常处置强制留痕 | 这是「合规底账」区别于「打卡工具」的地方 |
| **创造 Create** | 补录如实打标（不可关闭）；迎检包按使用单位出整链；欠费月账作为催款凭据；年度自行检查与定期检验窗口联动门 | 纸质时代结构性不存在的能力 |

## 4. USP（一句话）

> **梯保单是唯一把 TSG T5002-2017「四类周期叠层滚动 + 使用单位签字确认」做成小微价位、离线可用、30 秒落单的电梯维保底账。**

## 5. Kano 模型

| 层 | 功能 | 说明 |
|---|---|---|
| **基本型**（没有就不算产品） | 电梯档案、落单记录、记录可查可导出、维保人员在册 | 法定记录四要素（第七条） |
| **期望型**（越好越满意） | 四周期排班红黄绿、签字确认链、迎检打印包、检验/证件/演练到期点名 | 直击漏保与证明失效 |
| **兴奋型**（没想到还能这样） | 补录如实打标、救援时钟、月账催款凭据、自行检查与检验窗口联动 | 用户第一次「被工具保护」而非「被工具管理」 |
| **无差异** | 主题皮肤、多语言 | 不做 |
| **反向**（做了反而差） | 强制上云、强制账号、按台收费 | 明确不做 |

## 6. MVP 功能边界（本仓库已实现）

1. 电梯档案（品种对应附件 A~D、接管日、下次检验、月费）
2. 四周期滚动引擎 + 排班看板（按使用单位分组、建议本次类别）
3. 落单（叠层项目清单、异常强制说明、补录打标、自行检查检查人/审核人门禁）
4. 台账与签字确认（首次确认不可覆盖、确认日期不早于维保日期、待签字点名）
5. 应急（接报→到场→闭环三时点、30/60 分钟参数化、超时如实保留）+ 演练按品种半年点名
6. 月账（应收/已收/欠收/落单数/签字率）
7. 七项体检（六合规 + 一经营）
8. 出证三通道：确认单微信文本 / 打印版单文件 HTML（签字栏）/ 直接打印；迎检打印包（按使用单位整链）
9. 备份导出/导入、事件流埋点

## 7. 供应链分析（三条链）

### 7.1 内容链：法规原文是免费权威原料
- 上游：《特种设备安全法》、TSG T5002-2017 及附件 A~D（公开发布，零成本）
- 加工：把第六条叠层结构编译成 `itemsFor()` 并集函数；把第五条义务清单编译成体检项；把第七条四要素编译成确认单模板
- 风险：规则修订 → 参数化（周期天数、救援时限、黄线天数全部在设置页）；清单只做关键子集并明示「全量以原文为准」

### 7.2 技术链：零依赖 = 零供应商风险
- 无框架、无构建、无云；`python3 -m http.server` 即可跑；localStorage 存储、JSON 导出
- 数据主权在用户设备，天然满足「小微怕数据在别人手里」的心理；代价是多设备同步靠导出导入（诚实标注为 MVP 限制）

### 7.3 分发链：上游供应商即分销商
- **电梯配件经销商**向维保公司卖光幕、门机、钢丝绳、导靴、按钮、润滑油——**周周复购**，业务员常年上门
- 渠道动机不是「赚白标费」，而是：**下游维保公司被停业/吊证 = 配件商客户池流失**；帮下游合规存续 = 保护自己的应收与复购
- 白标形态：配件商 logo + 联系电话进入确认单/迎检包页脚，业务员上门即演示，装机零成本
- 明确不碰：检验机构、监管部门（保持中立，避免被视为「监管代理」）
