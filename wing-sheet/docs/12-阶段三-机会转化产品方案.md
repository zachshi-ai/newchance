## 价值主张画布（任务-痛点-爽点 ↔ 产品-止痛-创爽）

- **用户任务**：合法接单、通过检查、出事自证、按期换证。
- **痛点**：不知道自己是什么类别/要哪些纸；时限（前1日12时/起飞前1小时/24小时报告）靠记忆；检查现场拿不出记录。
- **产品止痛**：判档器（第62条结构化）、申请台账三段时钟（第26/30/40条）、航前放行+迎检自证包（第32条+92.547 留存口径）。
- **创爽**：月度小结把"收入 + 安全 + 合规"同屏发群里，合规变专业度展示；带病机被拒那一刻的"挡弹感"。

## 蓝海四动作（ERRC）

- **剔除**：飞行动画/社交分享/空域地图渲染（大厂 App 的主场）——本工具不做"好看"，只做"敢签字"。
- **减少**：注册门槛（免注册即用）、字段数量（只收法规要求数据，不收客户身份信息）。
- **增加**：条号级依据展示（每个钟/每个门禁都带条款）、判档器（厂商 App 也没有）、迎检自证包（全行业空白）。
- **创造**：「飞前 10 分钟」时刻占有率；开飞被拒的门禁体验（把监管逻辑前移成产品逻辑）。

## USP（三句话卖货）

1. **唯一按 761号令+CCAR-92 条号造钟的机队台账**：每一盏红灯都写得出条款（第10/12/16/26/30/40条、92.61/92.81/92.669/92.671）。
2. **判档器**：两个重量进去，义务清单出来——微/轻/小/中/大 + 农用包线（第62条/第11条3款）一秒定档。
3. **三道硬门禁**：未登记不开飞（第47条）、带病机不开飞（第32条(二)）、无批复/无起飞前报告不开飞（第19/30条）——工具替你说"不"。

## Kano 模型

- **基本型（没有就骂人）**：证照钟、执照/检查到期提醒、申请时限红线。
- **期望型（越多越好）**：航前检查单、检修闭环、月度小结、体检打分。
- **兴奋型（没想到会有）**：判档器义务清单、迎检自证包单文件 HTML、安全问题 24 小时钟自动起算、条号引用跟着每条记录走。

## 供应链分析（三层）

**① 产品侧（用户行业的上游）**：整机/电池 → 保险 → 培训考证 → 空域服务。本工具站在这些环节的交汇处但不碰交易：保险到期钟指向经纪（转介机会）、操作证书复训指向培训机构（渠道机会）、运营合格证指向民航部门（不代办，只备台账）。**不做交易环节的原因**：代办资质存疑、保司合作门槛高——工具先赢时刻，交易后置。

**② 产品自身供应链（零依赖决策）**：无服务器 → 无账单与停服风险；无 npm → 无投毒攻击面；无 CDN → 县域弱网/野外作业离线可用（PWA + SW 缓存）；数据 100% 本机 localStorage → 飞手最敏感的飞行位置与收入数据不出设备。导出 JSON 即离线归档（对齐 92.547 的 12/15 个月留存口径）。

**③ 分发供应链**：培训机构（结业即发，黏性最高）→ 植保机经销商（随机交付）→ 保险经纪（年续保天然触点）→ 行业协会/社群（信任背书）。渠道白标版让渠道用自己的牌子分发——合规工具对渠道是"帮客户活下来"的服务，不是成本。
