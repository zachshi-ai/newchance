> 项目：**灭菌单 SterilSheet** —— 小微口腔诊所的器械清洗消毒灭菌追溯单与院感自查台账
> 仓库：`newchance` · 状态：MVP 已开发并通过端到端验证（`app/` 目录，32/32 单元测试 + 浏览器全流程含召回闭环）
> 一句话：**灭菌效果肉眼看不见，台账是唯一的证明：灭菌单把一锅变成一单、把四类记录连成患者到监测的完整链、把过期发放变成工具硬性拒绝的事、把监测阳性变成自动生成的召回名单——诊所第一次「连得上、对得上、拿得出」。**

## 1. 痛点（真实世界，有据可查）

- **一人一用一灭菌是强制标准**：[WS 506-2016《口腔器械消毒灭菌技术操作规范》](14-调研来源.md#标准与法规红线口径的直接依据)（强制性卫生行业标准）要求口腔器械一人一用一消毒/灭菌、牙科手机等高度危险器械必须灭菌、清洗包装灭菌监测**记录并可追溯**——「每用一个包都要有台账」是法定动作。
- **灭菌是信任品**：效果肉眼不可见，且单条记录没有意义——患者→包→锅→监测必须**连成链**才算「可追溯」。小微诊所的现状是三本手写账 + 机壳上的指示胶带 + 靠记忆发放：链路天然断裂。
- **拿不出的代价被法律放大**：纠纷中隐匿、遗失、无法提供资料的医疗机构可被**推定有过错**（民法典 1222 条口径）；口腔是消费医疗，感染事件会被差评与本地新闻无限放大。
- **召回在今天几乎不可能被执行**：生物监测阳性要召回已发放器械，但发放没记录——「用过这锅的患者是谁」数不出来。这是纸本时代结构性不存在的能力。
- 第一性差距：**四类记录（锅次/监测/效期/患者）的可拼装性没有任何小微级工具承接**——灭菌单把记录变成链、把链变成 30 秒拿得出的证。

## 2. 方案（机会 → 产品）

**灭菌单**：零依赖、本地优先的 PWA。

1. **灭菌落账（一锅一单）**：装载明细 + 化学/BD/生物监测 + 操作者 30 秒记全，锅编号自动生成（日期-锅代码-当日序号）；化学不合格必须写处置说明且不放行。
2. **无菌柜（先灭先用）**：在库按失效日自动排序，纸塑 180 天/布类 7 天（逐包可改）；临期黄线、过期红灯；**过期与召回冻结包的发放被工具硬性拒绝**并给可执行指引。
3. **使用落账（患者端点）**：发放必填患者标识（姓名缩写/病历号，最小披露、不出设备）——追溯链的最后一环。
4. **召回闭环（红线引擎）**：生物监测阳性 → 批次冻结 + 自动生成已发放患者名单 + 处置登记守恒校验 → 写明经过才能销案；全程不可改判洗账。
5. **周期任务台账**：生物监测周期、培养结果宽限、医废交接（≤2 天）、健康证、指示物/消毒剂效期——到期自动亮灯。
6. **出证三通道**：追溯自证单（按患者拼链，召回历史如实打标）、月度迎检包（锅次台账 + 体检 + 签字栏）——微信文本 / 单文件 HTML 打印 / 直接打印，30 秒交付。
7. **院感体检**：七项自查打分（监测连续性/培养结果/过期在库/召回闭环/医废/健康证/耗材效期），检查前心里有底。

## 3. 诚实的现状声明（真实可落地，不空中楼阁）

- **已验证**（本仓库内可复现）：核心逻辑 32/32 单元测试通过（含守恒恒等式、FIFO、过期/冻结发放门禁、召回状态机、出证确定性、XSS 转义、导入导出往返）；浏览器端到端全流程含召回闭环真实运行通过；打印版单文件离线可用；零 npm/CDN/API 依赖；SW 缓存版本化。
- **未验证**（需真实用户，见 [docs/13 假设登记册](13-阶段四-产品落地验证闭环.md)）：落账留存（H1）、患者标识真实填写（H2）、迎检出示（H3）、追溯使用（H4）、召回真实执行（H5）、付费（H6/H7）、检查采信（H8）——全部标注「待验证」并配有可证伪判据。
- **边界与免责**：不做挂号病历收费、不碰传感器、不做监管报送；追溯单是诊所自查记录不是司法证据；监测频次与效期默认值为通识先验，**WS 506-2016 原文、设备说明书与属地要求永远赢**；患者标识最小披露且只存本机。
