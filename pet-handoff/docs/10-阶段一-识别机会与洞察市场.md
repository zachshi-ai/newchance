# 10 · 阶段一：识别机会与洞察市场

> 本阶段回答：世界的哪个痛点值得做？用第一性原理拆到底，用 JTBD / 船模型 / 非消费者分析还原真实场景，用 PESTEL 扫宏观，用机会缺口矩阵定位空白。

---

## 1. 第一性原理拆解

不问"市面上有什么宠物 App"，只保留不可再分的事实：

| # | 不可再分的事实 | 推论 |
|---|---|---|
| F1 | 节假日主人必然离家（春节/国庆是人类节律） | 托养需求是周期性刚需，与宠物数量正相关 |
| F2 | 动物无法自我陈述需求（饿了/病了/怕了都说不出） | 照护质量完全依赖"信息的完整传递" |
| F3 | 照护质量 = 信息质量 × 照护者执行力 | 两者都可控；信息质量是主人一侧唯一可控变量 |
| F4 | 现状：信息传递靠记忆 + 微信碎片 + 口头叮嘱 | 信息在"主人觉得说清了"处截断 |
| F5 | 纠纷与事故的善后成本极高（送医 8200 元、对簿公堂） | 预防信息断层的价值远超其工具价格 |
| F6 | 宠物被 83% 的主人视为家庭成员 | 情感权重高 → 对"确定性"的支付意愿高于功能型消费 |

**第一性结论**：解的本质不是"再造一个寄养平台"（那是船），而是**把照护信息本身变成可结构化、可送达、可留痕的对象**。撮合解决"找谁"，宠托付解决"交出去之后怎么不出错"。

## 2. 痛点 - 爽点 - 痛点模型（梁宁）

| 层 | 用户心理 | 宠托付对应 |
|---|---|---|
| **痛点**（恐惧/怕） | 怕走失、怕喂错药、怕应激生病、怕断粮断水、出了事说不清 | 交接单把禁忌红条置顶 + 紧急联系卡 + 易走失警示，直接对冲恐惧清单 |
| **爽点**（即时确定性） | 30 秒出一张"专业交接单"，发出去那一刻心里落地 | 一键生成 + 三通道送达（HTML 文件/纯文本/打印），即时完成感 |
| **痒点**（虚拟自我） | "我家毛孩子的护照比我的还精致" | 交接单排印如官方文件，可晒、可存档，满足"负责任的主人"身份叙事 |

优先级：痛点 > 爽点 > 痒点。MVP 只做痛点与爽点，痒点靠排版顺手满足，不做社交功能。

## 3. JTBD（待办任务）

**主任务陈述**：**当**我离家 N 天（节假日/出差/就医），**我要**把宠物的照护完整、可验证地交出去，**以便**它平安健康，我心里有底，出事有据可依。

三维拆解：

| 维度 | Job | 现状方案的失败点 |
|---|---|---|
| 功能性 | 告知喂食量/时间、用药剂量、禁忌、习惯 | 微信语音信息密度低，照护者靠回忆 |
| 情感性 | 离家期间持续安心（掌控感） | 只能反复打扰照护者确认 |
| 社会性 | 向家人/自己证明"我是尽责的主人"；给照护者"专业凭据" | 没有任何凭据化载体 |

**竞品不是别的 App，而是"微信长语音 + 口头叮嘱"和"什么都不给"**——它们免费、零门槛，这是我们真正的敌人（见阶段二波特五力：替代品威胁）。

## 4. 船模型

> 用户要的从来不是船，是安全过河。

| 元素 | 本场景 | 现状问题 |
|---|---|---|
| 海岸→海岸 | 家 → 主人回家 | — |
| 乘客 | 主人（与宠物一起） | — |
| 船 A：寄养机构 | 300 元/天起，节假日 30~50% 溢价 | 贵、陌生环境应激、交叉感染、操作不透明 |
| 船 B：上门宠托师 | 30~100 元/次，新业态爆发 | 个体服务质量参差，交接靠微信，无标准 |
| 船 C：亲友帮忙 | 免费 | 不懂宠物，"以为喂一把就行" |
| 河 | 信息断层 | 三条船共同的黑水区 |

**定位推论**：宠托付**不造船**，做**给所有船统一配发的《航行手册》**——横向赋能三种托养形态，与寄养机构/宠托师是合作关系而非竞争（B 端白标是后续渠道，见商业画布）。

## 5. 非消费者分析（Christensen）

| 非消费者类型 | 画像 | 为什么不用现有解 | 对产品的启示 |
|---|---|---|---|
| 从未写过交接说明的人 | 大多数第一次寄养的主人 | 不知道该交代什么；觉得"跟照护者说一声就行" | 模板要**预设结构**（犬/猫模板预填条目），让空白页变成填空题 |
| 用 Notion/纸质模板的人 | 已有意识的人群 | 每次托养重写一遍；无日程推算；不美观 | 档案一次建立反复复用；日程自动推算；排印精致 |
| **因放不下宠物而不出门的人** | 痛点最深的隐性非消费 | 任何托养都不放心 | 这是最强需求信号——交接单 + 日志回传正是给他们的"确定感" |

非消费者共同阻碍排序：**不知道写什么（门槛）> 懒得重写（精力）> 没凭据（信任）**。MVP 依次对应：模板预填、档案复用、时间戳版本声明。

## 6. PESTEL 宏观扫描

| 维度 | 要点 | 对本机会 |
|---|---|---|
| **P** 政治 | 多地推进养犬登记/芯片化管理；宠物友好城市试点 | 芯片号字段顺势而为；登记信息可手动归档 |
| **E** 经济 | 犬猫消费 3002 亿（2024, +7.5%）→ 3126 亿（2025）；预测 2028 破 4000 亿；单只犬年均 3006 元 | 大盘中"服务"增速快于商品；工具类成本低可先免费 |
| **S** 社会 | 19-30 岁养宠者占 80%；83% 视为家人；单身/少子化推高情感陪伴需求；假期出行常态化 | 目标人群与移动互联网重度用户重合，获客内容化可行 |
| **T** 技术 | 无统一宠物健康数据标准/API；短视频已普及喂养知识 | 无数据 API 不是缺陷——本地优先 + 手动录入恰好规避数据供应链风险，同时有机会成为"交接单事实标准" |
| **E** 环境 | 纯软件，无硬件/冷链/物流 | 供应链极轻（详见 12 供应链分析） |
| **L** 法律 | 寄养纠纷司法案例增多；服务责任认定依赖证据 | **交接单天然是证据链一环**（时间戳+版本声明），法律环境是顺风而非风险 |

结论：宏观无逆风，L（纠纷证据化）与 S（家庭成员化）是结构性顺风。

## 7. 机会缺口矩阵

以"用户重要性 × 市场现有解完整度"定位空白：

```
重要性 高 │  ①寄养撮合平台        ③【空白】托养信息交接
          │  （已有：多家平台）      （无结构化中文工具）
          │
重要性 低 │  ②宠物社交/头像相册    ④喂食打卡记录 App
          │  （泛滥）              （已有多个，且与托养场景脱节）
          └─────────────────────────────
             现有解完整度 高            低
```

- ①③交叉验证：撮合（找人）已解决，**交接（把事说清）无人做**——平台内置卡片（如 Rover Cards）绑定平台交易，无法覆盖宠托师个体、亲友帮忙、机构存档三大场景。
- ④是"日常记录"陷阱：频率高但重要性低、无付费动机；③频率低（每年数次）但单次情感权重极高，且首单即感知价值。

**阶段一结论**：宠托付占位 ③——结构化托养交接，一个真实存在、被媒体与司法案例反复引用、却无人产品化的缺口。
