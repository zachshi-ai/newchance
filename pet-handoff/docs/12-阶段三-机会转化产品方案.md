# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会变成什么产品、给谁创造什么价值、凭什么赢、供应链撑不撑得住？—— 商业画布定整体，价值主张画布对齐需求，蓝海四动作定差异化，USP 收敛表达，Kano 裁剪 MVP 范围，最后单独把供应链过一遍。

---

## 1. 商业画布（Business Model Canvas）

| 模块 | 内容 |
|---|---|
| **客户细分** | ① 假期出行的城市养宠青年（19-35 岁为主，猫双职工家庭/犬遛狗家庭）② 上门宠托师/小型寄养机构（B 端，需要专业凭据）③ 帮忙照护的亲友（被动用户，受益于清晰指令） |
| **价值主张** | 对主人：2 分钟把"说清楚的错觉"变成"说清楚的一页纸"，安心出门；对照护者：谁来看都能照做的指令 + 出事时的免责凭据；对机构：白标交接单提升专业形象 |
| **渠道** | ① 内容渠道：小红书/抖音"托养交接清单""出门前必做"（痛点内容天然有传播性）② 寄养机构与宠托师社群分发（白标）③ GitHub/应用商店（PWA 免安装）④ 节假日节点营销（节前 2 周脉冲） |
| **客户关系** | 自助 + 内容社群；无客服压力（本地优先、零账号）；机构客户一对一 |
| **收入来源** | MVP 全部免费（验证期）。Pro（验证后假门测试 H5）：多宠不限 + 多模板/品牌定制 + 日志导出报告 ¥6/月 或 ¥39/年；B 端白标 ¥XXX/年/店（待访谈定价） |
| **核心资源** | 交接单内容结构（格式标准）、犬猫照护模板知识库、本仓库代码与文档 |
| **关键业务** | 内容创作与分发、模板知识维护（兽医审校）、用户访谈与假设验证（OHELM 循环） |
| **重要伙伴** | 兽医师（内容审校）、寄养机构/宠托师（渠道兼受益者）、内容平台（流量） |
| **成本结构** | ≈ ¥0/月：静态托管（GitHub Pages/Vercel 免费）+ 域名 + 人力（内容与迭代）。这是零依赖架构的直接红利——跑 1 年不烧钱，验证失败成本趋近于零 |

## 2. 价值主张画布（Value Proposition Canvas）

**用户侧**

## 3. 蓝海战略四动作框架（ERRC）

| 动作 | 内容 | 为什么 |
|---|---|---|
| **剔除 Eliminate** | 账号注册、云同步默认开启、社交/社区、硬件联动（喂食器）、撮合抽佣 | 注册与硬件是转化漏斗最大漏洞；撮合是重运营红海，与"轻工具"定位冲突 |
| **减少 Reduce** | 字段数量（一页装下）、设置成本（零注册零配置）、页面数（7 个视图封顶） | 对冲 R1 惯性风险：比"组织一段微信语音"更省事才有人用 |
| **提升 Raise** | 照护者视角可读性（大字号禁忌红条、表格化喂食/用药）、凭据感（版本化+时间戳）、送达成功率（微信原生三通道） | 交接单的唯一 KPI 是"照护者真的看了照做了" |
| **创造 Create** | ① 单文件交接单（微信生态原生传递，行业无此物）② 照护日志回传闭环 ③ 免疫驱虫到期与托养时段联动预警 ④ 禁忌速查内嵌（照护前 30 秒教育） | 创造项全部零成本可做，构成体验差异点 |

**战略草图**（1-10 分，行业惯例水平 vs 宠托付）：注册门槛 8→0；交接信息结构化 2→9；凭据化 1→8；硬件联动 5→0；撮合 7→0；送达便利 3→9。**曲线形状：剔除-创造的典型蓝海轮廓，而非在既有维度上加分竞争。**

## 4. USP（独特销售主张）

> **主 USP**：**"2 分钟，生成一张照护者真正会看的托养交接单——微信一发即达，出门前最后 30 秒的安心。"**

三个支撑点：
1. **谁来看都能照做**：喂食精确到克与时间、禁忌红条置顶、用药剂量单列——不是"它吃一点点"，是"07:30 成犬粮 150g"。
2. **出事有据**：时间戳、版本声明、紧急联系与常去医院一页俱全，纠纷时它是证据链的一环。
3. **零门槛**：不注册、不下 App、数据不出设备；打开网页就能用。

广告语候选（A/B 待验证 H4）：「出门前，把毛孩子说清楚」「它不会说话，你替它说清楚」「比寄养单更懂它的，是你写下的这一页」。

## 5. Kano 模型 → MVP 范围裁剪

| 类别 | 功能 | MVP 决策 |
|---|---|---|
| **必备（有之不谢，无之抱怨）** | 宠物档案、喂食表、禁忌、紧急联系 | ✅ 全部落地 |
| **期望（越多越满意）** | 用药表、日程到期预警、数据导出备份 | ✅ 全部落地 |
| **魅力（无之不怪，有之惊喜）** | 单文件交接单、纯文本一键复制、照护日志回传、易走失自动警示 | ✅ 全部落地（构成传播点） |
| **无差异** | 宠物照片上传、多语言、暗色模式 | ❌ 砍掉（照片有隐私与体积成本，收益低） |
| **反向（做了扣分）** | 主动医疗/剂量建议、推送轰炸、云上传默认开启 | ❌ 明确不做并写入免责边界 |

Kano 的结论直接变成了 `app/` 里"有什么"和"坚决没有什么"的边界。

## 6. 供应链分析（重点：软硬两条链）

### 6.1 产品侧供应链（宠托付为用户整合的"上游"）

| 环节 | 现状 | MVP 处理 | 演进方向 |
|---|---|---|---|
| 免疫/驱虫周期知识 | 无统一 API，散见兽医科普 | 内置犬/猫模板（行业公开惯例），全站标注"遵医嘱" | 兽医审校（H8）→ 付费专家内容 |
| 有毒食物/植物清单 | 权威兽医机构公开资料 | 内置 16 条犬猫速查，注明"不完整" | 扩展 + 中毒急救渠道一键拨号 |
| 照护服务供给（寄养机构/宠托师） | 分散、个体化 | 不整合（不做撮合），以交接单标准**横向赋能** | B 端白标 = 把服务供给变成渠道 |
| 数据上游（疫苗记录/芯片） | 各医院自建记录，无互通 | 手动录入 + 芯片号字段兼容登记制 | 短期无解也不阻塞：低频数据手动成本可接受 |

**结论：产品侧供应链全部为"知识内容"而非"实体货物"——无库存、无物流、无冷链、无供应商账期，是本项目"真实可落地"的最大结构性优势。**

### 6.2 产品自身供应链（MVP 的技术依赖链，逐项消除单点故障）

| 依赖 | 风险 | MVP 决策 |
|---|---|---|
| 后端服务器/数据库 | 成本+运维+隐私 | ❌ 不存在：localStorage 本地优先，静态文件即产品 |
| npm 生态（440+ 主流包遭投毒的供应链攻击面） | 安全 | ❌ 零 npm 依赖，日期计算/存储/渲染全部手写（`core.js` 383 行纯函数） |
| CDN / 外链字体图标 | 断网即瞎 | ❌ 全部系统字体 + 内联 SVG + 本地生成 PNG 图标 |
| 第三方 API（地图/药品库/兽医库） | 配额、停服、付费墙 | ❌ MVP 不接任何 API |
| 托管平台（GitHub Pages/Vercel） | 唯一剩余依赖 | 任意静态服务器可替代（`npm start` = python http.server）；PWA + SW 缓存后完全离线可用 |
| 浏览器兼容 | 低 | 仅需 ES2020 + localStorage；无摄像头/蓝牙等高权限 API |

**供应链韧性自评**：除"托管平台"外无任何第三方依赖；托管平台本身有一键迁移方案。**这个 MVP 在断网、断托管、断 Git 托管商的假设下依然可在任何一台电脑上跑起来。**

### 6.3 分发供应链（获客链路）

```
内容生产（痛点故事/交接单样例）
  → 小红书/抖音/公众号（免费流量）
    → PWA 落地页（免安装直达）
      → 首单生成（即时价值）
        → 用户把交接单发给照护者 ← 照护者即新用户（产品自带裂变环）
```

关键设计：**交接单的接收方（照护者/机构）天然暴露在产品面前**——每次托养都是一次零成本分发，这是渠道设计里最重要的结构性杠杆。
