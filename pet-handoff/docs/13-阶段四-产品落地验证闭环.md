# 13 · 阶段四：产品落地验证闭环

> 本阶段回答：怎么证明它真的成立？—— HDD（假设驱动开发）把信念变成可证伪命题，MVP 是实验装置而非缩小版成品，OHELM 循环让每个数据都改变下一步动作。本页区分**已验证**与**待验证**，不允许含糊。

## 1. 假设登记册（HDD）

每条假设包含：陈述 → 最便宜的验证实验 → 可证伪判据 → 状态。判据不达标就**转向（pivot）或关闭**，不追加投入。

| # | 假设 | 最便宜验证 | 判据（可证伪） | 状态 |
|---|---|---|---|---|
| **H1** | 痛点真实：主人经历过托养信息断层并为此焦虑 | 20 个深度访谈（小红书/宠友群招募） | ≥12 人能讲出具体的信息遗漏事件；≥15 人表示愿意接收一张交接单 | ⬜ 待验证 |
| **H2** | 交接单会被照护者真正看 | 内嵌追踪：纯文本复制数 vs 交接单下载/发出数；回访 10 位主人问照护者反馈 | ≥70% 主人报告"照护者看过了"；≥30% 照护者使用了禁忌红条信息 | ⬜ 待验证 |
| **H3** | 首次使用后愿意留下（档案复用价值） | PWA 7 日/30 日回访（本地事件流 `events`） | 7 日回访 ≥25%；30 日 ≥10%（工具类基准） | ⬜ 待验证 |
| **H4** | 产品自带裂变：交接单接收方成为新用户 | 落地页加 "从交接单来访" 标记参数；观察 `pet_added` 归因 | ≥8% 新增用户来自交接单接收方 | ⬜ 待验证 |
| **H5** | 付费意愿成立（Pro：多宠+模板+导出报告） | 假门测试：设置页展示 Pro 入口，点击后收集邮箱+"你愿意付多少" | 点击率 ≥5% 且 ≥200 个邮箱中 ≥25% 给出 ≥¥30/年 心理价 | ⬜ 待验证 |
| **H6** | B 端白标有真实需求 | 访谈 5 家寄养机构 + 10 位宠托师 | ≥3 家愿意在门店流程中试用人格化交接单 | ⬜ 待验证 |

| **H8** | 内容专业性经得起检验 | 请 1 名执业兽医审校模板与禁忌清单 | 0 处专业性错误；审校后更新免责边界 | ⬜ 待执行 |

## 2. OHELM 验证循环

每个假设都跑同一个环，每周一次，留痕于本文件的状态列：

```
Observe 观察 ──→ Hypothesize 假设 ──→ Experiment 实验 ──→ Learn 学习 ──→ Modify 修正
（本地事件流+访谈）  （登记册立项）     （假门/埋点/A-B）   （数据 vs 判据）  （pivot / persevere / kill）
```

| 步骤 | 工具/载体 | 纪律 |
|---|---|---|
| **O**bserve | `设置 → 导出事件日志`（`events[]`：pet_added / handoff_generated / handoff_downloaded / handoff_text_copied / log_added / schedule_updated …，已内置于 app） | 只看行为，不听故事 |
| **H**ypothesize | 上表登记册 | 每条必须先写判据再跑实验，防事后合理化 |
| **E**xperiment | 假门（H5）、标记参数（H4）、访谈脚本（H1/H6） | 一次只动一个变量 |
| **L**earn | 每周复盘：数据 vs 判据，一行结论 | 结论写进登记册状态列，不许只存在脑子里 |
| **M**odify | 三选一：**persevere**（继续）/ **pivot**（改方向）/ **kill**（关闭并记录） | kill 也是成果：烧掉的是错误路线不是钱 |

**北极星指标**：每周**有效托养交接单数**（`handoff_generated` 且随后 72h 内有 `handoff_downloaded` 或 `handoff_text_copied`）——它同时代表有人出门（需求发生）和有人交付（价值送达）。护栏指标：生成耗时 <2 分钟、7 日回访 ≥25%、医疗边界投诉 = 0。

## 5. 诚实条款（本项目的科学底线）

1. **分离事实与信念**：本文档所有 ✅ 均可在 `app/` 复现；所有 ⬜ 在验证前不作为宣传依据。
2. **判据先行**：实验跑之前判据已公开写死，杜绝事后换标准。
3. **kill 可接受**：若 H1/H2 不达标，项目关闭并保留全部记录——低成本试错本来就是零依赖架构的设计目的。
4. **不碰医疗**：所有健康相关内容止步于"惯例 + 遵医嘱"，出现 1 次边界投诉即触发免责条款复查（护栏指标归零要求）。
