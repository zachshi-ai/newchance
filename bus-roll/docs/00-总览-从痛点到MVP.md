# 00 · 总览：从痛点到 MVP（护学账 BusRoll）

## 一句话

每台校车身上同时跑着四只法定证照钟、每位校车驾驶人身上跑着一只年度审验钟，而每个上学日的每一趟都要求「出车前七项检查 → 上车清点系带 → 下车核实全数离车」——护学账把这只钟和这本趟次账从园长的脑子里搬到手机上：超员拦下、带病拦下、少一人闭环不了，检查来了 30 秒出证。

## 痛点（三条腿）

1. **证照黑箱**：每半年安全技术检验（条例第20条）、校车标牌有效期（第16条）、交强险+承运人责任保险（第14条(五)）、驾驶人每年审验（第26条）——现状是遮光板夹证件+脑子记日期，漏一只就是扣车+1万~2万罚款（第45条）。
2. **趟次无痕**：随车照管人员的法定职责链（第39条五项，尤其(五)「核实学生下车人数，确认全部离车后本人方可离车」）全靠自觉，纸上没有痕迹——幼儿被遗忘校车的悲剧年年在暑期复现，出事就是刑责（超员入刑、遗弃类罪名）与吊销办学许可（第55条）。
3. **迎检突击**：开学季公安交管+教育联合检查逐台核验资质/年检/保险/维保/培训/隐患整改记录（2026-08 永州交警通报口径），小微民办园与校车公司的现状解法是检查前一夜补表格。

## 方案（零依赖本地优先 PWA）

一车一档四只钟（红黄绿+依据条号）+ 趟次点名四步状态机（出车前七项检查→上车点名超员硬拒→下车清点人数守恒→车内三查全数离车确认）+ 带病开不了趟（异常检查必须先登记隐患、闭环前发车被拒）+ 驾驶人审验钟与年龄红线 + 周期义务账（演练/教育/培训/设备/责任书）+ 八灯体检 + 三通道出证（迎检自证包单文件 HTML / 趟次点名卡打印 / 月度小结微信文本）。

## 仓库内验证

- `npm test` → 30/30 单元测试（证照钟边界、趟次状态机、超员/守恒红线、体检确定性、出证完整性）
- 浏览器端到端：建档→示例数据→看板红灯→建趟次→异常检查强制隐患→**带病发车被拒**→销案→**超员 40/19 被拒**→12 人发车→少一人被拒→12 人三查闭环→月度小结→迎检包下载→刷新持久化，本地埋点记录 `overload_blocked` 等全链路事件

## 边界（诚实条款）

不碰运营调度、不接卫星定位硬件、不做监管报送、不记学生姓名（未成年人信息最小披露）；口径全部参数化、属地实施办法永远赢；台账是自查与迎检底稿，不替代法定报送与执法认定。详见各篇「诚实条款」与 docs/14。
