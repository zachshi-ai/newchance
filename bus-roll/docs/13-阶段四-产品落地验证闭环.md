# 13 · 阶段四：产品落地验证闭环（护学账 BusRoll）

## 1. DSTE 主线（从战略到执行）

战略=「小微校车主体的趟次级自证工具」→ 执行拆解：法规内容库（docs/14）→ 点名状态机（core.js 红线引擎）→ 出证三通道（ui/reports）→ 渠道联营包（白标授权码）→ 验证埋点（本地 events）。每一步都有仓库内可验证产物，不落地为 PPT。

## 2. MVP 定义与已验证功能

**MVP 切线**：一车一档四钟 + 趟次四步点名 + 三道硬拦截 + 隐患闭环 + 义务账 + 八灯体检 + 三通道出证。
**不做（本版）**：调度排班、硬件接入、报送接口、学生名单、多校区权限。

## 3. HDD 假设登记册（H1~H8，可证伪判据）

| # | 假设 | 证伪判据（90 天内） |
|---|---|---|
| H1 | 园长愿意为一车一档建档 | 建档后 7 日内登记 ≥1 只证照钟的比例 <30% 则证伪 |
| H2 | 趟次点名会变成日常习惯 | 周活跃点名车辆数连续 3 周下滑则证伪 |
| H3 | 超员拦截真实发生且被接受 | `overload_blocked` 事件=0 且无人反馈，说明没人在真用点名则证伪 |
| H4 | 带病门禁推动隐患真闭环 | 开卡的隐患 14 日闭环率 <50% 则证伪 |
| H5 | 出证被真实出示 | 自证包/点名卡生成后无打印/下载动作记录则存疑（本地只能记生成事件） |
| H6 | 299/年付费意愿 | 渠道演示后 30 日转化 <1 单则证伪 |
| H7 | 校车服务商愿做白标渠道 | 触达 10 家、0 家签约则证伪 |
| H8 | 保险经纪第二渠道成立 | 触达 5 家、0 家愿意联合演示则证伪 |

## 4. OHELM 循环

**Observe**：开学季检查通报与遗忘悲剧（外部）；本地 events（内部）。**Hypothesize**：H1~H8。**Experiment**：示例数据+单园试点。**Learn**：看板红灯是否被逐周清零。**Measure**：北极星指标=**周活跃点名车辆数**（每台每周至少 1 次真实点名闭环）。

## 5. 北极星与护栏

- 北极星：周活跃点名车辆数（不是注册数、不是打开数——点名闭环才是价值发生）。
- 护栏：证照红灯平均滞留天数（应下降）；出证生成后 7 日内留存率。

## 6. 第一桶金三路径

1. **直营授权码**：¥299/年（早鸟 ¥199），心智锚=「一次超员罚款 1 万~2 万、吊销许可=终身」。
2. **服务商白标联营**：¥1500/年/商，分发其挂靠园（上游即渠道，动机=保运力保维保收入）。
3. **保险经纪联动**：向承运人责任险投保人赠送工具+经纪补贴，换投保续保场景（第14条(五)强制险=年年续=年年触点）。

## 7. 90 天验证排期（与学期和执法节奏对齐）

- **第 1~2 周（开学检查季）**：属地 10 家民办园/校车公司建档试点；收集第一批 events。
- **第 3~6 周**：每周回访红灯清零情况；打磨迎检包与点名卡打印样式（检查组真实反馈）。
- **第 7~10 周**：渠道签约（2~3 家服务商白标试点）；定价 A/B（299 vs 199）。
- **第 11~13 周**：复盘 H1~H8，判定 go / pivot；若 H2 证伪→转向「检查前自查包」单点工具。

## 8. 诚实条款

技术可行性已在仓库内验证（30/30 测试 + 浏览器端到端含两道红线拦截）；商业假设（建档留存/点名习惯/拦截真实发生/隐患闭环/出证使用/付费/双渠道）全部标注「待验证」并配有可证伪判据；TAM/SAM 用宽区间并标注权威口径待复核，收入测算不预设渠道成功；工具不判记录真伪、只保完整与闭环，**台账是义务的底线，不是事故的护身符**。
