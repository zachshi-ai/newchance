# 护学账 BusRoll 🚌

> **小微校车证照时钟与每趟点名照管台账：每半年安检钟、标牌/双险到期钟、驾驶人年度审验钟与年龄红线，趟次四步点名（出车前七项检查 → 上车清点系带 → 下车核实守恒 → 车内三查全数离车）——少一个人趟次闭环不了，带一辆病车今天就发不了车，检查来了 30 秒出证。**
> 零依赖 · 本地优先 · 免注册 · 可离线 · 数据不出设备

校车是法规给「证明」定价最高的行业：每台车四只法定证照钟（每半年安全技术检验（条例第20条）、校车标牌有效期（第16条）、交强险与承运人责任保险（第14条(五)））、每位驾驶人一只年度审验钟（第26条）与 25~60 周岁年龄红线（第23条(一)）；每个上学日的每一趟都有法定动作链——出车前对制动、转向、外部照明、轮胎、安全门、座椅、安全带逐项检查（第41条）、清点人数系好安全带（第39条(三)）、**核实下车人数、确认全部离车后照管员方可离车（第39条(五)——防遗忘就是这一条）**。而罚则真金白银：无标牌/无资格扣车+1万~2万（第45条）、超员扣车+从重处罚+刑修九后严重超员入刑（第50条、刑法133条之一(三)）、民办校出伤亡事故**暂停招生直至吊销办学许可证**（第55条）。1~10 台车的民办园与校车公司的现状是四只钟散在脑子里、点名靠喊、检查前一夜补表——护学账把这本账变成白箱：一车一档上钟 → 每趟 30 秒点名（超员当场拒绝、带病当场拒绝、少一人当场拒绝）→ 八灯体检 → 一键出迎检自证包 / 趟次点名卡 / 月度小结。

## 3 条命令跑起来

```bash
cd bus-roll
npm start           # 等价于 python3 -m http.server 8101 --directory app
open http://localhost:8101
```

没有 npm 也可以：任意静态服务器指向 `app/` 目录即可（它就是这个产品的全部）。
首次进入点「**载入示例数据**」，看板上的红灯都是演示钩子，30 秒体验完整点名流程。

## 功能

| 模块 | 说明 |
|---|---|
| 🚌 **一车一档 + 四只证照钟** | 车牌/核载（照行驶证签注抄，第15条）/标牌；**每半年安检钟**（第20条，+6 个月自动推导、月末钳制）、**标牌有效期钟**（第16条）、交强险钟、**承运人责任险钟**（第14条(五)）；缺登记亮「未登记」——比过期更早暴露 |
| 👮 **驾驶人资格与审验钟** | 取得资格日（第24条交管签注）+ **每年审验钟**（第26条）+ **年龄红线**（第23条(一) 25~60 周岁，超龄自动点名禁驾）；未登记资格=建趟次被拒（第25条「禁止聘用」） |
| 🧒 **随车照管员** | 第38条「应指派照管人员随车全程照管」——建趟次一个照管员都不勾，趟次建不起来；未指派可处 500 元（第53条）写进文案 |
| 🚦 **趟次四步点名** | ①出车前**七项检查**（第41条逐项原文列举：制动/转向/外部照明/轮胎/安全门/座椅/安全带）②**上车点名**：清点人数+落座系带关门确认（第39条(三)），**超核载硬性拒绝**（第34条）③**下车清点**：下车+中途下车=上车才许闭环，中途下车逐人留因（第39条(五)）④**车内三查**全数离车确认才闭环——防遗忘的工具化 |
| 🛑 **带病开不了趟** | 检查有异常必须先登记隐患+整改措施（第22条停运维修口径）；**隐患闭环前点「发车」被硬性拒绝**（第41条「不得驾驶存在安全隐患的校车上道路行驶」）——销案复查才放行 |
| 🗓 **周期义务账** | 应急演练/学生交通安全教育（第12条）、驾驶人安全教育（第10条）、照管员培训（第38条）、安全设备检查（第21条）、责任书备案复核（第11条）——「定期」全部参数化，打勾自动滚动 |
| 🩺 **八灯体检** | 证照钟/驾驶人资格/未闭环趟次/隐患超期/在册隐患/周期义务等确定性扣分，迎检前先自查 |
| 📑 **三通道出证** | **迎检自证包**（单文件 HTML：单位档案+一车一档四钟+驾驶人资格审验+照管员+近期趟次守恒+隐患闭环+义务账+体检，含签字栏）/ **趟次点名卡**（一趟一卡，照管员/驾驶人/复核三方签字栏）/ **月度小结**（微信文本，含守恒校验行与未闭环点名） |
| ⚙️ **数据自持** | 100% 本地存储；**趟次只记人数、不记学生姓名**（未成年人信息最小披露，与第39条「清点/核实人数」的义务颗粒度一致）；JSON 导出/导入（含结构校验）；本地事件流可导出（`overload_blocked` 等验证埋点） |

## 为什么没有后端 / 没有依赖

这不是偷懒，是设计（详见 [docs/12 供应链分析](docs/12-阶段三-机会转化产品方案.md)）：
**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**
民办园在县城也在乡镇，接送早高峰网络时好时坏，PWA 离线可用；月度小结走微信文本，不依赖任何在线服务；不记学生姓名（本地优先即未成年人信息最小披露的实现方式）。**不做调度排班、不装卫星定位硬件、不做监管报送、不碰学生名单**——车队系统、监控平台是互补不是对手，这里是园长自己的证照与点名底账。

## 第一桶金（详见 docs/13）

主攻「**校车服务公司/经销商联营**」：校车服务商手握下游数十家挂靠园的订车与维保关系，下游被停运/吊销许可（第54/55条）= 公司运力与维保收入损失——帮下游合规存续 = 保护服务商自己的资产。¥1500/年/商白标分发其挂靠园；主体侧 ¥299/年（早鸟 ¥199）授权码，心智锚=「一次超员从重处罚+入刑风险，一次停运=流失整学期学费」；第二渠道为校车保险经纪（承运人责任险系第14条(五)强制险，年年续保年年触点，理赔要的就是点名与检查的真实记录）。
