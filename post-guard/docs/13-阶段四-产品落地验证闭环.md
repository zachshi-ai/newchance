# 13 · 阶段四：产品落地验证闭环

> 本阶段使用的框架：DSTE 主线、MVP 范围裁剪、HDD 假设驱动开发（H1-H8 假设登记册）、OHELM 循环、北极星指标、第一桶金、90 天验证排期。
> 铁律：**每个假设都有可证伪判据与放弃线；我们不把未验证的信念当成果。**

## 1. DSTE 主线（从战略到执行）

```
市场洞察：GBZ 188—2025 换挡（2026-08-01）× 小微接害企业存量口径失效 × 罚则 5万~30万
   ↓
战略意图：成为小微企业「职业健康监护台账」的默认底稿工具
   ↓
创新焦点：定档引擎（法规知识工程化）+ 三钟模型 + 一键法定交付物
   ↓
业务设计：免费工具（获客/信任）→ 服务变现（建档/年度/转介）→ B2G2B 放大
   ↓
执行计划：MVP（已交付）→ 5 个乡镇渠道地推验证 → 假设判据复盘 → 决定加码/转向/放弃
```

## 2. MVP 范围裁剪（已交付 vs 明确不做）

**已交付**（本仓库 `app/`，35/35 测试+端到端验证）：岗位定档引擎、员工三钟、检查登记与处置待办、合规四件套、自证包、离岗档案复印件、示例数据、JSON 备份、设置覆盖口径。

**MVP 明确不做**（防止范围膨胀）：多企业/集团版、云端同步、提醒推送通道（短信/订阅消息——本地通知先验证价值）、体检预约对接、检测机构数据库、职业卫生健康培训课件市场。每项都等 H 系列假设给出信号再排。

## 4. OHELM 循环（Objective → Hypothesis → Experiment → Learn → Measure → 下一轮）

以 H1 为例走一轮完整循环：

1. **Objective**：小微企业能把监护台账建档并持续维护。
2. **Hypothesis**：H1（现场帮建后 30 天留存 ≥40%）。
3. **Experiment**：5 个乡镇地推，每站现场用示例数据+真实岗位帮建 2 家。
4. **Measure**：30 天后检查 JSON 备份导出量+回访确认检查记录新增。
5. **Learn**（预设分支）：留存高 → 加码 H5 付费实验；留存低 → 访谈断点在「录入太累」还是「没被检查逼过」，前者转代建服务，后者换渠道（找刚被检查过的企业）。

每轮 OHELM 的产出写回本文件（Learn 与下一轮 Objective），保持验证历史可审计。

## 5. 北极星指标与护栏指标

- **北极星：活跃监护钟数** = 近 30 天内有检查记录/钟况查看行为的企业 × 在监护的员工数。理由：它同时编码了「建档」（有钟）与「真用」（活跃），且与产品价值（持续证明合规）直接同向。
- 护栏指标：红线企业数（应下降）、自证包导出次数（应上升）、备份导出量（数据安全习惯）。

## 6. 第一桶金（首个 100 元怎么来）

**路径 A（主推）：建档服务。** 地推现场免费帮建 + 留下工具 → 两周后回访，对已激活企业报价「职业健康监护建档管家」：定岗定档复核+员工全量导入+机构报告解读+自证包定制抬头，¥399~899/厂（按人数分档）。成本=半天人工/厂。**预计首月 3~5 单即回收全部验证差旅成本**——这是「服务先行」路线，不依赖任何线上付费基础设施。

**路径 B（并行验证）：体检季服务费。** ¥199/年：周期预警+新规口径更新+自证包重出。体检季前一个月（高峰前的提醒窗口）推销。

**路径 C（机会型）：机构转介。** 与 1 家职业健康检查机构谈成：工具内「该体检了」红黄灯的企业由机构上门接检，返佣 5%~10%。仅在 A/B 现金流转正后再投入。

第一桶金判据：90 天内路径 A+B 合计现金流 > ¥3,000，且至少 1 单来自转介绍（口碑信号）。

## 8. 诚实条款
