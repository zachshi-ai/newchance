## 1. 痛点（真实世界，有据可查）

农药经营的台账不是经营偏好，是法定义务：

- **购销台账 = 法定义务 + 2 年保存期**：《农药管理条例》第 26、27 条要求经营者建立采购与销售台账并保存 2 年以上，不执行台账制度的责令改正、拒不改正可处罚款（[条例官方版本](14-调研来源.md#法规与政策红线口径的直接依据已逐条核验)）。
- **"电子台账"是办证前置条件**：《农药经营许可管理办法》第 7 条第（四）项把"可追溯电子信息码扫描识别设备 + 购销电子台账计算机管理系统"写进许可条件——新增门店与换证店主必须跨过这道坎。
- **禁限用红线正在收紧且时机正在进行**：农业农村部第 736 号公告，氧乐果、克百威、灭多威、涕灭威自 **2026-06-01 起（三个月前）全面禁止销售和使用**——存量清库与台账核查是当下进行时；现行禁用农药数十种、限制使用农药 32 种须定点经营、实名购买。
- **过期农药按劣质农药管理**：经营即没收 + 罚款——效期是资金账与违法红线的交点。
- **药害纠纷的举证压在门店**：拿不出进货来源与产品信息的经营者可能先行担责（最高法涉农典型案例口径）——批号/追溯码是门店把责任回溯到厂家的唯一通道。
- **现状解法 = 纸台账本 + 记忆 + 检查前突击**：乡镇店主不会 Excel、懒得开机扫码器，纸台账对不上实物、经不起核对。
- 第一性差距：**"购销之间的证明黑箱"没有任何小微级工具承接**——购销单把落账变顺手、把红线变亮灯、把出证变打印。

## 2. 方案（机会 → 产品）

**购销单**：零依赖、本地优先的 PWA。

1. **商品建档即红线体检**：禁用名录完全一致命中 → 拒绝建档（无后门）；限制使用名录命中或手动勾选 → 自动打「限」标（销售强制实名）；支持农药/种子/肥料三类。
2. **进货建批**（条例第 26 条字段）：供货人/批号/追溯码/效期/进价一次落账；农药批次效期必填、效期早于进货日拒绝。
3. **销售落账**（条例第 27 条字段）：临期先发 FIFO、跨批自动分配、限用强制实名（缺证件号拒绝入账）、库存不足**整单拒绝**、撤销精确回滚；库存不落库——剩余 = 进货 − 已售 − 报损，由流水唯一派生（账实守恒）。
4. **效期三态管理**：临期 90 天窗（可调）点名 → 过期自动踢出卖场 → 过期在库一键封存报损（劣药红线变成一个按钮）。
5. **三通道出证**：药害自证单（按购买人捞出卖单与批次明细）、采购/销售台账文本（微信转发）、迎检打印包（单文件 HTML：店铺 + 守恒体检 + 两本台账 + 效期盘点，直接打印或下载）。
6. **账本体检 + 数据自持**：过期在库/限用实名缺漏/禁用档案三查；100% 本地存储，JSON 导出/导入，本地事件流可导出（验证闭环数据入口）。

## 3. 诚实的现状声明（真实可落地，不空中楼阁）

- **已验证**（本仓库内可复现）：核心逻辑 32/32 单元测试通过（含账实守恒、整单拒绝不部分入账、限用实名强制、临期先发 FIFO、效期边界、名录匹配、导出确定性、XSS 转义、导入导出往返）；浏览器端到端全流程（示例数据 → 看板过期/临期预警 → 销售落账（FIFO 跨批）→ 自证单出证 → 过期一键封存 → 迎检包生成）真实运行通过；打印包为单文件、离线可用；零 npm/CDN/API 依赖；SW 缓存版本化。
- **未验证**（需真实用户，见 docs/13 假设登记册）：落账留存（H1）、迎检包真实使用与采信（H2）、自证单真实纠纷使用（H3）、付费意愿（H4）、批发商渠道（H5）——全部标注"待验证"并配有可证伪判据。
- **边界与免责**：不碰追溯平台报送、不做扫码硬件绑定、不做财务进销存；内置禁限用名录是常见条目通识整理、以农业农村部最新公告为准（手动标记永远可覆盖）；打印台账不承诺执法采信；限用实名信息最小披露、只存本机。
