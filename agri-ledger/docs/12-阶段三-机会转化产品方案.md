# 12 · 阶段三：机会转化产品方案

> 本阶段回答：机会怎么变成一个可卖的产品？用商业画布与价值主张画布定结构，用蓝海四动作定差异化，用 Kano 裁 MVP，最后把供应链想透——本项目供应链分析的重头戏是**农资流通链**（批号/追溯码让门店与上游绑定）与**分发链**（县级批发商即渠道，且渠道动机比任何同类项目都硬：赊销应收账款的保全）。

---

## 1. 商业画布（Business Model Canvas）

| 模块 | 内容 |
|---|---|
| **客户细分** | 乡镇/县域持证农资门店（1~2 人经营，农药为主或农药+种子+肥料混卖）；正在申办农药经营许可的筹备户；渠道客户：**县级农资批发商/经销商**（联营贴牌，见 §6.3） |
| **价值主张** | 对店主：禁限用红线建档即体检、效期临期先知道、过期一键封存、限用实名不漏填、迎检 30 秒出台账包、药害索赔按人出自证单、办证口径的"电子台账"要件就地满足；对执法者/农户：拿得出、说得清、对得上；对批发商：下游门店合规存续 = 赊销应收账款的保全 |
| **渠道** | 直达：抖音/快手"农资店被罚/药害扯皮"场景内容 + 乡镇店主微信群 + 农资展会；渠道：**县级批发商联营**（上游供应商即分销商）、县域推广员分佣 |
| **客户关系** | 免费自助 + 内容号陪跑（名录更新/迎检话术/清库提醒）；批发商渠道由商家代维护客户关系 |
| **收入来源** | 免费版（单店全功能）；Pro 待验证（H4 假门 ¥99/年）：多店管理、经营月报、自定义台账抬头；县级批发商联营年费 ¥1200/商（白标 ≤50 家门店）待验证（H5） |
| **核心资源** | 禁限用名录与迎检话术的内容模板库（公告跟踪）、"购销单 = 农资合规台账"品类心智、县级批发商渠道关系 |
| **关键业务** | 名录内容运营（公告跟踪与更新）、渠道拓展（批发商/展会）、留存运营（效期/临期预警触达） |
| **重要伙伴** | 县级农资批发商（渠道 + 名录与清库节奏的真实信息源）、静态托管平台、农资展会与县域推广员 |
| **成本结构** | 近零边际成本：无服务器账单、无 npm 审计、单人维护；获客内容制作为主要成本 |

## 2. 价值主张画布（Value Proposition Canvas）

**客户侧（乡镇店主）**

| 客户任务 | 痛点 | 期望收益 |
|---|---|---|
| 进货时记台账 | 纸本懒得写，发票塞抽屉，回头全忘 | 照标签抄 30 秒落账，供货人/批号/追溯码/效期一次记全 |
| 判断"这个还能不能卖" | 名录几十种靠记忆，736 号公告四种刚禁售 | 建档即体检：禁用拒绝建档、限用自动打「限」标 |
| 卖限制使用农药 | 实名购买常忘登记，检查一问就露馅 | 带「限」标商品落账强制实名，缺证件号拒绝入账 |
| 效期与清库 | 压货过季才发现过期，过期 = 劣药违法 | 临期 90 天窗先发先卖；过期自动踢出卖场、一键封存点名 |
| 执法上门检查 | 台账本对不上实物，突击补填经不起核对 | 迎检打印包：账实守恒体检 + 采购/销售台账 + 效期盘点，30 秒出证 |
| 药害索赔找上门 | 说不清货源与批号，先行担责 | 自证单按购买人捞出全部卖单与批次（批号/追溯码/效期/登记证号） |
| 办证 / 换证 | "电子台账管理系统"这道坎不知道怎么过 | 店铺档案 + 台账输出就是电子台账要件的活证明 |

**产品侧**

| 功能 | 减痛 / 创益 |
|---|---|
| 进货建批（效期必填、批号/追溯码登记） | 减痛：台账 26 条字段一次记全，账实自动守恒 |
| 销售落账（限用强制实名 + 临期先发 FIFO） | 减痛：实名不漏填；卖出的每件可追到批，药害自证有据 |
| 禁限用名录建档体检 | 创益：红线的判断成本趋近于零（736 号公告条目带生效日期） |
| 过期在库点名 + 一键封存报损 | 减痛：劣药红线变成一个按钮 |
| 药害自证单 + 迎检打印包（微信文本 / 单文件 HTML / 直接打印） | 创益：检查与纠纷两场的"当场拿得出" |
| 账实守恒体检（进货 = 已售 + 报损 + 库存） | 创益：账本经得起"与实物核对"的追问 |

**契合检验**：七个客户任务 ↔ 六项功能一一对应（台账出证覆盖检查与办证两个任务），无"我们做了但没人要"的悬空功能。

## 3. 蓝海战略四动作框架（ERRC）

| 动作 | 内容 | 效果 |
|---|---|---|
| **剔除 Eliminate** | 扫码硬件绑定（追溯码手输即可）、财务进销存与报表、在线商城/集采、追溯平台报送、农技问答 AI、多角色权限与实施培训 | 与通用进销存正面会战的战场全部放弃；报送义务与资金合规一并剔除 |
| **减少 Reduce** | 建档字段（商品 8 项、批次 8 项，全部照标签抄）、落账动作（进货 3 步、销售勾选即落）、报告格式（台账一种模板、自证单一种格式） | 把"系统"从文书工作降为"顺手"级动作 |
| **增加 Increase** | 禁限用名录建档体检（含 736 号公告生效日期）、过期在库点名与一键封存、限用实名强制、账实守恒体检、药害自证单、迎检打印包 | 把"记台账"升级为"有红线、有效期、有守恒、有凭据"的合规经营闭环 |
| **创造 Create** | **"购销之间的证明确定性"**——店主从未体验过"当场拿得出、对得上、说得清"；执法者与农户第一次见到门店递出的结构化凭据 | 非消费者（纸本老店主、筹备办证户、被 SaaS 伤过的老板）转化为用户 |

## 4. USP（独特销售主张）

> **唯一为乡镇农资门店设计的合规购销台账：进货卖出顺手落账，禁限用红线当场亮灯，效期临期先知道、过期一键封存，执法检查 30 秒打出台账包，药害索赔按人出凭据。不做进销存财务、不做电商集采、不碰追溯报送，一部手机就能用，免费开始。**

- 对比纸台账本：有红线、有效期、有守恒、有凭据，"回头补"变成"当场记完"；
- 对比管家婆们：不要钱（单店）、不要学、不要电脑，专管进销存不管的那一段（合规与自证）；
- 对比追溯平台：它是监管数据链，购销单是门店自己的经营底账与自证凭据——互补不替代。
- 三句话之外的克制：**不说"保证免罚"，不说"替代报送与官方系统"**——证据效力边界见诚实条款（docs/13 §6）。

## 5. Kano 模型 → MVP 范围裁剪

| 类型 | 功能 | MVP 取舍 |
|---|---|---|
| 基本型（没有就骂） | 商品/供应商建档、进货建批、销售落账、台账导出（文本/HTML/打印） | ✅ 已做（32/32 测试覆盖核心逻辑） |
| 期望型（越多越好） | 效期过滤与临期先发 FIFO、限用实名强制、过期剔除与撤销回滚、账实守恒 | ✅ 已做 |
| 兴奋型（超出预期） | 禁限用名录建档体检、过期一键封存、药害自证单、迎检打印包、账本体检三查 | ✅ 已做（数据齐了自动出现）；名录自动更新/多店报表进 Pro/迭代池（H4 验证后再投入） |
| 无差异（别做） | 财务进销存、电商集采、农技问答、赊销记账、会员营销 | ❌ 永不做（偏离合规台账主线） |

## 6. 供应链分析（重点：农资流通链 + 技术链 + 分发链）

### 6.1 农资流通供应链（门店是链条最后一公里——台账即供应链数据结构）

农资从工厂到农田：**生产企业 → 省级代理 → 县级批发商 → 乡镇门店 → 农户**。条例要求的采购台账字段（生产企业、供货人、批号、追溯码、许可证明文件编号）本质上是**把供应链上游逐环写进门店账本**——台账做得越全，门店在链条中的位置越可证明：

| 环节 | 链路 | 暗账（没人记的部分） | 购销单的动作映射 |
|---|---|---|---|
| 进货 | 县级批发商送货上门 / 赶集日自采 | 发票塞抽屉、批号效期无人抄、赊销口说无凭 | `applyIntake` 进货建批：供货人/批号/追溯码/效期/进价一次落账（26 条字段口径） |
| 存储周转 | 品类更替频繁（高毒退市、生物药替代） | 哪批先到期靠翻箱，压货过季才发现 | `sellableBatches` 临期先发 FIFO；临期 90 天窗点名；过期自动踢出卖场 |
| 处置 | 过期品下架封存（劣药红线） | 封存无记录，处置全靠扔 | `recordLoss` 过期/破损/其他三类报损落账，账实守恒不断 |
| 销售 | 农户散买为主，限用实名 | 卖给谁靠脸熟，限用身份证号懒得要 | `applySale` 27 条字段落账；限用强制实名；分配落批可追溯 |
| 纠纷回溯 | 药害索赔、执法抽检 | 货源说不清 → 经营者先行担责 | `proofOfSale` 自证单 + `inspectionHtml` 迎检包，当场出证 |

**上游不碰、下游不碰**：不碰批发商的仓储配送（ERRC 剔除集采），不碰农户的用药指导（剔除农技服务）——购销单只把门店这一环的"进、存、销、处"记成一本守恒的账，它是门店与上游批发商、下游农户、侧向执法者一切对话的底气。

### 6.2 产品自身供应链（MVP 的技术依赖链，逐项消除单点故障）

与仓库内其余项目同一架构纪律：**无服务器 → 无账单；无 npm → 无投毒攻击面；无 CDN → 断网可用；无第三方 API → 无停服风险。**

| 依赖 | 决策 | 单点故障消除 |
|---|---|---|
| 后端/数据库 | 无（localStorage 本地优先） | 无云账单、无停服；实名信息不出设备；乡镇网络差照常用 |
| 第三方库 | 无（core.js 纯函数，日期/队列/守恒/导出自实现） | 无供应链投毒面；`node --test` 零依赖可测 |
| 分发 | 任意静态服务器（`python3 -m http.server` 3 条命令） | 文档根即部署根，可迁移任意托管 |
| 出证 | 微信文本 + 单文件 HTML（内联样式）+ 系统打印 | 不依赖任何在线渲染/消息服务，执法者与农户零安装 |
| PWA 离线 | sw.js 缓存应用壳（版本化 + `cache:'reload'` 更新） | 断网可用；升级可靠到达 |

### 6.3 分发供应链（获客链路——上游供应商即分销商，且渠道动机更硬）

```
内容制作（抖音/快手："农资店被罚第一现场""药害索赔说不清货源" 场景内容 + 迎检台账模板引流）
      ↓ 免费工具承接（零摩擦，扫码即用）
直达用户（乡镇店主微信群 / 农资展会 / 县域推广员）
      ↓ 规模化放大（本项目独有的渠道结构）
渠道分层：① 县级农资批发商联营（B2B2C）：商家把购销单贴牌赠给下游 10~200 家零售门店
         → 商家动机（比同类联营更硬）：农资赊销普遍（春赊秋还），批发商最大的资产是
           对下游门店的应收账款；门店因台账违规被罚、因误卖禁用品被吊证 = 坏账。
           帮门店合规存续 = 保护批发商自己的资产负债表；
           白标台账落款 = 批发商每周对门店的品牌触达
         → 购销单动机：一个县级批发商背后是 10~200 家活跃门店，获客成本 ≈ 0
         ② 县域推广员分佣：农技站离职人员/农资老业务员按成交 20% 分佣
         ③ 展会场景：省级农资展会现场"扫码建档送迎检台账包"，办证季（换证高峰）集中转化
```

每层渠道都已有真实存在的服务商（县级批发商、县域推广员）——不需要发明新的中间商，只需给他们一个更好送的商品。**县级批发商是全链路里"上游供应商反过来是分销商"的角色，且其渠道动机（赊销应收账款保全）比流量型渠道深一层——供应链即渠道，与翻房单的洗涤厂联营、消课单的教具商联营同构，但供应链角色与行业完全不同。**

---

**阶段三结论**：商业结构成立的关键在"近零成本 + 免费增值 + 批发商渠道复用"；产品差异化在"把购销之间的证明黑箱变成白箱，并顺手把效期红线和禁限用红线翻译成店主每天看得懂的动作"。所有付费与渠道假设进入阶段四的假设登记册逐一证伪。
